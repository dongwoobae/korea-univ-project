# 모바일 UI 전수 점검

- 점검일: 2026-08-18
- 점검 기준 커밋: `e1509ed`
- 대상: 공개 지도 모바일(320×568에서 상태 9종, 390×844에서 지목 검증), 관리자 모바일 4개 화면
- 점검 방식: Playwright로 각 상태를 띄운 뒤 DOM에서 직접 측정한다. ① 쌓임 맥락에
  갇힌 z-index ② `elementFromPoint`로 본 조작 대상 가림 ③ 터치 타깃 크기
  ④ 가로 넘침 ⑤ 뷰포트 이탈. 아래 수치는 모두 그 실측값이다.

## 1. 요약

발단은 모바일에서 피드백 모달이 검색창·필터·목록 버튼에 가리는 제보였다. 원인은
`.ku-map-actions`가 z-index로 만든 쌓임 맥락 안에 모달이 갇힌 것이었고, 같은 계열의
결함이 더 있는지 훑었다. **쌓임 맥락에 갇힌 z-index는 앱 코드 기준 추가 0건**이지만,
"보이지 않는 요소가 히트 테스트를 가져간다"는 같은 뿌리의 문제가 하나 더 있었다.

## 2. 수정 완료

### MOB-01. 시설 필터의 투명 영역이 지도와 언어 선택을 삼킨다

모바일 `.ku-filter-panel`은 `left:16; right:16; background:transparent; border:0`이라
실측 박스가 **x16 y76 w358 h44**(390×844 기준)다. 눈에 보이는 트리거는 폭 112px뿐이고
나머지 246px는 투명하지만 히트 테스트는 그대로 가져간다. y=98 지점에서
`elementFromPoint`는 x148·188·228·268·308·348 전부 `div.ku-filter-panel`을 돌려줬다.

- **지도**: 해당 띠 전 구간에서 탭·드래그가 먹지 않는다.
- **언어 선택**: 목록 첫 항목 "한국어"의 박스가 x250 y76 w118 h44라 정확히 이 띠에
  들어간다. `.ku-language`는 z-index 1000, `.ku-filter-panel`은 1050이므로 필터 패널이
  위에 온다. EN·中文는 아래에 있어 정상이고 **한국어로 되돌리는 것만 불가능했다.**

[`2026-07-22-ux-audit.md`](./2026-07-22-ux-audit.md)의 UX-P0-01 완료 기준은 "390px
화면에서 한국어·영어·중국어를 모두 선택할 수 있다"였다. 당시 추가된 E2E
(`e2e/public-map-p0.spec.ts`)는 한국어 → EN → 中文만 밟고 **한국어로 돌아오는 경로를
밟지 않아** 이 구멍을 잡지 못했다.

수정은 모바일 `.ku-filter-panel`에 `pointer-events: none`을 주고
`.ku-mobile-filter-trigger`·`.ku-mobile-filter-content`에만 `auto`를 되돌리는 것이다.
레이아웃을 건드리지 않고 투명 구간만 통과시킨다. 회귀 가드는
`e2e/public-map-p0.spec.ts`의 "모바일 시설 필터의 투명 영역이 지도와 언어 선택을
가로채지 않는다" — 히트 테스트 4지점과 EN → 한국어 왕복을 함께 단언한다.

### MOB-02. 피드백 모달이 스크롤되지 않아 오류 복구가 막힌다

`.ku-feedback-backdrop`은 `position:fixed; display:grid; place-items:center`인데
`overflow` 지정이 없었다(=visible). 320×568 실측:

| 상태                     | 모달 높이 | 제출하기 bottom | 뷰포트 |
| ------------------------ | --------- | --------------- | ------ |
| 평시                     | 559       | 558             | 568    |
| 서버 오류 안내가 붙은 뒤 | **630**   | **629**         | 568    |

백드롭은 `overflow: visible`이고 document도 스크롤되지 않아, "서버 제출에
실패했습니다. 잠시 후 다시 시도하거나 메일로 보내주세요"라는 안내는 보이는데
**제출하기와 '메일로 보내기'가 둘 다 화면 밖으로 나가 닿지 않았다.** 오류 복구 경로가
막히는 케이스라 P0으로 둔다.

수정은 백드롭을 `justify-items:center; align-items:start; overflow-y:auto`로 바꾸고
모달에 `margin: auto 0`을 주는 것이다. 여유가 있으면 자동 마진이 가운데로 밀고,
없으면 0으로 접히며 위에서부터 쌓여 스크롤로 닿는다. `place-items:center`를 둔 채
`overflow`만 켜면 넘친 위쪽이 스크롤 범위 밖으로 나가므로 그 조합은 쓸 수 없다.
회귀 가드는 `e2e/public-map.spec.ts`의 "작은 화면에서 오류 안내가 붙어도 제출과 메일
대안에 닿는다".

### MOB-03. '현재 지도 목록' 패널이 '현 위치' 버튼을 덮는다

수정 전 390×844 실측: 패널 y551–696, '현 위치' 버튼 y664–712으로 **32px 겹쳤다.**
버튼 중심(350,688)의 히트 테스트는 패널 안쪽 목록 버튼으로 잡혔다. `.ku-map-browse`는
z-index 1050(전면일 때 1060), `.ku-map-actions`는 1000이다.

시설 필터와 상세 패널은 열릴 때 `.ku-map-actions`를 `display:none`으로 치우는 규칙이
`map-ui.css`의 모바일 블록에 있는데(`[data-panel-open]`·`[data-overlay-open]`),
목록 패널만 그 처리가 빠져 있었다.

출처 표기를 한 줄로 줄이면서 목록 트리거를 `bottom` 92 → 44로 내렸고, 패널도 같이
내려와 겹치는 폭이 두 버튼으로 늘었다. 그래서 아래 선택지 중 A를 택했다.

- **선택지 A (채택)**: 목록 패널 열림 상태를 `.ku-map-actions`의 `data-overlay-open`으로
  올려 같이 숨긴다. 다른 두 패널과 동작이 일치한다. 목록을 보는 동안 확대·현 위치를
  못 쓰는 것은 감수한다 — 모바일에서 확대 버튼은 이미 숨겨져 있고, 같은 맞바꿈을
  시설 필터에서 이미 받아들이고 있다.
- 선택지 B: 패널 `bottom`을 액션 스택 위로 올린다. 버튼은 살아 있지만 목록 높이가
  줄고, 액션 스택 높이가 바뀌면 다시 어긋난다.

회귀 가드는 `e2e/public-map-p0.spec.ts`의 "모바일에서 목록 패널이 지도 액션 버튼·출처
표기와 겹치지 않는다".

## 3. 남은 항목

### MOB-04. 필터 드롭다운이 바깥 탭으로 닫히지 않고, 그 탭이 지도로 샌다 (P1)

드롭다운(390×844에서 y128–406)이 열린 상태로 y446을 탭하면 히트가 건물 폴리곤(`path`)에
잡히고 — 즉 **뒤의 지도가 조작되면서** — 드롭다운은 그대로 열려 있다.

`LanguageSwitcher`는 바깥 `pointerdown`과 Escape로 닫는 처리가 있으나(`rootRef`로
포함 여부 판정), `FilterPanel`과 `MapBrowseList`에는 없다. 세 개가 같은 지도 위
드롭다운인데 닫히는 방식이 다르다.

### MOB-05. 터치 타깃 (P2)

| 요소                                                | 실측 크기  | 비고                                   |
| --------------------------------------------------- | ---------- | -------------------------------------- |
| `.ku-side-handle`                                   | 390×**22** | WCAG 2.5.8 최소 24×24 미달             |
| 관리자 `← 대시보드`                                 | 60×**15**  | 동일                                   |
| `.ku-search-clear`                                  | 26×26      |                                        |
| `.ku-side-close` · `.ku-feedback-close` · 목록 닫기 | 36×36      | 이 저장소가 곳곳에 세운 44px 기준 미달 |
| `.ku-chip` · `.ku-side-action`                      | 높이 40    | 동일                                   |

`.ku-side-handle`은 `.ku-side-close`와 접근 이름이 둘 다 "닫기"로 겹치기도 한다.

착수하려면 먼저 **어느 기준을 쓸지** 정해야 한다. WCAG 2.5.8(24×24)만 넘길지, 이
저장소가 이미 여러 곳에 적어 둔 44px을 기준으로 볼지에 따라 손댈 범위가 크게 달라진다.
지도 화면은 컨트롤이 조밀해 전부 44px로 올리면 지도 가시 영역이 줄어든다.

### MOB-06. safe-area 처리가 실제로는 꺼져 있다 (P2)

브라우저에서 읽은 값:

```
<meta name="viewport">        =  width=device-width, initial-scale=1
env(safe-area-inset-bottom)   =  0px
```

`src/app/layout.tsx`에 `export const viewport`가 없어 Next 기본 태그가 나가고, 그 기본값에는
`viewport-fit=cover`가 없다(`node_modules/next/dist/docs/01-app/03-api-reference/04-functions/generate-metadata.md`
의 "Default Fields" 절). 그래서 `map-ui.css`와 `admin-ui.css`가 쓰는
`env(safe-area-inset-bottom)` 여섯 군데가 전부 0으로 계산된다.

기본값(`viewport-fit=auto`)에서는 브라우저가 이미 안전 영역 안쪽에 레이아웃하므로
**지금 가려지는 것은 없다.** 문제는 그 코드가 아무 일도 하지 않으면서 처리한 것처럼
보인다는 점이다. 둘 중 하나를 골라야 한다.

- `viewport: { viewportFit: "cover" }`를 켠다 — 화면 끝까지 쓰고 env()가 의도대로 산다.
  대신 노치·홈 인디케이터가 있는 기기에서 전 화면을 다시 확인해야 한다.
- env() 호출을 지운다 — 지금 동작과 동일하고 코드가 정직해진다.

## 4. 문제 없음으로 확인한 범위

- **쌓임 맥락에 z-index가 갇히는 사례**: 앱 코드 기준 추가 0건. 검출된 것은 전부
  Leaflet 내부 pane(map-pane 400 아래 marker 600·popup 700 등, 의도된 구조)이다.
  관리자 모달 4종은 인라인 `zIndex:2000`으로 헤더(100) 위에 정상적으로 뜬다.
- **가로 스크롤 넘침**: 0건.
- **상세 패널**: 390×844에서 `scrollHeight` 896 / `clientHeight` 523으로 스크롤 정상.
  잘려서 못 읽는 구간 없음.
- **모바일 분기**: `resize` 리스너와 ref로 최신값을 유지하고, 호버 툴팁은 모바일에서
  렌더되지 않는다.

## 5. 점검의 한계

전 뷰포트 × 전 상태 조합을 돌리려 했으나 상태당 로딩이 40~90초라 완주하지 못했다.
그래서 **가장 빡빡한 320×568로 공개 지도 상태 9종을 훑고, 390×844에서는 거기서 나온
항목을 지목 검증**하는 방식으로 좁혔다. 360×640은 두 값 사이라 별도 결함이 나올 여지가
낮다고 보고 건너뛰었다 — 확인한 것이 아니라 판단이다.

관리자 화면은 4개(`/admin/dashboard`, `/admin/buildings`, `/admin/buildings/new`,
`/admin/dashboard/feedback`)만 390×844에서 훑었다. 모달을 연 상태와 건물 상세 화면은
포함되지 않았다.
