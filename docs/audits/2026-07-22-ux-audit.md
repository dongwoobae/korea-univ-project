# 고려대학교 배리어프리 지도 UX 전수 점검

- 점검일: 2026-07-22
- 점검 기준 커밋: `678d813`
- 대상: 공개 지도, 모바일 공개 화면, 관리자 로그인 및 관리 화면, 시스템 다크 모드
- 점검 방식: 주요 사용자 여정의 Playwright 목 데이터 렌더링, 데스크톱/모바일/다크 모드 시각 점검, 상호작용·오류 상태·접근성 코드 감사

## 1. 요약

핵심 지도 기능과 관리자 CRUD 흐름은 동작하지만, 배포 전에 우선 처리할 문제가 있다. 특히 모바일에서 언어 변경과 즐겨찾기 접근이 불가능하고, 관리자 다크 모드에서는 일부 콘텐츠를 읽기 어려우며, 지도 데이터 로드 실패가 빈 데이터처럼 보일 수 있다.

우선순위별 권장 조치는 다음과 같다.

1. 모바일 언어 선택·즐겨찾기·관리자 메뉴 복구
2. 관리자 다크 모드와 데이터 오류 상태 수정
3. 캠퍼스 필터 의미 정리 및 현재 위치 표시 개선
4. 모달·토스트·폼 접근성 정비
5. 관리자 검색·필터·페이지네이션과 데이터 품질 현황 추가
6. 접근 가능한 경로 안내 사용자 여정 설계

## 2. 우선순위 기준

| P1   | 주요 작업을 불필요하게 어렵게 하거나 반복적인 실수 가능성이 높은 문제                                |

| P3   | 장기적인 제품 가치와 완성도를 높이는 개선 과제                                                       |

## 3. 즉시 개선이 필요한 항목

> **진행 상태 (2026-07-22)**: 이 절의 P0 6건 + [UX-P1-12](#ux-p1-12-건물-상세의-시설-상태-변경-오류를-확인하지-않음)를 구현 완료. 상세 구현 명세는 [`docs/specs/2026-07-22-ux-implementation-spec.md`](../specs/2026-07-22-ux-implementation-spec.md). 검증: `tsc --noEmit`·`next build`·E2E **32건 전부 통과**(기존 19 + 신규 13, 회귀 없음). 신규 E2E: 모바일 언어 드롭다운/즐겨찾기 배지(`e2e/public-map-p0.spec.ts`), 시설 API·건물상세 오류 상태, 모바일 관리자 메뉴·시설 상태변경 실패(`e2e/admin-p0.spec.ts`), 다크 모드 대비 회귀 가드(`e2e/admin-dark.spec.ts` — 전 관리자 화면+모달에서 미이관 하드코딩 밝은색·근검정 텍스트 0을 computed-style로 단언). 이 배치의 P0 후속 과제 없음.

### UX-P0-01. 모바일에서 언어를 변경할 수 없음 ✅ 구현 완료 (2026-07-22)

- 사용자 영향: 현재 선택된 언어 버튼 하나만 보이며, 이를 눌러도 같은 언어가 다시 선택된다. 한국어가 익숙하지 않은 사용자가 영문·중문 UI에 접근할 수 없다.
- 근거: `src/components/map/map-ui.css`의 모바일 규칙은 비활성 언어 버튼을 모두 숨긴다. `src/components/map/LanguageSwitcher.tsx`에는 메뉴를 펼치는 상태가 없고 버튼 클릭 시 즉시 `setLang`만 호출한다.
- 권장 개선: 현재 언어 버튼을 누르면 세 언어가 펼쳐지는 드롭다운 또는 팝오버로 변경한다. 바깥 클릭과 Escape로 닫히고, 선택 후 트리거로 초점이 돌아와야 한다.
- 완료 기준: 390px 화면에서 한국어·영어·중국어를 모두 선택할 수 있고 키보드와 스크린리더로도 동일하게 조작할 수 있다.

### UX-P0-02. 모바일에서 즐겨찾기에 접근할 수 없음 ✅ 구현 완료 (2026-07-22)

- 사용자 영향: 데스크톱에서는 검색창 옆에 있는 즐겨찾기 버튼이 모바일 CSS에서 완전히 숨겨진다. 저장한 건물을 모바일에서 다시 찾을 수 없다.
- 근거: `src/components/map/map-ui.css`의 `.ku-favorite-button` 모바일 규칙이 `display: none`을 사용한다.
- 권장 개선: 검색창 내부, 모바일 필터 트리거 옆 또는 하단 액션 영역에 즐겨찾기 진입점을 유지한다. 저장 개수 배지를 함께 표시하면 발견하기 쉽다.
- 완료 기준: 모바일에서 즐겨찾기 목록 열기, 빈 상태 확인, 항목 선택과 지도 이동이 가능하다.

### UX-P0-03. 관리자 다크 모드의 콘텐츠 대비가 깨짐 ✅ 구현 완료 (2026-07-22)

- 사용자 영향: 관리자 시설·명소·경사도 카드가 흰색으로 고정된 반면 상위 텍스트 색상은 다크 모드 토큰을 상속해 밝아진다. 시설명과 설명이 거의 보이지 않는다.
- 근거: `src/app/admin/admin-ui.css`의 `.ku-admin-content > div` 색상 토큰과 관리자 페이지의 `background: "#fff"` 인라인 스타일이 충돌한다.
- 권장 개선: 관리자 페이지의 하드코딩된 흰색·검정색·회색을 `--ku-surface`, `--ku-text-*`, `--ku-border` 토큰으로 교체한다. 상태 배지와 주요/위험 버튼도 양쪽 색상 모드에서 대비를 검증한다.
- 완료 기준: 시스템 다크 모드에서 관리자 로그인, 네 개 목록, 건물 상세와 모든 모달의 본문·보조문구·입력값이 WCAG AA 대비로 읽힌다.

### UX-P0-04. 공개 지도 데이터 오류가 빈 데이터처럼 보임 ✅ 구현 완료 (2026-07-22)

- 사용자 영향: 시설·경사도·명소 요청 실패가 무시되며, 건물 요청 실패도 로딩만 종료된다. 사용자는 실제로 정보가 없는 것인지 서비스 장애인지 구분할 수 없다.
- 근거: `src/components/map/useMapData.ts`에서 시설과 경사도 요청의 `catch`가 비어 있고, 명소 실패는 빈 배열로 대체된다. 응답의 `ok` 여부도 확인하지 않는다.
- 권장 개선: 데이터 종류별 `loading/error/ready` 상태를 두고 지도 상단에 재시도 가능한 비차단 안내를 제공한다. 접근성 시설 정보는 오류를 빈 상태로 대체하지 않는다.
- 완료 기준: 각 API의 4xx, 5xx, 네트워크 실패에서 오류 종류와 재시도 동작이 표시되며, 빈 데이터 문구와 구분된다.

### UX-P0-05. 건물 상세 조회 실패가 ‘정보 없음’처럼 보임 ✅ 구현 완료 (2026-07-22)

- 사용자 영향: 건물·시설·사진 쿼리 오류를 검사하지 않아 시설 정보가 없는 건물로 오해할 수 있다.
- 근거: `src/components/SidePanel.tsx`의 병렬 조회는 반환된 오류를 사용하지 않고 데이터만 상태에 저장한다.
- 권장 개선: 건물 기본 정보, 시설, 사진 중 어느 조회가 실패했는지 구분하고 해당 섹션에 재시도 버튼을 제공한다.
- 완료 기준: 조회 실패 시 `등록된 시설 정보가 없습니다` 대신 오류 안내가 나타나며 다시 불러올 수 있다.

### UX-P0-06. 모바일 관리자에서 설정과 지도 보기에 접근할 수 없음 ✅ 구현 완료 (2026-07-22)

- 사용자 영향: 모바일 관리자 헤더에는 로그아웃만 남는다. 피드백 수신 이메일 설정과 공개 지도 확인 경로가 사라진다.
- 근거: `src/app/admin/admin-ui.css`에서 `.ku-admin-settings`, `.ku-admin-map-link`를 모바일에서 숨긴다.
- 권장 개선: 헤더의 더보기 메뉴 또는 계정 메뉴에 이메일 설정, 공개 지도 보기, 로그아웃을 모두 제공한다.
- 완료 기준: 모바일 관리자에서 데스크톱과 같은 계정·설정 기능에 접근할 수 있다.

## 4. 공개 지도 UX 개선 항목

### UX-P1-01. 캠퍼스 필터의 동작과 명칭이 일치하지 않음 ✅ 구현 완료 (2026-07-22)

> **결정**: 실제 동작(경계 표시 전용)에 맞춰 명칭만 정직화. `campusTitle`을 `캠퍼스 영역`(en `Campus Areas` / zh `校区范围`)으로 리라벨하고 건물 필터링 로직은 도입하지 않음.

- 사용자 영향: 캠퍼스를 선택해도 건물은 그대로이고 캠퍼스 경계만 나타난다. 사용자는 필터가 고장 났다고 느낄 수 있다.
- 근거: `src/components/map/Map.tsx`에서 `activeCampuses`는 `campusBoundaries.features`만 거르는 데 사용된다.
- 권장 개선: 선택한 캠퍼스의 건물만 표시하거나 나머지를 흐리게 처리한다. 경계 표시 기능만 유지한다면 명칭을 `캠퍼스 경계 표시`로 바꾼다.
- 완료 기준: 필터 제목과 실제 지도 변화가 동일한 의미를 전달한다.

### UX-P1-02. 현재 위치가 지도에 남지 않음 ✅ 구현 완료 (2026-07-22)

- 사용자 영향: 위치 버튼은 지도만 이동시키고 사용자 위치 마커나 정확도 범위를 표시하지 않는다. 이동 후 정확한 현재 위치를 알기 어렵다.
- 권장 개선: 현재 위치 마커, 정확도 원, 요청 중 상태, 재시도 동작을 제공한다. 지도 영역 밖 토스트는 유지한다.
- 완료 기준: 허용된 영역 안에서 현재 위치와 정확도 범위가 지도에 남고, 재요청 시 갱신된다.

### UX-P1-03. 모바일 필터 배지가 첫 로드부터 1로 표시됨 ✅ 구현 완료 (2026-07-22)

- 사용자 영향: 사용자가 필터를 조작하지 않아도 명소 기본 표시가 활성 조건으로 계산되어 `1`이 나타난다. 무엇이 적용 중인지 바로 알기 어렵다.
- 근거: `src/components/map/FilterPanel.tsx`의 `totalActive`에 기본값이 `true`인 `showLandmarks`가 포함된다.
- 권장 개선: 사용자가 기본값에서 변경한 조건만 세거나 배지를 `명소 표시 중` 같은 상태 요약으로 바꾼다.

### UX-P1-04. 검색의 탐색성과 결과 상태가 부족함 ✅ 구현 완료 (2026-07-22)

> **범위**: 건물 + 명소 통합(시설은 제외 — 사용자 결정). 세 이름 필드(`name`/`name_en`/`name_zh`)에 리터럴 부분일치(음차 없음). combobox ARIA + 키보드(↓↑·Home/End·Enter·Escape), 결과 없음·개수·초과(cap 8) 안내, 초기화(×) 버튼.

- 문제:
  - 결과가 없을 때 아무 안내도 없다.
  - 방향키로 결과를 이동하거나 Escape로 닫을 수 없다.
  - Enter는 항상 첫 번째 결과를 선택한다.
  - 현재 언어의 건물명만 검색하며 시설·명소는 검색할 수 없다.
  - 결과가 최대 6개로 잘리지만 더 많은 결과가 있다는 안내가 없다.
- 권장 개선: WAI-ARIA combobox 패턴을 적용하고 한국어·영문·중문 이름, 시설, 명소를 통합 검색한다. 결과 없음, 결과 개수와 검색 초기화를 제공한다.

### UX-P1-05. 모바일 상세 패널의 손잡이와 닫기 동작이 불명확함 ✅ 구현 완료 (2026-07-22)

> **범위**: 손잡이를 실제 조작 요소(버튼)로 전환 — 아래로 임계값(80px) 이상 스와이프하면 닫히고, 그 이하면 제자리 복귀. 순수 탭/키보드 활성화도 닫기로 처리(`aria-label`=닫기). 바깥 한 번 탭 닫기는 보조로 유지. 임계값 판정은 리렌더 타이밍에 의존하지 않도록 ref로 최신 오프셋을 읽는다.

- 사용자 영향: 손잡이는 드래그할 수 있을 것처럼 보이지만 장식이며, 패널 바깥을 한 번 누르면 정보가 즉시 닫힌다.
- 권장 개선: 실제 스와이프 단계를 지원하거나 손잡이를 제거한다. 바깥 탭보다 닫기 버튼과 아래로 스와이프를 주 동작으로 사용한다.

### UX-P1-06. 시설 영상에 자막 대체 수단이 없음 ✅ 구현 완료 (2026-07-22)

> **범위**: `<video>`에 접근 이름(`${시설명} 영상`) 부여, 저장된 `video_caption`(언어별 `_en`/`_zh` 폴백)을 `<figure>`/`<figcaption>`으로 영상 바로 아래 텍스트 표시. 관리자 영상 업로드 모달이 캡션 입력·자동번역을 지원하므로 동등 텍스트 = 관리자가 입력한 캡션.
>
> **남은 한계(정직화)**: 캡션이 비어 있으면 접근 이름만 남고 영상 내용(접근 경로 시연·조작법 등)의 동등 텍스트는 보장되지 않는다(시설 행의 이름·위치·설치 여부는 영상 내용을 설명하지 못함). 완료 기준의 "모든 영상"을 충족하려면 **관리자 업로드 시 캡션 필수화**가 필요 — Phase 4 관리자 후속 과제로 분리. (codex UX 리뷰 2026-07-22 지적 반영)

- 사용자 영향: 청각장애 사용자나 소리를 재생할 수 없는 환경에서 영상 내용을 확인하기 어렵다.
- 권장 개선: 저장된 영상 설명을 `<track>` 자막 또는 영상 바로 아래의 텍스트 설명으로 제공한다.
- 완료 기준: 영상마다 접근 가능한 이름과 자막 또는 동등한 텍스트 설명이 있다.

### UX-P1-07. 음성 기능 실패 피드백이 부족함 ✅ 구현 완료 (2026-07-22)

> **범위**: 음성 검색 `alert` → 토스트 전환. `onerror`를 권한 거부(`not-allowed`/`service-not-allowed`)·네트워크(`network`)·인식 실패(`no-speech` 및 기타)로 구분 안내, 사용자 중지(`aborted`)는 무음. "듣는 중" 상태를 `role=status aria-live=polite` 라이브 영역으로 알림. TTS 미지원도 토스트.

- 사용자 영향: 음성 검색 인식 오류는 조용히 종료되고, TTS 미지원 환경에서는 버튼을 눌러도 아무 반응이 없다.
- 권장 개선: 권한 거부, 미지원, 인식 실패, 네트워크 오류를 토스트로 구분해 안내하고 버튼에 듣는 중 상태를 라이브 영역으로 알린다.

### UX-P2-01. 지도 마커와 라벨이 많아질 때 겹침 ✅ 구현 완료 (2026-07-23)

> **결정**: 낮은 줌에서는 가까운 시설·명소를 화면 픽셀 거리 기준으로 묶고, 명소와 지하철역의 상시 라벨은 각각 줌 18·17부터 표시한다. 별도 플러그인 없이 현재 Leaflet 투영 좌표를 사용하며, 군집을 선택하면 개별 마커가 보이는 줌까지 확대한다. 현재 지도 범위의 공개 시설·명소는 활성 필터를 반영해 현 위치 또는 지도 중심에서 가까운 순서의 목록으로 함께 제공한다.

- 사용자 영향: 명소와 역 라벨이 항상 표시되어 데이터가 증가하면 건물과 시설을 가릴 수 있다.
- 권장 개선: 줌 단계별 라벨 생략, 충돌 회피, 시설 클러스터링과 현재 지도 내 결과 목록을 적용한다.

### UX-P2-02. 다크 모드에서도 기본 지도 타일이 밝음 ✅ 구현 완료 (2026-07-23)

> **결정**: 시스템 `prefers-color-scheme`이 다크일 때 CARTO Dark Matter(`dark_all`), 라이트일 때 Positron(`light_all`) 타일을 사용한다. 실행 중 시스템 설정 변경도 즉시 반영하며, 공개 지도·시설/명소 좌표 선택 지도·건물 폴리곤 편집 지도에 같은 규칙을 적용한다. 어두운 타일 위 건물과 캠퍼스 경계에는 식별성이 검증된 항공사진용 고채도 캠퍼스 팔레트를 재사용한다. 항공사진 모드는 시스템 색상 모드와 무관하게 유지하고 OpenStreetMap·CARTO 출처 표기도 그대로 제공한다.

- 사용자 영향: 컨트롤과 상세 패널은 어두워지지만 CARTO 기본 타일은 밝게 유지되어 시각적으로 단절되고 눈부심이 남는다.
- 권장 개선: 시스템 다크 모드에서 사용 가능한 어두운 베이스맵을 검토한다. 타일 공급자 약관과 출처 표기는 기존 검토 기준을 따른다.

### UX-P2-03. 피드백 제출이 `mailto:`에 의존함 ✅ 구현 완료 (2026-07-23)

> **결정**: 공개 `POST /api/feedback`이 유형·내용·페이지 주소를 서버에서 재검증한 뒤 직접 읽기 정책이 없는 `feedback_submissions` 테이블에 저장한다. 이름과 연락처는 받지 않고 저장 항목과 민감정보 입력 금지를 폼에 안내한다. 제출 중·성공·실패 상태를 명시하며 기존 `mailto:`는 서버 제출 실패 시에도 사용할 수 있는 보조 수단으로 유지한다. 단순 봇 제출은 숨김 필드와 요청·본문 길이 제한으로 완화한다.

- 사용자 영향: 로컬 메일 앱이 없거나 학교 웹메일만 사용하는 사용자는 제출할 수 없다.
- 권장 개선: 서버 제출을 기본으로 하고 `mailto:`를 보조 수단으로 제공한다. 제출 성공·실패와 개인정보 안내를 명시한다.
- 후속 결정: 관리자 페이지에서 접수·조회·처리하는 피드백함을 구축한 뒤 `mailto:` 보조 수단을 제거한다. 이번 범위에서는 피드백 코드를 변경하지 않으며 상세 범위와 완료 조건은 [관리자 피드백함 후속 개발 문서](../future-development/admin-feedback-inbox.md)에서 관리한다.

### UX-P3-01. 접근 가능한 경로 안내가 대표 여정으로 제공되지 않음 ↗ 후속 개발 이관

- 사용자 영향: 건물과 시설은 찾을 수 있지만 출발지에서 목적지까지 접근 가능한 경로를 판단하기 어렵다.
- 권장 개선: 장기적으로 `출발지 선택 → 목적지 선택 → 엘리베이터·경사도·공사 구간을 반영한 경로 → 구간별 주의사항`을 핵심 여정으로 설계한다.
- 범위 결정: 보행로 네트워크와 현장 검증이 필요한 독립적인 개발 규모이므로 현재 지도 완성 범위에서 제외한다. 상세 설계와 단계별 범위는 [접근 가능한 경로 탐색 후속 개발 문서](../future-development/accessible-routing.md)에서 관리한다.

## 5. 관리자 UX 개선 항목

### UX-P1-08. 신규 건물 등록에 기존 DB 캠퍼스 선택이 남아 있음 ✅ 구현 완료 (2026-07-23)

> **결정**: 수동 선택을 제거하고 폴리곤 기반 판정 결과만 읽기 전용으로 표시한다. 어느 캠퍼스에도 포함되지 않는 건물은 경고를 표시하되, 인접 지역 데이터일 수 있으므로 `campus=null`로 저장을 허용한다.

- 사용자 영향: 관리자가 선택하는 `서울/의료원/녹지` 값과 GeoJSON 영역으로 판정하는 실제 캠퍼스 구분이 충돌한다.
- 근거: `src/app/admin/buildings/new/page.tsx`에서 `campus` 상태와 선택 입력을 유지하며 그대로 DB에 저장한다.
- 권장 개선: 수동 캠퍼스 필드를 제거하고 폴리곤 저장 후 영역 기반 판정 결과를 읽기 전용으로 표시한다. 경계 밖이면 저장 전에 경고한다.

### UX-P1-09. 시설·명소 위치의 캠퍼스 영역 여부를 알 수 없음 ✅ 구현 완료 (2026-07-23)

> **결정**: 캠퍼스 경계는 데이터 분류와 입력 실수 발견을 위한 안내 기준이며 서비스 범위의 하드 제한이 아니다. 고려대와 인접하고 학생 유동이 많은 지역의 시설·명소도 가치가 있으므로, 영역 밖 경고를 즉시 표시하되 저장은 허용한다.

- 사용자 영향: 현장 조사 중 GPS 오차나 잘못된 지도 클릭을 알아채기 어렵고, 반대로 유효한 인접 지역 데이터까지 일률적으로 차단하면 서비스 가치가 줄어든다.
- 구현: 공개 지도와 건물 목록에서 쓰는 경계 판정 로직을 시설·명소 폼에도 재사용한다. 선택 위치의 캠퍼스 또는 영역 밖 경고를 라이브 영역으로 표시하고, 경고 상태에서도 저장할 수 있다.

### UX-P1-10. 건물 폴리곤과 건물 자체를 두 번 저장해야 함 ✅ 구현 완료 (2026-07-23)

> **결정**: 신규 건물 폼에서는 지도에 폴리곤이 완성되거나 편집되는 즉시 폼의 `geojson` 상태에 반영하고, 하단 `건물 저장` 한 번으로 기본 정보와 폴리곤을 함께 저장한다. 지도 내장 삭제 모드는 제거하며 기존 폴리곤이 있을 때 새 그리기를 잠근다. 교체는 경고 내용을 확인한 뒤 `폴리곤 지우고 다시 그리기`를 명시적으로 선택해야 한다.

- 사용자 영향: 폴리곤 편집기에서 저장한 뒤 다시 페이지 하단의 건물 저장을 눌러야 해 완료했다고 오해하기 쉽다.
- 권장 개선: 단일 제출로 합치거나 `기본 정보 → 폴리곤 → 검토 및 저장` 단계형 폼으로 변경한다.

### UX-P1-11. 시설 상태 표시와 변경 동작이 하나의 배지에 섞임 ✅ 구현 완료 (2026-07-23)

> **결정**: 시설 상태는 읽기 전용 `현재 상태: 설치/미설치` 배지로 표시하고, 상태 변경은 `미설치로 변경/설치로 변경` 버튼으로 분리한다. 독립 시설 목록과 건물 상세의 시설 목록에 같은 공용 컨트롤을 사용한다.

- 사용자 영향: `설치` 버튼이 현재 상태인지, 누르면 설치로 바뀌는 동작인지 모호하다.
- 권장 개선: `현재 상태: 설치`와 `미설치로 변경`을 분리하거나 명확한 스위치와 설명을 사용한다.

### UX-P1-12. 건물 상세의 시설 상태 변경 오류를 확인하지 않음 ✅ 구현 완료 (2026-07-22)

- 사용자 영향: DB 변경이 실패해도 성공 토스트가 표시될 수 있어 관리자가 잘못된 상태를 신뢰하게 된다.
- 근거: `src/app/admin/buildings/[id]/page.tsx`의 `handleToggleInstalled`는 업데이트 오류를 검사하지 않는다.
- 권장 개선: 오류 검사, 처리 중 비활성화, 낙관적 갱신 롤백과 재시도를 적용한다.

### UX-P1-13. 확인·오류 UI가 화면마다 다름 ✅ 구현 완료 (2026-07-23)

> **결정**: GPX 업로드 성공·실패와 삭제 성공·실패는 공용 토스트로 알리고, 삭제 전 확인은 처리 중 중복 실행을 막는 공용 확인 모달을 사용한다.

- 사용자 영향: 경사도 화면은 브라우저 기본 `alert/confirm`을 사용하고 다른 화면은 토스트와 확인 모달을 사용한다.
- 권장 개선: GPX 업로드·삭제도 공용 토스트와 확인 모달로 통일한다.

### UX-P1-14. 긴 건물 상세 화면의 작업 위치를 잃기 쉬움 ✅ 구현 완료 (2026-07-23)

> **결정**: 기존 2열/연속 편집 흐름은 유지하면서 사진·이름·소속·폴리곤·시설·삭제/복구로 바로 이동하는 고정 섹션 내비게이션과 현재 섹션 강조를 제공한다. 이름·소속·폴리곤의 미저장 상태를 상단과 해당 섹션에 표시하고, 새로고침·탭 닫기·상단 이동 버튼 사용 시 이탈 경고를 표시한다.

- 사용자 영향: 사진·이름·학과·폴리곤·시설·삭제가 한 페이지에 이어져 모바일과 반복 작업에서 이동량이 많다.
- 권장 개선: 섹션 내비게이션 또는 탭, 상단 요약, 저장되지 않은 변경 경고를 제공한다.

### UX-P2-04. 건물 외 관리 목록에 검색·정렬·필터가 없음 ✅ 구현 완료 (2026-07-23)

> **결정**: 독립 시설에는 다국어 이름·설명 검색, 시설 유형·설치 상태 필터와 최근/오래 수정순·이름순 정렬을 제공한다. 명소에는 이름·설명 검색과 사진 유무 필터, 경사도에는 경로명·GPX 파일명 검색을 제공하며 두 목록에도 같은 정렬을 적용한다. 세 목록의 정확한 최근 수정순을 위해 `updated_at`과 자동 갱신 트리거를 추가하고 기존 행은 `created_at`으로 초기화한다.

- 사용자 영향: 시설·명소·경사도 데이터가 늘면 특정 항목이나 미설치 시설을 찾기 어렵다.
- 권장 개선: 이름 검색, 시설 유형·설치 상태 필터, 최근 수정일 정렬을 제공한다.

### UX-P2-05. 관리자 목록에 페이지네이션이 없음 ✅ 구현 완료 (2026-07-23)

> **결정**: 건물·독립 시설·명소·경사도 목록은 필터·검색·정렬을 Supabase 쿼리에 반영하고 페이지당 20개 행과 정확한 총 개수만 조회한다. 조건 변경 시 첫 페이지로 돌아가며 삭제 등으로 마지막 페이지가 비면 유효한 페이지로 보정한다. 건물별 시설 개수도 전체 시설을 내려받지 않고 현재 페이지의 건물 ID에 해당하는 행만 조회한다. 데스크톱과 모바일에 `현재 N개 / 총 N개`, 이전·다음 페이지와 현재 페이지 위치를 동일하게 제공한다.

- 사용자 영향: 데이터가 증가할수록 초기 로드와 DOM 렌더링이 느려지고 스크롤 작업이 길어진다.
- 권장 개선: 서버 측 페이지네이션과 `총 N개 / 현재 N개` 표시를 사용한다.

### UX-P2-06. 업로드 진행과 부분 실패를 파악하기 어려움 ✅ 구현 완료 (2026-07-23)

> **결정**: 건물 사진 다중 업로드는 선택한 파일마다 `대기 중 → 압축 중 → 업로드 중 → 완료/실패` 상태를 같은 패널에 유지한다. 전체 배치의 성공·실패 개수를 라이브 영역으로 알리고, 일부 파일만 실패하면 성공 결과는 보존한 채 실패 파일만 다시 시도할 수 있다. 파일 선택기는 처리 중 중복 실행을 막고, 전부 성공한 뒤에는 결과 패널을 닫을 수 있다.

- 사용자 영향: 사진 다중 업로드는 전체 `업로드 중` 상태만 보여주며 파일별 진행률과 재시도가 없다.
- 권장 개선: 파일별 대기·압축·업로드·성공·실패 상태, 성공/실패 개수와 실패 항목 재시도를 제공한다.

### UX-P2-07. 자동 번역 실패가 저장 성공에 묻힘 ✅ 구현 완료 (2026-07-23)

> **결정**: 시설 원문 저장과 번역 상태를 분리해 `pending`·`translated`·`failed`로 영속화한다. 원문은 저장됐지만 번역 API 또는 번역 컬럼 갱신이 실패하면 경고 토스트와 `번역 필요` 배지를 표시하고, 독립 시설 목록과 건물별 시설 목록에서 원문 기준 재번역을 실행할 수 있다. 기존 데이터도 원문이 있는데 영문·중문 중 하나가 비어 있으면 마이그레이션 시 `pending`으로 분류한다.

- 사용자 영향: 시설 원문은 저장되지만 영문·중문이 오래된 상태로 남을 수 있다.
- 권장 개선: 원문 저장 성공과 번역 상태를 분리하고 `번역 필요` 배지와 재번역 동작을 제공한다.

### UX-P2-08. 관리자 현황이 단순 개수에 그침 ✅ 구현 완료 (2026-07-23)

> **결정**: 건물 관리 첫 화면은 공개 건물 기준으로 등록 시설 수와 `시설 정보 없음`, `사진 없음`, `위치 없음`, `갱신일 없음 또는 1년 이상 경과`, `번역 대기·실패 시설`을 DB 함수 한 번으로 집계한다. 브라우저에서 전체 건물·시설·사진 행을 내려받아 세지 않으며, 보완 필요 값이 1개 이상이면 경고 색상으로 강조한다.

- 사용자 영향: 어느 건물을 먼저 조사하거나 보완해야 하는지 판단하기 어렵다.
- 권장 개선: 기존 등록 시설 수는 유지하면서 `시설 정보 없음`, `사진 없음`, `위치 없음`, `갱신일 오래됨`, `번역 필요` 개수를 추가한다.

## 6. 접근성 공통 개선 항목

### A11Y-P1-01. 관리자 폼 레이블과 입력 요소가 프로그램적으로 연결되지 않음

- 문제: 많은 `<label>`이 `htmlFor` 없이 입력 요소와 분리되어 있다.
- 개선: 모든 입력에 고유 `id`, 연결된 `htmlFor`, 오류 설명의 `aria-describedby`를 제공한다.

### A11Y-P1-02. 모달 초점 관리가 부족함

- 문제: 시설·명소 모달은 dialog 역할만 있고 제목 연결, 최초 초점, 포커스 트랩, 닫은 뒤 초점 복귀가 없다. 공용 확인 모달은 dialog 역할과 Escape 처리도 없다.
- 개선: 공용 Dialog 컴포넌트로 통합하고 `aria-labelledby`, `aria-describedby`, Escape, 포커스 트랩과 복귀를 제공한다.

### A11Y-P1-03. 토스트가 보조기기에 전달되지 않음

- 문제: `src/components/Toast.tsx`에 `role="status"` 또는 `role="alert"`가 없고 닫기 버튼의 접근 가능한 이름도 없다.
- 개선: 성공·정보는 polite status, 오류는 assertive alert로 알리고 닫기 버튼에 명확한 이름을 제공한다.

### A11Y-P1-04. 지도 요소의 목록형 대체 탐색이 부족함 ✅ 구현 완료 (2026-07-23)

> **결정**: 현재 지도 범위와 활성 필터를 반영한 시설·명소 목록을 지도 위의 독립된 disclosure로 제공한다. 항목은 현 위치가 있으면 현 위치, 없으면 지도 중심에서 가까운 순으로 정렬하고, 항목 버튼을 선택하면 해당 위치를 줌 18로 이동한다. 목록은 기본 HTML 제목·목록·버튼 구조로 구성해 마커를 직접 조작하지 않아도 키보드와 스크린리더로 탐색할 수 있게 한다.

- 문제: 시설과 명소를 지도 시각 요소 외의 방식으로 훑어볼 수 없다.
- 개선: 현재 지도 범위의 시설·명소 목록, 거리순 정렬과 검색 결과를 제공해 키보드와 스크린리더 사용자가 동일한 데이터에 접근하게 한다.

### A11Y-P2-01. 일부 관리자 동작의 터치 영역이 작음

- 문제: 수정·삭제·상태 버튼 일부가 권장 터치 영역 44px보다 작다.
- 개선: 모바일에서 최소 44×44px을 확보하고 인접 위험 동작 사이에 충분한 간격을 둔다.

## 7. 권장 구현 단계

### Phase 1. 모바일 핵심 기능 복구

- 모바일 언어 메뉴 구현
- 모바일 즐겨찾기 진입점 복구
- 모바일 관리자 더보기 메뉴 추가
- 관련 공개 지도·관리자 모바일 E2E 추가

### Phase 2. 신뢰성과 다크 모드

- 관리자 인라인 색상을 디자인 토큰으로 전환
- 공개 지도와 상세 패널의 데이터 오류·재시도 상태 구현
- 관리자 상태 변경 오류 처리
- 라이트/다크 시각 회귀 테스트 추가

### Phase 3. 지도 탐색 개선

- 캠퍼스 필터 의미 확정 및 구현
- 현재 위치 마커와 정확도 표시
- 모바일 필터 배지 의미 수정
- 통합 검색과 키보드 탐색 적용
- 줌 단계별 라벨·마커 군집과 현재 지도 범위 목록 적용

### Phase 4. 관리자 작업 효율

- 수동 캠퍼스 선택 제거 및 영역 자동 판정
- 위치의 캠퍼스 영역 판정과 비차단 경고
- 검색·필터·정렬·서버 페이지네이션
- 데이터 품질 요약과 번역 상태 표시

### Phase 5. 접근성 기반 정비

- 공용 Dialog와 Toast 패턴
- 폼 레이블·오류 연결
- 영상 자막/텍스트 설명
- 지도 데이터의 목록형 대체 탐색 적용

### Phase 6. 접근 가능한 경로 안내

- 현재 릴리스 이후의 별도 고도화 단계로 이관
- 출발지·목적지 사용자 여정
- 경사도, 엘리베이터, 공사·통행 제한 데이터 모델
- 구간별 접근성 주의사항과 대체 경로
- 상세 범위: [접근 가능한 경로 탐색](../future-development/accessible-routing.md)

## 9. 점검 범위의 한계

- 점검은 목 데이터와 현재 코드 구조를 기준으로 수행했다.
