## 1. 왜 바꾸는가 — 실측값은 도인데 코드는 %로 읽는다

2026-10-06에 운영 `slope_segments`를 anon 키로 전수 조회했다.

- 39행, 전부 포인트에 `slope`가 실린 수기 포맷이다. `gpx_file`이 있는 행은 없다.
  2026-10-05 생성 38행, 2026-09-01 생성 1행.
- 입력한 사람(동우)이 확인했다: **39행 전부 도(°) 단위로 입력했다.** 현장 측정기가 도를 낸다.
- 코드는 같은 값을 %로 읽는다 — 입력란 단위 표기 `%`(`SlopeSegmentList.tsx`), 색 경계 `slopeColor()`
  (`theme.ts`), 경고 `slopeWarning()`(`slopeRoute.ts`), 공개 팝업 `경사 {absoluteSlope}%`(`SlopeLayer.tsx`).

**공개 지도가 경사를 실제보다 낮게 보여준다.** 10°는 17.6%인데 "10%"로 표시되고 그 색으로 칠해진다.

구간 62개를 두 방식으로 센 결과:

| 범례 칸(현행) | 값을 %로 읽음(지금 화면) | 도→% 변환(실제) |
| ------------- | -----------------------: | --------------: |
| 1% 이하       |                        0 |               0 |
| 1 – 2%        |                        4 |               1 |
| 2 – 5%        |                       21 |               8 |
| 5 – 8.33%     |                       27 |              13 |
| 8.33 – 12%    |                       10 |              10 |
| 12% 초과      |                        0 |          **30** |

변환하면 1/12(8.33%)를 넘는 구간이 62개 중 40개, 거리로 2,644m 중 1,693m다. 지금 범례는 데이터의
절반이 들어가는 칸을 하나("12% 이상")로 뭉갠다.

## 2. 저장 단위는 도, 키는 그대로 `slope`

포인트의 `slope` 값의 의미를 **도(°)**로 확정한다. 저장 포맷의 모양은 바꾸지 않는다.

**데이터 이전이 없다.** 저장된 값이 이미 도다. 틀린 것은 데이터가 아니라 읽는 코드다. 코드 배포만으로
39행이 올바르게 보이고, 배포 순서 문제가 생기지 않는다.

### 2.1 기각한 대안

- **키를 `slopeDeg`로 바꾼다.** 단위가 데이터에 박혀 같은 오해가 재발하기 어렵다. 그러나 39행 jsonb
  일괄 갱신이 필요하고, 코드와 데이터 중 어느 쪽이 먼저 나가도 그 사이 공개 지도가 `slope`를 못 찾는다.
  지금 코드는 `slope`가 없으면 GPX 분기로 떨어져 고도(`ele: null`)로 계산하므로 **전 구간이 0%로**
  그려진다. 이름이 주는 이득이 이 위험을 넘지 못한다.
- **%로 변환해 저장한다.** 법 기준과 같은 단위라 비교가 쉽다. 그러나 측정 원값이 반올림된 파생값으로
  바뀌고, 39행 이전이 필요하며, 입력은 도·저장은 %로 단위가 갈린다.
- **도와 %를 둘 다 저장한다.** 같은 사실을 두 곳에 적는다. 한쪽만 고쳐지는 순간 어느 쪽이 참인지
  알 수 없다.

키 이름이 단위를 말하지 않는 문제는 `SlopeRoutePoint.slope`의 타입 주석, 입력란의 단위 표기, 이 문서로 막는다.

### 2.2 정밀도 — 경사는 반올림해 저장하지 않는다

`toStoredSegments`는 지금 `slope`와 `distance`를 모두 `round1`로 반올림한다. **`slope`에서는 반올림을 뗀다.**
`distance`는 `round1` 그대로다.

- 도로 입력한 값은 친 그대로 저장된다. 이미 십진 소수라 잃을 것이 없다.
- %로 입력한 값은 `percentToDeg` 결과를 반올림하지 않고 저장한다.

**어떤 자릿수로 반올림해도 기준선 하나 이상이 위 칸으로 밀린다.** % → 도 → 자릿수 반올림 → % 왕복을 계산한 결과:

| 입력(%)        | 정확한 도 | 소수 1자리    | 2자리            | 3자리           | 4자리           |
| -------------- | --------- | ------------- | ---------------- | --------------- | --------------- |
| 1/18 (5.5556)  | 3.179830° | 5.5909 (넘음) | 5.555853 (넘음)  | 5.555853 (넘음) | 5.555503        |
| 1/12 (8.3333)  | 4.763642° | 8.3972 (넘음) | 8.326933         | 8.333963 (넘음) | 8.333260        |
| `12.5` (= 1/8) | 7.125016° | 12.4557       | 12.508834 (넘음) | 12.499971       | 12.499971       |
| `2`            | 1.145763° | 1.9201        | 2.007398 (넘음)  | 2.000414 (넘음) | 2.000065 (넘음) |

칸·경고 비교는 % 단위로 `값 ≤ 경계 + 1e-9`다. `tan(atan(x))` 왕복의 부동소수 오차(1e-15 규모)가 정확한
경계값을 넘기지 않게 하는 허용오차다. 표시만 반올림한다(%와 도 모두 소수 첫째 자리, 범례 기준선의 도는 둘째 자리).

기존 E2E의 저장값 단언(`slope`가 `9.4`, `7.2`)은 도로 친 값이라 그대로 맞는다.

## 3. 입력·판정·표시

### 3.1 변환은 한 곳

`src/lib/slopeScale.ts`(신규)에 둔다.

- `degToPercent(deg) = tan(deg) × 100`, `percentToDeg(pct) = atan(pct / 100)`
- 기준선 상수는 **비율**로 적는다 — `1/18`, `1/12`, `1/8`. %로 미리 계산한 리터럴(`8.33`)을 쓰지 않는다.
  리터럴은 반올림 오차를 품고 여러 곳에 복사된다(지금 `8.33`이 `theme.ts`·`slopeRoute.ts`·`SlopeLegend.tsx`에
  따로 있다).
- 색 칸(`SLOPE_BANDS`)과 색·경고 판정이 여기 산다. `theme.ts`의 `slopeColor`와 `SlopeLegend.tsx`의
  `ITEMS`가 같은 경계를 따로 적고 있던 것을 하나로 합친다 — 범례와 지도 색이 어긋날 수 없게 된다.
- **밖으로 내놓는 판정 함수는 도를 받고, 이름에 그것을 적는다** — `slopeColorFromDeg(deg)`,
  `slopeWarningFromDeg(deg)`처럼. % 기준 칸 조회는 모듈 안 함수다. 지금 `theme.ts`의
  `slopeColor(absSlopePct)`를 이름 그대로 옮기면, 저장값(도)을 그대로 넘기는 호출부(`SlopeLayer`,
  `SlopeRouteMap`)가 지금의 오독을 새 모듈에서 반복한다.
- 범례가 칸 라벨을 그리려면 경계값이 필요하므로 `SLOPE_BANDS`(경계와 색)는 데이터로 내놓는다.

`slopeRoute.ts`는 경로 계산·검증만 남기고 단위 판단은 `slopeScale.ts`를 부른다.

### 3.2 범위는 도로, 칸·경고는 %로

**입력 범위는 도로 직접 검사한다 — `0 ≤ deg ≤ 45`.** %로 입력한 값도 `percentToDeg`로 바꾼 뒤 같은 검사를
거친다. `atan`은 단조라 `0~100%`와 `0~45°`가 정확히 대응한다.

범위를 %로 바꾼 뒤 검사하면 안 된다. `tan`은 주기 함수라 도 입력 `181°`가 `1.75%`, `-179°`가 `1.75%`,
`200°`가 `36.4%`로 바뀌어 0~100% 검사를 통과하고, 공개 지도에 평지에 가까운 색으로 그려진다.

범위 안(0~45°)에서는 `tan`이 단조이므로 색·경고는 **%로 바꾼 뒤** 비교한다. 법 기준이 비율이라 %에서
경계가 정확히 맞물린다.

| 판정                      | 조건          | 다른 단위 | 지금                      |
| ------------------------- | ------------- | --------- | ------------------------- |
| 입력 범위(저장 막음)      | 0° ≤ 값 ≤ 45° | 0~100%    | 0~100%를 % 값에 직접 적용 |
| 완화 한도 경고(저장 허용) | 1/12 초과 (%) | 4.76°     | 문구 변경                 |
| 오타 의심 경고(저장 허용) | 30% 초과      | 16.70°    | 같음                      |

범위 오류 문구는 두 단위를 함께 적는다 — `N번 구간의 경사도는 0~45°(0~100%) 사이여야 해요`. 오류 목록은 구간 입력란이
아니라 저장 버튼 아래에 한 번 나오므로 고른 단위를 알 필요가 없게 한다.

경고 문구: `1/12 완화 한도 초과`(지금 `법적 기준(1/12) 초과`). 30% 문구는 도 환산을 덧붙인다 —
`이 값이 맞나요? 30%(약 16.7°)를 넘는 보행 경사로는 매우 드뭅니다`. 1/18 초과 안내는 두지 않는다.
실측 62구간 중 51개(82%)가 1/18을 넘어 거의 모든 입력에 뜨는 소음이 된다.

### 3.3 입력 — 단위 선택

- 구간 입력란 위에 `도(°) / 퍼센트(%)` 선택. **경로 단위로 하나**이고 구간마다 고르지 않는다 — 한
  경로는 같은 측정기로 잰다.
- 기본 도. 마지막 선택은 `localStorage`에 기억한다. 읽기·쓰기는 try/catch로 감싸고 실패하면 도.
- 입력란 옆에 다른 단위 환산값을 실시간 표시 — `[ 8 ] °  = 14.1%`. 단위를 잘못 고른 채 입력한
  실수를 그 자리에서 보이게 하는 장치다.
- **입력 문자열은 선택 단위로 들고, 편집기 상태로는 도만 올린다.** 입력할 때마다 도→선택 단위로
  되돌려 `value`에 꽂으면 `8.3`을 치는 도중 `8.29999`로 바뀌는 식의 왕복 오차가 입력을 흔든다.
- 단위를 바꾸면 이미 입력한 값은 **물리량을 유지**한다. 저장될 도 값은 그대로이고, 입력란의 문자열만
  새 단위로 다시 쓴다.
- 기존 경로를 열면 저장된 도 값을 선택 단위로 바꿔 채운다.

### 3.4 표시

- 공개 지도 팝업: `경사 17.6% (10.0°)`. %를 앞에 둔다 — 범례 경계가 %로 읽히기 때문이다.
- 범례: 칸마다 `% · °` 병기. 아래에 기준선 세 줄.

기준처럼 읽힐 수 있어 15%를 택했다.

## 5. 편집기 사용성

`/admin/slopes/new`, `/admin/slopes/[id]`의 `SlopeRouteEditor` + `SlopeRouteMap`.

### 5.1 배치 — 항상 위아래

`SlopeRouteEditor`의 2열 그리드(`minmax(0, 2fr) minmax(260px, 1fr)`)를 없앤다. 지도를 전체 폭으로 위에,
그 아래 단위 선택·스냅 토글·구간 입력란을 쌓는다. 모바일·데스크톱 같다.

지금 375px 폭에서는 페이지 패딩 24px×2를 빼고 둘째 열 최소 260px과 간격 20px을 주면 지도 열이 47px이다.
관리자가 "데스크톱 버전으로 보기"로 우회해 작업했다.

### 5.2 구간 번호

그리기가 끝나면 각 구간 중점에 번호표(`1`, `2`, …)를 띄운다. 입력란의 `구간 N`과 같은 번호다.
꼭짓점을 끌면 따라 옮긴다 — 미리보기 선을 다시 그리는 effect가 같이 다시 그린다.

번호표는 `pmIgnore: true`, `interactive: false`로 만든다. geoman의 스냅·전역 모드 대상에서 빠지고
편집선으로 가야 할 클릭을 가로채지 않는다(5.5의 근거와 같다).

### 5.3 최대 줌 19

지금 지도에도 타일 레이어에도 `maxZoom`이 없어서 Leaflet `TileLayer` 기본값 18이 지도 상한이 된다.
첫 `setView(center, 19)`는 타일 레이어를 붙이기 전이라 19로 들어갔다가 레이어가 붙으며 18로 깎인다.

지도와 타일 레이어 모두 `maxZoom: 19`. 공개 지도(`Map.tsx`의 `setMaxZoom(19)`, `TileLayer maxZoom={19}`)와
같은 상한이다. CARTO `light_all`은 키를 붙이면 캠퍼스 좌표에서 z19 이상도 실제 내용을 준다
(2026-10-06 확인. 키 없이는 모든 줌에서 "API KEY REQUIRED" 타일).

### 5.4 현재 위치에서 열기

- **새 경로일 때만.** 열자마자 `navigator.geolocation.getCurrentPosition`(고정밀, 제한 10초).
  받은 위치가 캠퍼스 범위 안이면 그 자리를 줌 18로 연다. 19로 열면 주변이 안 보인다.
- 거부·실패·시간 초과·범위 밖이면 지금처럼 `KU_CENTER`. 따로 알리지 않는다.
- 기존 경로 편집은 지금처럼 선에 맞춘다(`fitBounds`).
- **위치 응답보다 사용자가 먼저 움직이면 화면을 옮기지 않는다.** 응답은 최대 10초 뒤에 온다. 그 사이
  지도를 끌거나 확대·축소했거나 그리기를 시작했으면, 늦게 온 응답이 그 화면을 줌 18의 다른 곳으로
  순간이동시킨다 — 그리던 선이 화면 밖으로 사라진다. 첫 `dragstart`·`zoomstart`·`pm:drawstart`가
  일어나면 자동 이동을 취소한다. 새 경로 화면은 첫 `setView` 뒤 응답 전까지 코드가 지도를 움직이지
  않으므로 이 사이의 `zoomstart`는 사용자 조작이다. 파란 점은 그래도 찍는다.
- 편집기가 사라진 뒤(페이지 이탈) 도착한 응답은 아무것도 하지 않는다. 지도 정리 시 취소 표시를 세운다.
- 꼭짓점을 찍지 않는다. 내 위치는 **파란 점**으로만 표시한다 — `pmIgnore: true`, `interactive: false`.
  현장에서 경로 위 어디에 서 있는지 보며 그리기 위한 것이다.
- 파란 점은 **처음 받은 위치에 고정**한다. 위치를 계속 따라가지 않는다(`watchPosition` 아님). 측정은 한
  자리에 서서 하고 걸으면서 하지 않는다(동우, 2026-10-06).
- 현재 위치로 다시 이동하는 버튼은 두지 않는다.
- 범위는 공개 지도의 `KU_BOUNDS`(`Map.tsx`) 값이다. 지금 `Map.tsx` 안에 `L.latLngBounds([lat, lng], [lat, lng])`로
  묶여 있다. **Leaflet을 import하지 않는 새 모듈 `src/lib/mapBounds.ts`**로 옮기고 두 지도가 각자
  `L.latLngBounds`로 감싼다. `src/lib/neighborLayer.ts` 파일 주석이 설명하는 SSR 제약 때문이다.
  - 값은 이름 있는 필드로 둔다 — `{ south, west, north, east }`. 무명 숫자 쌍이면 `[lat, lng]`와
    `[lng, lat]`이 뒤집혀도 타입이 잡지 못하고 범위 판정만 조용히 틀린다.
  - `src/lib/campusGeometry.ts`에 두지 않는다. 그 모듈은 GeoJSON `Position`(`[lng, lat]`)을 다룬다.

### 5.5 건물 표시와 스냅 토글

`fetchNeighborBuildings` + `addNeighborLayer`로 회색 건물과 이름을 깐다. 건물 영역 편집기
(`PolygonEditor.tsx`)와 같다.

그대로 깔면 안 되는 이유 — geoman 2.19.3 배포본(`dist/leaflet-geoman.js`)에서 확인했다:

- **스냅 목록**은 지도 위 `L.Polyline`(폴리곤 포함)·`L.Marker`·`L.CircleMarker` 전부다. 빠지는 것은
  `snapIgnore: true`이거나, `snapIgnore`가 없으면서 `pmIgnore: true`인 레이어뿐이다. `interactive: false`는
  보지 않는다.
- **전역 드래그·편집 대상**은 `pm`이 있고 `pmIgnore`가 아닌 레이어다(`LayerGroup`·geoman 임시 레이어 제외).
  편집기 툴바는 `dragMode: true`다.

그래서:

- `addNeighborLayer`에 선택 인자로 레이어 옵션을 받게 한다. 편집기는 `pmIgnore: true, snapIgnore: false`로
  깐다 — 드래그·편집 대상에서는 빠지고 스냅 목록에는 남는다. 기존 호출부(`PolygonEditor`,
  `BuildingPolygonPreview`)는 인자를 주지 않으므로 동작이 그대로다.
- `건물 외곽선에 붙이기` 체크박스, **기본 꺼짐.** geoman 전역 옵션 `snappable`을 켜고 끈다. 꺼진 동안은
  자기 선의 꼭짓점에도 붙지 않는다 — 꼭짓점 2~5개짜리 경로에서 잃는 것이 없다.

### 5.6 geoman 한국어와 액션 버튼 배치

- geoman 내장 한국어(`ko`)를 켠다. 액션이 `끝내기 / 마지막 꼭지점 제거 / 취소`, 안내 툴팁도 한국어가 된다.
  운영을 넘겨받을 사람에게 영어 UI보다 낫다.
- 언어 설정은 geoman 전역이다. 경사도 편집기만 켜면 같은 세션에서 그 화면을 거친 뒤에만 건물 영역
  편집기가 한국어가 된다. **`PolygonEditor`도 같이 켠다.**
- 액션 버튼은 그리기 버튼 오른쪽으로 가로로 뻗어 지도 폭을 가린다. CSS로 그리기 버튼 오른쪽에 **세로로** 쌓아
  왼쪽 위 모서리만 차지하게 한다. 버튼 아래로 쌓으면 툴바의 이동 버튼을 덮는다. 편집기 컨테이너 클래스로 범위를 한정해 건물 영역 편집기의 배치는
  건드리지 않는다.

## 6. GPX 코드 정리 (2026-08-30 문서 7장 실행)

그 문서 7장의 1~3단계(GPX 행 보관·삭제·0건 확인) 중 **삭제와 0건은 운영 데이터로 확인된다**(1장).
1단계(삭제 전 GPX 파일로 보관)가 실행됐는지는 확인할 수 없다.

4단계 목록을 그대로 실행한다. 추가로:

- 관리자 경사도 목록의 GPX 안내 문구 "GPX 등록은 종료됐어요. 경로는 직접 그려서 등록해주세요"를 지운다.
  7장이 말한 "v1에서 남겨둔 업로드 종료 안내"가 이것이다. 목록 행의 `(파일명)` 표시와 검색 대상
  `gpx_file`도 뗀다.
- 7장은 목록의 `?redirected=` Toast effect도 지우라고 했지만 **남긴다.** 같은 effect가 `missing`(삭제된 경로)
  안내에도 쓰인다(`REDIRECT_NOTICE`). `gpx` 항목만 지우고 아래 `invalid` 항목을 더한다.
- `gpx_file` 컬럼은 남긴다. 스키마 변경은 이 범위가 아니다.

### 6.1 저장 포맷은 한 함수로만 읽는다

`readRoutePoints`가 저장 포맷의 **유일한 decoder**가 된다.

- 지금은 `points[1].slope`가 없으면 GPX 행으로 보고 통과시킨다. 이제 그런 행은 없으므로
  **첫 포인트 뒤의 모든 포인트에 `slope`·`distance`가 없으면 그 행을 버린다.**
- 값 범위도 본다 — `0 ≤ slope ≤ 45`(도), `distance > 0`. 지금은 유한성만 본다(`hasFiniteMetrics`). 범위를
  안 보면 `90°`나 음수 거리도 "유효한 저장 포맷"이 된다.
- **관리자 편집 페이지도 이 함수를 거친다.** 지금 `/admin/slopes/[id]`는 DB 값을 `SlopeSegment`로 캐스팅해
  바로 `readStoredVertices`·`readStoredSlopes`에 넘긴다. 그러면 공개 지도가 버리는 행을 편집기는 열고
  다시 저장할 수 있다 — 두 화면이 서로 다른 포맷을 허용한다. decoder가 거부하면 목록으로 보내고
  `REDIRECT_NOTICE.invalid`("저장 형식이 깨진 경로라 열 수 없어요")를 띄운다.

## 8. 테스트 계획

### 8.1 무너지는 기존 단언 — 새 의미로 고쳐 쓴다

입력 단위 기본값이 도라 E2E가 넣는 숫자는 이제 도다.

| 위치 (`e2e/admin-buildings-slopes.spec.ts`)         | 지금                   | 바뀐 뒤                                      |
| --------------------------------------------------- | ---------------------- | -------------------------------------------- |
| 수정 화면 미리보기 색 (목 경로 2, 7.2)              | `#C96C24`              | 7.2° = 12.63% → `#AE3B1E`                    |
| 경고 테스트 `10` 입력                               | `법적 기준(1/12) 초과` | `1/12 완화 한도 초과`                        |
| 경고 테스트 `45` 입력                               | 30% 경고 문구          | 45° = 100% → 새 30% 문구, 저장 가능          |
| 경고 테스트 `120` 입력                              | 저장 막힘              | 저장 막힘. 이제 도 범위 검사(0~45°)가 막는다 |
| 미리보기 색 `1` 입력                                | `#B5AFA8`              | 1° = 1.75% → `#B5AFA8` (그대로)              |
| 미리보기 색 `10` 입력                               | `#AE3B1E`              | 10° = 17.63% → `#7A1414`                     |
| 저장 후 공개 지도 확인 — `slopeColor(10)` 주석과 색 | `#AE3B1E`              | `#7A1414`                                    |
| 저장 후 공개 지도 확인 — 팝업 `"10%"`               | `toContainText("10%")` | `17.6%`와 `10.0°`                            |
| GPX 업로드·거부·다운로드·리다이렉트 테스트          | 있음                   | 삭제 (6장)                                   |

저장값 단언(`slope`가 `9.4`, `7.2`)은 그대로 통과해야 한다. 도로 친 값은 친 그대로 저장된다(2.2).

`120` 입력 테스트는 지금도 통과하지만 이유가 바뀐다. `tan`의 주기성 때문에 `120`만으로는 범위를 도로
검사하는지 %로 검사하는지 구분하지 못한다(`tan(120°)`는 음수라 % 검사로도 막힌다). 아래 8.3에 `181`을 더한다.

### 8.2 vitest

- `slopeScale`: 도↔% 왕복, 0°/45°, 기준선 상수가 비율에서 나오는지
- **기준선 왕복:** % 단위로 입력 → `percentToDeg` → 저장(반올림 없음) → `degToPercent` → 칸 판정이 입력한 %의 칸과
  같은지. 입력값은 두 묶음이다 — 정확한 비율 `WALKWAY_RATIO*100`·`RELAXED_RATIO*100`·`RAMP_EXCEPTION_RATIO*100`(2026-10-06: `100/12`는 `(1/12)*100`보다 1ulp 크다. 넘침은 허용 오차 테스트 `100/12 + 1e-12`가 맡는다), 그리고 사람이 칠 값 `2`·`5.56`·`8.33`·`12.5`·`15`.
  2.2절의 실패를 고정하는 테스트다
- 칸 경계: 각 경계값(포함)과 그 바로 위
- **범위:** `0`·`45` 통과, `-0.1`·`45.01`·`90`·`181`·`-179`·`200` 거부(도 입력). `100%` 통과, `100.01%`·`-1%` 거부(% 입력)
- 경고: 도 입력에 대해 1/12(`4.76` 아님, `4.7636…` 전후)·30%(`16.70°` 전후)
- `toStoredSegments`: `slope`는 반올림하지 않고 `distance`는 `round1`
- `readRoutePoints`: `slope`·`distance` 없는 행, `slope` 범위 밖, `distance ≤ 0`인 행을 버린다

### 8.3 Playwright

- % 단위로 입력하면 도로 저장된다 (목 백엔드가 받은 `slope`)
- 입력란 옆 환산값 표시, 단위 전환 시 물리량 유지
- 도 단위 `181` 입력 → 저장 막힘
- 선을 끝내면 구간 번호표가 구간 수만큼 보인다
- 지도 `getMaxZoom()`이 19
- 위치 권한·좌표를 준 새 경로 화면은 그 좌표 근처로, 권한 거부면 `KU_CENTER`로 열린다. 범위 밖 좌표도 `KU_CENTER`
- 위치 응답 전에 지도를 끌면 응답이 와도 화면이 그대로다
- 375px 뷰포트에서 지도 폭이 페이지 콘텐츠 폭과 같다
- 스냅 체크박스 기본 해제
- 그리기 시작 후 액션 버튼 문구가 `끝내기`
- 공개 지도 경사도 팝업에 `%`와 `°`가 함께 나온다
- 깨진 저장 포맷의 경로를 `/admin/slopes/[id]`로 열면 목록으로 돌아가 `invalid` 안내가 뜬다
- `e2e/admin-dark.spec.ts`가 `/admin/slopes/new`·`/admin/slopes/2`에서 지도 밖 요소의 하드코딩 밝은 색을 검사한다.

## 10. 구현 시 확인할 것

- geoman `setGlobalOptions({ snappable })`는 모든 그리기 도구의 옵션을 그 자리에서 바꾸고, 그리기 중 힌트 마커는
  마우스를 움직일 때마다 `this.options.snappable`을 다시 읽는다(2.19.3 배포본). 그리는 도중의 토글도 바로 반영된다
- `pmIgnore: true, snapIgnore: false`로 깐 건물에 실제로 스냅되는지 브라우저에서 본다. 배포본 코드상 스냅 목록은
  `pm` 객체 없이 레이어 좌표만 쓰지만, 계산 단계까지 따라가 보지는 않았다
- geoman 액션 컨테이너의 실제 DOM 클래스(`leaflet-pm-actions-container` 등)
- `AGENTS.md`의 지시에 따라 `node_modules/next/dist/docs/`의 해당 가이드를 읽고 코드를 쓴다

### B. 건물 사진 라이트박스와 다운로드

- **다운로드 URL 계약:**
  - 운영 사진 69장 전부 Supabase Storage 공개 URL이고 `?t=<timestamp>`가 붙어 있다(2026-10-06 조회).
    다른 origin이라 `<a download>`는 무시된다.

    `?`가 두 번 생기거나, 건물명의 `&`·`#`이 새 파라미터나 fragment로 잘린다.
  - 파일명은 `건물명-번호.webp`.
  - Supabase는 `download=<이름>`에 `Content-Disposition: attachment; filename*=UTF-8''…`로 답한다(같은 날 실제
    사진 URL로 확인, 한글 파일명 포함).
- E2E: 클릭 열림, Esc 닫힘·포커스 복귀, 이전·다음. 다운로드 링크는 URL을 파싱해 `t`가 남아 있는지와
  `download` 값이 기대한 파일명과 같은지 단언한다. 목 사진 URL(`e2e/support/mockBackend.ts`)은 지금 쿼리가 없으므로
