## 1. 왜 바꾸는가 — 실측값은 도인데 코드는 %로 읽는다

2026-10-06에 운영 `slope_segments`를 anon 키로 전수 조회했다.

- 39행, 전부 포인트에 `slope`가 실린 수기 포맷이다. `gpx_file`이 있는 행은 없다.
  2026-10-05 생성 38행, 2026-09-01 생성 1행.
- 입력한 사람(동우)이 확인했다: **39행 전부 도(°) 단위로 입력했다.** 현장 측정기가 도를 낸다.
- 코드는 같은 값을 %로 읽는다 — 입력란 단위 표기 `%`(`SlopeSegmentList.tsx`), 색 경계 `slopeColor()`
  (`theme.ts`), 경고 `slopeWarning()`(`slopeRoute.ts`), 공개 팝업 `경사 {absoluteSlope}%`(`SlopeLayer.tsx`).

**공개 지도가 경사를 실제보다 낮게 보여준다.** 10°는 17.6%인데 "10%"로 표시되고 그 색으로 칠해진다.

구간 62개를 두 방식으로 센 결과:

| 범례 칸(현행)  | 값을 %로 읽음(지금 화면) | 도→% 변환(실제) |
| -------------- | -----------------------: | --------------: |
| 1% 이하        |                        0 |               0 |
| 1 – 2%         |                        4 |               1 |
| 2 – 5%         |                       21 |               8 |
| 5 – 8.33%      |                       27 |              13 |
| 8.33 – 12%     |                       10 |              10 |
| 12% 초과       |                        0 |          **30** |

변환하면 1/12(8.33%)를 넘는 구간이 62개 중 40개, 거리로 2,644m 중 1,693m다. 지금 범례는 데이터의
절반이 들어가는 칸을 하나("12% 이상")로 뭉갠다.

## 2. 저장 단위는 도, 키는 그대로 `slope`

포인트의 `slope` 값의 의미를 **도(°)**로 확정한다. 저장 포맷의 모양은 바꾸지 않는다.

**데이터 이전이 없다.** 저장된 값이 이미 도다. 틀린 것은 데이터가 아니라 읽는 코드다. 코드 배포만으로
39행이 올바르게 보이고, 배포 순서 문제가 생기지 않는다.

### 2.1 기각한 대안

- **키를 `slopeDeg`로 바꾼다.** 단위가 데이터에 박혀 같은 오해가 재발하기 어렵다. 그러나 39행 jsonb
  일괄 갱신이 필요하고, 코드와 데이터 중 어느 쪽이 먼저 나가도 그 사이 공개 지도가 `slope`를 못 찾는다.
  지금 코드는 `slope`가 없으면 GPX 분기로 떨어져 고도(`ele: null`)로 계산하므로 **전 구간이 0%로**
  그려진다. 이름이 주는 이득이 이 위험을 넘지 못한다.
- **%로 변환해 저장한다.** 법 기준과 같은 단위라 비교가 쉽다. 그러나 측정 원값이 반올림된 파생값으로
  바뀌고, 39행 이전이 필요하며, 입력은 도·저장은 %로 단위가 갈린다.
- **도와 %를 둘 다 저장한다.** 같은 사실을 두 곳에 적는다. 한쪽만 고쳐지는 순간 어느 쪽이 참인지
  알 수 없다.

키 이름이 단위를 말하지 않는 문제는 `SlopePoint.slope`의 타입 주석, 입력란의 단위 표기, 이 문서로 막는다.

### 2.2 정밀도 — 도 소수 둘째 자리

`toStoredSegments`는 지금 `round1`로 소수 첫째 자리에서 반올림한다. 도는 둘째 자리(`round2`)로 바꾼다.
`distance`는 첫째 자리 그대로다.

첫째 자리면 %로 입력한 값이 기준선을 넘어간다. 8.33%(1/12) → 4.7636° → `round1` 4.8° → 8.40% →
"1/12 초과"로 바뀐다. 둘째 자리면 4.76° → 8.327%로 기준선 안에 남는다. 이미 저장된 첫째 자리 값은
그대로 유효하다.

## 3. 입력·판정·표시

### 3.1 변환은 한 곳

`src/lib/slopeScale.ts`(신규)에 둔다.

- `degToPercent(deg) = tan(deg) × 100`, `percentToDeg(pct) = atan(pct / 100)`
- 기준선 상수는 **비율**로 적는다 — `1/18`, `1/12`, `1/8`. %로 미리 계산한 리터럴(`8.33`)을 쓰지 않는다.
  리터럴은 반올림 오차를 품고 여러 곳에 복사된다(지금 `8.33`이 `theme.ts`·`slopeRoute.ts`·`SlopeLegend.tsx`에
  따로 있다).
- 색 칸(`SLOPE_BANDS`)과 `slopeColor()`가 여기 산다. `theme.ts`의 `slopeColor`와 `SlopeLegend.tsx`의
  `ITEMS`가 같은 경계를 따로 적고 있던 것을 하나로 합친다 — 범례와 지도 색이 어긋날 수 없게 된다.

`slopeRoute.ts`는 경로 계산·검증만 남기고 단위 판단은 `slopeScale.ts`를 부른다.

### 3.2 판정은 % 기준

색·경고·입력 상한은 모두 **도를 %로 바꾼 뒤** 비교한다. 법 기준이 비율이라 %에서 경계가 정확히 맞물린다.

| 판정                         | 조건(%)              | 도 환산  | 지금                     |
| ---------------------------- | -------------------- | -------- | ------------------------ |
| 입력 하한                    | 0 이상               | 0°       | 같음                     |
| 입력 상한(저장 막음)         | 100 이하             | 45°      | 같음 (단위만 명시)       |
| 완화 한도 경고(저장 허용)    | 1/12 초과            | 4.76°    | 문구 변경                |
| 오타 의심 경고(저장 허용)    | 30 초과              | 16.70°   | 같음                     |

경고 문구: `1/12 완화 한도 초과`(지금 `법적 기준(1/12) 초과`). 30% 문구는 도 환산을 덧붙인다 —
`이 값이 맞나요? 30%(약 16.7°)를 넘는 보행 경사로는 매우 드뭅니다`. 1/18 초과 안내는 두지 않는다.
실측 62구간 중 51개(82%)가 1/18을 넘어 거의 모든 입력에 뜨는 소음이 된다.

### 3.3 입력 — 단위 선택

- 구간 입력란 위에 `도(°) / 퍼센트(%)` 선택. **경로 단위로 하나**이고 구간마다 고르지 않는다 — 한
  경로는 같은 측정기로 잰다.
- 기본 도. 마지막 선택은 `localStorage`에 기억한다. 읽기·쓰기는 try/catch로 감싸고 실패하면 도.
- 입력란 옆에 다른 단위 환산값을 실시간 표시 — `[ 8 ] °  = 14.1%`. 단위를 잘못 고른 채 입력한
  실수를 그 자리에서 보이게 하는 장치다.
- **입력 문자열은 선택 단위로 들고, 편집기 상태로는 도만 올린다.** 입력할 때마다 도→선택 단위로
  되돌려 `value`에 꽂으면 `8.3`을 치는 도중 `8.29999`로 바뀌는 식의 왕복 오차가 입력을 흔든다.
- 단위를 바꾸면 이미 입력한 값은 **물리량을 유지**한다. 저장될 도 값은 그대로이고, 입력란의 문자열만
  새 단위로 다시 쓴다.
- 기존 경로를 열면 저장된 도 값을 선택 단위로 바꿔 채운다.

### 3.4 표시

- 공개 지도 팝업: `경사 17.6% (10.0°)`. %를 앞에 둔다 — 범례 경계가 %로 읽히기 때문이다.
- 범례: 칸마다 `% · °` 병기. 아래에 기준선 세 줄.

## 5. 편집기 사용성

`/admin/slopes/new`, `/admin/slopes/[id]`의 `SlopeRouteEditor` + `SlopeRouteMap`.

### 5.1 배치 — 항상 위아래

`SlopeRouteEditor`의 2열 그리드(`minmax(0, 2fr) minmax(260px, 1fr)`)를 없앤다. 지도를 전체 폭으로 위에,
그 아래 단위 선택·스냅 토글·구간 입력란을 쌓는다. 모바일·데스크톱 같다.

지금 375px 폭에서는 페이지 패딩 24px×2를 빼고 둘째 열 최소 260px과 간격 20px을 주면 지도 열이 47px이다.
관리자가 "데스크톱 버전으로 보기"로 우회해 작업했다.

### 5.2 구간 번호

그리기가 끝나면 각 구간 중점에 번호표(`1`, `2`, …)를 띄운다. 입력란의 `구간 N`과 같은 번호다.
꼭짓점을 끌면 따라 옮긴다 — 미리보기 선을 다시 그리는 effect가 같이 다시 그린다.

번호표는 `pmIgnore: true`, `interactive: false`로 만든다. geoman의 스냅·전역 모드 대상에서 빠지고
편집선으로 가야 할 클릭을 가로채지 않는다(5.5의 근거와 같다).

### 5.3 최대 줌 19

지금 지도에도 타일 레이어에도 `maxZoom`이 없어서 Leaflet `TileLayer` 기본값 18이 지도 상한이 된다.
첫 `setView(center, 19)`는 타일 레이어를 붙이기 전이라 19로 들어갔다가 레이어가 붙으며 18로 깎인다.

지도와 타일 레이어 모두 `maxZoom: 19`. 공개 지도(`Map.tsx`의 `setMaxZoom(19)`, `TileLayer maxZoom={19}`)와
같은 상한이다. CARTO `light_all`은 키를 붙이면 캠퍼스 좌표에서 z19 이상도 실제 내용을 준다
(2026-10-06 확인. 키 없이는 모든 줌에서 "API KEY REQUIRED" 타일).

### 5.4 현재 위치에서 열기

- **새 경로일 때만.** 열자마자 `navigator.geolocation.getCurrentPosition`(고정밀, 제한 10초).
  받은 위치가 캠퍼스 범위 안이면 그 자리를 줌 18로 연다. 19로 열면 주변이 안 보인다.
- 거부·실패·시간 초과·범위 밖이면 지금처럼 `KU_CENTER`. 따로 알리지 않는다.
- 기존 경로 편집은 지금처럼 선에 맞춘다(`fitBounds`).
- 꼭짓점을 찍지 않는다. 내 위치는 **파란 점**으로만 표시한다 — `pmIgnore: true`, `interactive: false`.
  현장에서 경로 위 어디에 서 있는지 보며 그리기 위한 것이다.
- 현재 위치로 다시 이동하는 버튼은 두지 않는다.
- 범위는 공개 지도의 `KU_BOUNDS`(`Map.tsx`) 값이다. 지금 `Map.tsx` 안에 `L.latLngBounds`로 묶여 있다.
  **Leaflet을 import하지 않는 모듈**에 숫자 쌍으로 옮기고 두 지도가 각자 `L.latLngBounds`로 감싼다.
  `src/lib/neighborLayer.ts` 파일 주석이 설명하는 SSR 제약 때문이다.

### 5.5 건물 표시와 스냅 토글

`fetchNeighborBuildings` + `addNeighborLayer`로 회색 건물과 이름을 깐다. 건물 영역 편집기
(`PolygonEditor.tsx`)와 같다.

그대로 깔면 안 되는 이유 — geoman 2.19.3 배포본(`dist/leaflet-geoman.js`)에서 확인했다:

- **스냅 목록**은 지도 위 `L.Polyline`(폴리곤 포함)·`L.Marker`·`L.CircleMarker` 전부다. 빠지는 것은
  `snapIgnore: true`이거나, `snapIgnore`가 없으면서 `pmIgnore: true`인 레이어뿐이다. `interactive: false`는
  보지 않는다.
- **전역 드래그·편집 대상**은 `pm`이 있고 `pmIgnore`가 아닌 레이어다(`LayerGroup`·geoman 임시 레이어 제외).
  편집기 툴바는 `dragMode: true`다.

그래서:

- `addNeighborLayer`에 선택 인자로 레이어 옵션을 받게 한다. 편집기는 `pmIgnore: true, snapIgnore: false`로
  깐다 — 드래그·편집 대상에서는 빠지고 스냅 목록에는 남는다. 기존 호출부(`PolygonEditor`,
  `BuildingPolygonPreview`)는 인자를 주지 않으므로 동작이 그대로다.
- `건물 외곽선에 붙이기` 체크박스, **기본 꺼짐.** geoman 전역 옵션 `snappable`을 켜고 끈다. 꺼진 동안은
  자기 선의 꼭짓점에도 붙지 않는다 — 꼭짓점 2~5개짜리 경로에서 잃는 것이 없다.

### 5.6 geoman 한국어와 액션 버튼 배치

- geoman 내장 한국어(`ko`)를 켠다. 액션이 `끝내기 / 마지막 꼭지점 제거 / 취소`, 안내 툴팁도 한국어가 된다.
  운영을 넘겨받을 사람에게 영어 UI보다 낫다.
- 언어 설정은 geoman 전역이다. 경사도 편집기만 켜면 같은 세션에서 그 화면을 거친 뒤에만 건물 영역
  편집기가 한국어가 된다. **`PolygonEditor`도 같이 켠다.**
- 액션 버튼은 그리기 버튼 오른쪽으로 가로로 뻗어 지도 폭을 가린다. CSS로 그리기 버튼 아래 **세로로** 쌓아
  왼쪽 위 모서리만 차지하게 한다. 편집기 컨테이너 클래스로 범위를 한정해 건물 영역 편집기의 배치는
  건드리지 않는다.

## 6. GPX 코드 정리 (2026-08-30 문서 7장 실행)

그 문서 7장의 1~3단계(GPX 행 보관·삭제·0건 확인) 중 **삭제와 0건은 운영 데이터로 확인된다**(1장).
1단계(삭제 전 GPX 파일로 보관)가 실행됐는지는 확인할 수 없다.

4단계 목록을 그대로 실행한다. 추가로:

- 관리자 경사도 목록의 GPX 안내 문구 "GPX 등록은 종료됐어요. 경로는 직접 그려서 등록해주세요"를 지운다.
  7장이 말한 "v1에서 남겨둔 업로드 종료 안내"가 이것이다. 목록 행의 `(파일명)` 표시와 검색 대상
  `gpx_file`도 뗀다.
- `readRoutePoints`는 지금 `points[1].slope`가 없으면 GPX 행으로 보고 통과시킨다. 이제 그런 행은 없으므로
  **`slope`·`distance`가 없는 행은 못 쓰는 행으로 버린다.** 남겨두면 GPX 분기를 지운 뒤 그런 행이 들어올 때
  조용히 엉뚱하게 그려진다.
- `gpx_file` 컬럼은 남긴다. 스키마 변경은 이 범위가 아니다.

## 8. 테스트 계획

### 8.1 무너지는 기존 단언 — 새 의미로 고쳐 쓴다

입력 단위 기본값이 도라 E2E가 넣는 숫자는 이제 도다.

| 위치 (`e2e/admin-buildings-slopes.spec.ts`)        | 지금                         | 바뀐 뒤                                   |
| -------------------------------------------------- | ---------------------------- | ----------------------------------------- |
| 수정 화면 미리보기 색 (목 경로 2, 7.2)             | `#C96C24`                    | 7.2° = 12.63% → `#AE3B1E`                 |
| 경고 테스트 `10` 입력                              | `법적 기준(1/12) 초과`       | `1/12 완화 한도 초과`                     |
| 경고 테스트 `45` 입력                              | 30% 경고 문구                | 45° = 100% → 새 30% 문구, 저장 가능       |
| 경고 테스트 `120` 입력                             | 저장 막힘                    | 120° > 45° → 저장 막힘 (그대로)           |
| 미리보기 색 `1` 입력                               | `#B5AFA8`                    | 1° = 1.75% → `#B5AFA8` (그대로)           |
| 미리보기 색 `10` 입력                              | `#AE3B1E`                    | 10° = 17.63% → `#7A1414`                  |
| 최종 확인 테스트의 `slopeColor(10)` 주석과 색      | `#AE3B1E`                    | `#7A1414`                                 |
| GPX 업로드·거부·다운로드·리다이렉트 테스트         | 있음                         | 삭제 (6장)                                |

저장값 단언(`slope`가 `9.4`, `7.2`)은 그대로 통과해야 한다. 도로 넣고 도로 저장하며 `round2`가 값을 바꾸지 않는다.

### 8.2 vitest

- `slopeScale`: 도↔% 왕복, 0°/45°, 기준선 상수가 비율에서 나오는지
- **기준선 왕복:** 5.56·8.33·12.5%를 % 단위로 입력 → `percentToDeg` → `round2` → `degToPercent`가 같은 색 칸에
  남는지. 2.2절의 실패를 고정하는 테스트다
- `slopeColor` 칸 경계: 각 경계값과 그 바로 위
- `slopeWarning`·`validateRoute`: 도 입력에 대해 1/12(4.76°)·30%(16.70°)·45° 경계
- `toStoredSegments`: `round2`
- `readRoutePoints`: `slope` 없는 행을 버린다

### 8.3 Playwright

- % 단위로 입력하면 도로 저장된다 (목 백엔드가 받은 `slope`)
- 입력란 옆 환산값 표시, 단위 전환 시 물리량 유지
- 선을 끝내면 구간 번호표가 구간 수만큼 보인다
- 지도 `getMaxZoom()`이 19
- 위치 권한·좌표를 준 새 경로 화면은 그 좌표 근처로, 권한 거부면 `KU_CENTER`로 열린다. 범위 밖 좌표도 `KU_CENTER`
- 375px 뷰포트에서 지도 폭이 페이지 콘텐츠 폭과 같다
- 스냅 체크박스 기본 해제
- 그리기 시작 후 액션 버튼 문구가 `끝내기`
- 공개 지도 경사도 팝업에 `%`와 `°`가 함께 나온다
