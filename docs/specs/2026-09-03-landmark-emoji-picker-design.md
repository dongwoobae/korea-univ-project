# 명소 이모지 피커 설계

2026-09-03

## 배경

관리자 명소 폼의 이모지 입력은 자유 텍스트 한 칸이다
(`LandmarkFormModal.tsx`의 `이모지 *`). 관리자가 이모지를 직접 타이핑하거나
다른 데서 복사해 붙여야 해서, 목록에서 골라 넣게 해 달라는 요청이 들어왔다.

이모지를 쓰는 곳은 명소뿐이다. 시설 유형 5종·명소 카테고리·지하철·UI 컨트롤은
전부 lucide SVG이고 코드에 고정돼 있다(`2026-08-13-public-map-lucide-icons-design.md`,
`2026-08-18-restore-landmark-emoji-design.md`). 관리자 화면에서 `icon`을 다루는
파일 8개를 확인했는데 입력 칸은 명소 폼 하나뿐이고 나머지는 읽기 전용 표시다.

## 라이선스 확인

요청 시점에 "이모지 목록을 DB에 저장해 띄워도 되는가"가 선결 질문으로 나왔다.
세 가지를 나눠 봐야 한다.

| 대상                                  | 저작권                            | 결론                             |
| ------------------------------------- | --------------------------------- | -------------------------------- |
| 이모지 **문자**(유니코드 코드포인트)  | 저작권 대상이 아니다              | 저장·표시 자유                   |
| 이모지 **메타데이터**(이름·태그·분류) | Unicode CLDR → Unicode License v3 | 저작권 고지를 붙이면 재배포 자유 |
| 이모지 **그림**(폰트·PNG·SVG)         | 벤더마다 다르다                   | 여기서만 제약이 생긴다           |

`landmarks.icon`은 `text`에 이모지 문자를 그대로 넣으므로 첫 줄에 해당하고,
렌더링도 뷰어의 OS 폰트가 그리는 네이티브 방식이라 그림을 재배포하지 않는다.
따라서 **그림 라이선스는 이 프로젝트에 해당 사항이 없다.** Apple 이모지가
macOS 화면에 뜨는 것은 그 기기의 폰트가 그리는 것이지 우리가 배포하는 것이 아니다.

그림을 번들해야 했다면 Apple·Meta·Samsung·JoyPixels 무료판은 쓸 수 없고
Noto(Apache 2.0)·Twemoji(CC BY 4.0)·Fluent(MIT)·OpenMoji(CC BY-SA 4.0)만
가능했겠으나, 네이티브 렌더링을 유지하므로 그 선택 자체가 필요 없다.

## 범위

- 명소 폼의 이모지 입력 칸을 피커로 교체한다.
- 자유 텍스트 입력은 없앤다.
- `landmarks.icon`의 저장 형식(이모지 문자 그대로)은 그대로 둔다.
- 시설·카테고리·UI 아이콘은 건드리지 않는다.

한 항목의 형상:

```json
{
  "hexcode": "1F333",
  "label": "나무",
  "unicode": "🌳",
  "group": 3,
  "order": 754,
  "tags": ["낙엽", "낙엽수", "숲"]
}
```

`label`과 `tags`가 한국어라 "나무"·"다람쥐"·"벚꽃"으로 검색된다. 이것이
`@emoji-mart/data`를 기각한 이유다.

### 검색 정렬

CLDR 주석은 구체적 명사에 강하고 장소·추상어에 비어 있다. 실측:

| 검색어   | 결과                                            |
| -------- | ----------------------------------------------- |
| `다람쥐` | 1건 — 🐿️ 얼룩다람쥐                             |
| `나무`   | 15건 — 🌳 나무, 🌲 소나무, 🌴 야자수, 🌱 새싹 … |
| `꽃`     | 19건 — 🌸 벚꽃, 💐 꽃다발, 🪷 연꽃 …            |
| `광장`   | 0건                                             |
| `연못`   | 0건                                             |

부분 문자열로 맞추면 잡음이 섞인다 — `책`이 🚶 보행자를 물고(태그 `산책`),
`벤치`가 💪 알통을 문다(태그 `벤치프레스`). 그래서 정렬을 셋으로 나눈다.

1. `label`이 검색어와 정확히 같은 것
2. `label`이 검색어로 시작하는 것
3. 나머지 부분 일치(`label` 포함 → `tags` 포함 순)

검색이 0건이어도 그룹 탭으로 훑을 수 있어 막다른 길이 되지 않는다.

## 스키마

`supabase/migrations/20260903000000_widen_landmark_icon.sql`

```sql
alter table landmarks drop constraint if exists landmarks_icon_length;
alter table landmarks
  add constraint landmarks_icon_length check (char_length(icon) <= 16);
```

상한을 8에서 16으로 올린다. 현재 데이터의 최댓값은 10코드포인트이고, 8로 두면
95건을 고를 수 없는데 그 이유가 화면에 드러나지 않는다. 16은 지금 최댓값에
여유를 둔 값이다.

`check` 자체를 없애지 않는 이유는 원래와 같다 — 폼 제약은 클라이언트 전용이고
`landmarks`의 RLS가 `with check (true)`라 REST로 직접 긴 값을 넣을 수 있다.

### 렌더 가드

`check`는 길이만 본다. 상한을 16으로 넓히면 `"ABCDEFGHIJKLMNO!"` 같은 16자
임의 문자열도 통과하고, `landmarkEmoji()`가 그대로 돌려주고, 30px 마커 원
밖으로 넘친다. `escapeHtml`은 `& < > "`만 막으므로 U+202E(RTL 재정의)나
단독 ZWJ도 통과한다.

그래서 `landmarkEmoji()`에 가드를 둔다 — 이모지가 아닌 값은
`LANDMARK_FALLBACK_EMOJI`로 떨어뜨린다. 저장된 값이 무엇이든 화면이 지켜지고,
**상한 8에도 이미 있던 같은 구멍이 함께 닫힌다.**

판정은 세 조각이다. `\p{Extended_Pictographic}` 하나로는 부족한데, **국기가
`Regional_Indicator`이고 키캡(`1️⃣`)은 숫자에 `U+20E3`이 붙은 형태**라 둘 다
그 속성에 들지 않기 때문이다. 실측으로 확인했다.

1. 키캡 전용 패턴 — 숫자·`#`·`*`가 앞에 오는 유일한 경우다
2. 전체 일치 — 글리프(`Extended_Pictographic`·`Regional_Indicator`)와 이어
   붙이는 부품(ZWJ·이형 선택자·스킨톤·태그)만 허용한다. `🌳ABC` 같은 혼합이
   여기서 걸린다
3. 글리프 존재 — 부품만 있고 글리프가 없는 값(ZWJ 단독)을 막는다

`v` 플래그의 `\p{RGI_Emoji}`가 한 줄로 끝나지만 ES2024라 지원 범위가 좁다.

`emojibase-data` 3,979건 전수로 검증했다. 거부된 5건은 전부 `component`
그룹(맨 스킨톤 수정자)이고 피커가 이미 제외하는 그룹이다.

### 빈 문자열

`landmarks.icon`은 `not null`이지만 빈 문자열은 `not null`도 길이 `check`도
통과한다. `LandmarkFormModal`의 초기값이 `landmark?.icon ?? "✨"`였고 `??`는
`null`·`undefined`만 잡아 `""`를 그대로 뒀다. 그 상태에서 `validate()`가
저장을 막으므로, 자유 입력이 없어진 뒤 피커 로딩까지 실패하면 이름 수정조차
못 하게 된다.

`|| "✨"`로 바꾸는 대신 **초기값도 `landmarkEmoji(landmark?.icon)`을 쓴다.**
폴백 리터럴이 폼에 복제돼 있던 것이 사라지고, 공백·이모지 아닌 값까지 같은
규칙으로 처리된다. 이 경로의 보장은 `mapIcons.test.ts`가 진다 — 이 저장소의
vitest는 `environment: "node"`라 컴포넌트 테스트가 없다.

## UI

이모지 입력 칸(`중문 설명` 아래, `위치` 위)을 다음으로 바꾼다.

```
이모지 *
┌──────┐
│  🐿️  │   ← 현재 값 미리보기 겸 펼침 버튼
└──────┘
   ↓ 펼침
┌────────────────────────────────┐
│ [검색: 나무, 다람쥐 ...      ] │
│ 스마일리 · 사람 · 동물 · 음식  │  ← 그룹 탭
│ ────────────────────────────── │
│ 🌳 🌲 🌴 🌵 🌷 🌸 🌹 🌺 🌻 🌼 │  ← 8열 격자
│ ...                            │
└────────────────────────────────┘
```

- 펼침 버튼은 `aria-expanded`와 `aria-haspopup="listbox"`를 갖는다.
- 격자는 `role="listbox"`, 각 칸은 `role="option"` + `aria-label={label}`.
- 이모지 자체는 `aria-hidden`으로 두고 한국어 `label`을 접근성 이름으로 준다.
  이모지 문자를 그대로 읽히면 스크린 리더가 벤더별 이름을 제각기 읽는다.
- 격자는 높이를 고정하고 세로 스크롤한다. 3,979개를 한 번에 그리지 않고
  선택된 그룹만 렌더한다 — 가장 큰 그룹이 `people-body` 388건이다.
- 검색 결과에도 상한을 둔다(200건). 한 글자 검색이 그룹 최대치를 넘긴다.

## 초점과 키보드

모달이 `useModalFocus`로 초점 덫과 Escape 닫기를 걸고 있어 두 가지를 처리해야 한다.

1. **Escape** — 피커가 열린 상태의 Escape는 피커만 닫아야 한다. 컨테이너에서
   `capture`로 먼저 잡는 방법은 **쓸 수 없다.** `useModalFocus`의 핸들러가
   `document`에 `capture: true`로 붙어 있는데, DOM capture는 `document`가
   하위 컨테이너보다 먼저라 어느 쪽이 등록돼 있든 모달이 먼저 닫힌다.

   대신 `useModalFocus`가 이미 가진 중첩 장치를 쓴다. 모듈 스코프의
   `dialogStack`과 핸들러 첫 줄의 `if (dialogStack.at(-1) !== dialog) return;`이
   그것이다. 피커가 자기 컨테이너로 `useModalFocus`를 호출하면 스택 최상단이
   되어, 모달의 핸들러는 조기 반환하고 피커의 핸들러만 Escape를 처리한다.

   모달의 `closeOnEscape`를 끄는 방식은 쓰지 않는다 — 그 플래그는 저장·업로드 중
   닫힘 방지용이라 의미가 섞인다.

2. **Tab** — 선택된 그룹만 그려도 최대 388칸이 탭 정지점이 된다. 격자는
   roving tabindex로 둔다(선택된 칸만 `tabindex="0"`, 나머지 `-1`,
   방향키로 이동).

## 테스트

이 변경이 무너뜨리는 기존 단언 두 개:

- `e2e/accessibility-dialog-toast.spec.ts` — `getByLabel("이모지 *")`에
  `toBeEditable()`. 버튼은 editable이 아니다. 펼침 버튼의 존재와
  `aria-expanded` 확인으로 바꾼다.
- `e2e/admin-content.spec.ts` — `toHaveValue("✨")`와 `iconInput.fill("📸")`.
  버튼에는 `fill`이 안 된다. 기본값은 버튼의 접근성 이름으로, 선택은
  펼침 → 격자에서 클릭으로 바꾼다. 저장 결과가 `icon === "📸"`인지 보는
  마지막 단언은 그대로 둔다.

`src/lib/mapIcons.test.ts`의 `landmarkEmoji` 테스트는 읽기 경로라 대부분
그대로지만, **렌더 가드가 들어가면 "저장된 이모지를 그대로 돌려준다"의
의미가 좁아진다** — 이모지인 값만 그대로 돌려준다. 이 테스트는 확장한다.

`e2e/support/mockBackend.ts`는 insert 시 DB `check`를 흉내내지 않는다. 길이
제약은 e2e로 확인할 수 없고 마이그레이션 자체가 유일한 보장이다.

새로 필요한 것:

- 그룹 필터가 `component` 그룹을 제외하는지
- 한국어 검색("나무")이 🌳를 찾는지, 정확 일치가 부분 일치보다 위에 오는지
- 격자에서 고른 값이 `form.icon`에 들어가고 미리보기가 바뀌는지
- 피커가 열린 상태의 Escape가 피커만 닫고 모달은 남기는지
- `landmarkEmoji`가 이모지 아닌 값(`"ABCDEFGHIJKLMNO!"`, `"‮"`,
  단독 ZWJ)을 폴백으로 떨어뜨리는지
- 저장된 `icon`이 빈 문자열일 때 폼이 폴백을 채워 저장이 막히지 않는지

## 나중에 바꿀 때의 비용

`landmarks.icon`이 패키지 id도 이미지 URL도 아닌 **이모지 문자**를 담기 때문에,
저장된 값이 여기서 고른 것들에 묶이지 않는다.

- **데이터 패키지 교체** — 피커가 목록을 그릴 때만 쓰므로 어댑터 한 곳이면 된다.
  DB는 손대지 않고 기존 명소 4건의 값도 그대로 유효하다.
- **그림 세트 교체**(네이티브 → Twemoji·Noto 등) — **편집할 지점은 둘이지만
  확인할 표면은 다섯이다.** 편집은 `iconography.tsx`의 `LandmarkEmoji`와
  `LandmarkMarkers.tsx`의 Leaflet HTML 문자열 두 곳뿐이다(시설 아이콘이 이미
  같은 이유로 두 벌인 구조다). 그러나 `2026-08-18` 설계가 "5개 지점"이라 부른
  소비 지점 — 마커 `divIcon`, 마커 팝업, `MapBrowseList`, `SearchControl`,
  관리자 명소 목록 — 은 크기가 15·16·20px로 제각각이라 레이아웃을 다섯 곳
  모두 확인해야 한다.

  다만 이때 위 "라이선스 확인"의 그림 항목이 그제야 발동한다 — 출처 표기와
  에셋 번들이 함께 온다.

## 배포

`emojibase-data`는 현재 `package.json`에 없다(dependencies 16개, `package-lock.json`
에도 없다). 구현의 첫 단계는 의존성 추가다. 이걸 건너뛰고 import를 먼저 쓰면
모듈 해석에서 막힌다.

마이그레이션(상한 8 → 16)이 앞서고 코드가 뒤따른다. 순서가 뒤집히면 16까지
허용하는 UI가 8에서 거부당한다. 반대 순서로 배포되는 동안에는 상한만 넓어진
상태라 무해하다.

렌더 가드(`landmarkEmoji`)와 폼 초기값은 피커와 독립이고 현재 코드의 구멍을
닫는 것이므로 마이그레이션과 함께 먼저 나간다.
