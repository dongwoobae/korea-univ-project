# 공개 지도 메뉴 재배치 설계

2026-10-27

## 이 문서의 목적

멘토링 설계(`docs/specs/2026-10-25-mentoring-feedback-design.md`) 6장이 PR ④의 요구다 — 사용자가 고른 모양(웹 왼쪽 아이콘 줄, 모바일
아래 가로 줄)과 열린 패널 전이 표. 이 문서는 그것을 코드로 옮길 때 정할 것(버튼 자리·크기, 상태를 두는 곳, 초점, 시험)을 적는다.
6장에 있는 것은 되풀이하지 않고 절 번호로 가리킨다.

결정 표기: **[사용자]**는 사용자가 정한 것, **[판단]**은 Claude가 정하고 사용자에게 알린 것이다. 이 문서의 결정은 모두 **[판단]**이고,
사용자 결정은 6장에 있다.

## 1. 화면 모드

| 모드       | 조건                                           | 모습                                                                          |
| ---------- | ---------------------------------------------- | ----------------------------------------------------------------------------- |
| `expanded` | 폭 768px 이상, `ku_menu_collapsed`가 `"false"` | 지금 모습 + 접기 버튼(2장)                                                    |
| `rail`     | 폭 768px 이상, 그 밖(처음 방문 포함)           | 왼쪽 위 세로 아이콘 줄(3장)                                                   |
| `bar`      | 폭 768px 미만                                  | 아래 가로 줄(4장). 저장 값을 읽지 않는다(6.3 "모바일에는 접기·펼치기가 없다") |

- 폭 판정은 지금처럼 `window.innerWidth < 768`이다. 처음 값도 첫 그리기 때 이 식으로 정한다. 지금은 `false`로 시작해 효과에서
  고치므로 휴대폰에서 펼친 웹 모습이 한 번 그려진다. 공개 지도는 `MapWrapper.tsx`가 `ssr: false`로 불러 첫 그리기에 `window`가 있다.
- **[사용자]** 2026-10-27 처음 방문은 접힌 줄이다(멘토링 설계 6.2). 처음에는 펼침으로 정했다가 바꿨다.
- 저장 값 읽기·쓰기는 멘토링 설계 2장 규칙을 따른다(없음·예외·모르는 값은 "없을 때" 값인 접힘, 쓰기 실패는 화면만 바꾼다). 처음
  값은 `useState` 초기화 함수에서 읽는다 — 즐겨찾기(`loadFavoritesFromStorage`)와 같은 방식이다.
- 접기·펼치기를 누르면 열린 패널을 닫고, 초점을 짝 버튼(접기 ↔ 펼치기)으로 옮긴다. 누른 버튼이 사라지므로 초점이 문서 처음으로
  떨어지지 않게 하려는 것이다.

## 2. 웹 펼침 — 접기 버튼

- 검색 상자 줄을 `[검색창][별][접기]`로 한다. 접기는 별과 같은 46px 아이콘 버튼(`ChevronsLeft`), 이름은 "메뉴 접기"(`title`과
  `aria-label`).
- 상자 폭(324px)은 그대로라 검색창이 54px 좁아진다(244 → 190px, 테두리·안쪽 여백을 뺀 값). 영어 안내 글("Search buildings...")이
  끝에서 잘릴 수 있다. 상자를 넓히면 필터 패널·즐겨찾기 목록 자리까지 바뀌어 "지금 모습과 같다"(6.2)에서 멀어진다. 필터 패널 안에
  두면 패널이 스크롤될 때 "늘 보이는" 조건을 잃는다.
- 이 모드에서 열린 패널 상태(5장)가 쓰는 값은 `favorites`(별)와 `browse`(왼쪽 아래 "현재 지도 목록")뿐이다.
  - 필터는 늘 펼쳐져 있어 여닫지 않는다.
  - 검색은 패널이 아니다. 검색창은 늘 보이고, 결과 목록은 지금처럼 초점·검색어로 뜬다. 검색창에 초점이 가거나 글을 바꾸면 열린
    즐겨찾기·목록을 닫고, 즐겨찾기·목록이 열려 있으면 결과 목록을 숨긴다(지금은 즐겨찾기만 그렇다). 이렇게 해서 "한 번에 하나"를
    지킨다. 검색창을 `search` 상태로 두면 초점이 떠난 뒤에도 상태가 남아, 아무 데서나 누른 Esc가 초점을 검색창으로 끌고 온다.
  - 검색창은 결과 목록을 가리키는 콤보박스(`aria-expanded`·`aria-controls`)이고 그 뜻은 바꾸지 않는다.
- 필터 패널과 목록 패널이 겹칠 때 마지막으로 누른 쪽을 앞에 두는 규칙(`frontMapPanel`)은 이 모드에서 그대로 쓴다. 다른 두 모드에는
  패널이 하나뿐이다.
- 건물 상세가 열려 있으면 왼쪽 아래 "현재 지도 목록"을 숨기는 지금 규칙도 그대로다.

## 3. 웹 접힘 — 왼쪽 아이콘 줄

- 자리: `top: 20px; left: 20px`, 폭 64px. 지도 위 카드 모양(`--ku-map-control` 바탕, 테두리, `--ku-shadow-floating`)은 검색 상자와 같다.
- 위에서부터 **펼치기**(`ChevronsRight`, "펼치기") — 가름줄 — **검색**(`Search`) · **필터**(`SlidersHorizontal`) · **즐겨찾기**
  (`Star`) · **목록**(`List`). 버튼은 64×56px, 아이콘 20px 밑에 11px 이름.
  - 펼치기를 맨 위에 두는 것은 펼친 모습의 접기 버튼이 위쪽에 있어서다. ⑤의 다크모드 토글은 목록 아래 맨 끝에 붙는다(`docs/specs/2026-10-28-dark-mode-design.md` 1.2).
- 수 표시: 필터는 기본값에서 벗어난 조건 수(지금 모바일 필터 배지와 같은 셈), 즐겨찾기는 개수, 목록은 지금 화면 안 항목 수. 0이면
  표시하지 않는다. 지금 모바일 필터 버튼은 0도 보였다. 버튼 접근 이름은 수가 있으면 `즐겨찾기 (1)`처럼 지금 별 버튼 꼴을 따른다.
- 패널을 여는 버튼: `aria-expanded`, `aria-controls`(5.1의 id). 열린 버튼은 글자 `--ku-crimson-600`, 바탕 `--ku-crimson-100`(지금 언어
  버튼의 눌린 모양).
- 패널 자리: 줄 오른쪽 8px 띄워 `top: 20px; left: 92px`, 폭 324px(펼친 상자와 같다), 높이는 `calc(100dvh - 40px)`까지이고 넘치면
  패널 안에서 스크롤한다.
  - 검색: 검색창과 결과. 별·접기 버튼은 없다(즐겨찾기는 줄에 있다).
  - 필터: 제목 "시설 필터"(지금 모바일 필터 버튼의 이름) 아래 지금 필터 내용.
  - 즐겨찾기: 지금 즐겨찾기 목록(제목 "즐겨찾기 (n)" 포함).
  - 목록: 지금 "현재 지도 안의 시설과 명소" 패널(제목·설명·닫기 버튼 포함).
- 왼쪽 아래 "현재 지도 목록" 버튼과 그 패널은 이 모드에서 그리지 않는다(6.2). 출처 표기는 왼쪽 아래 그대로다.

## 4. 모바일 — 아래 가로 줄

### 4.1 줄과 비키는 것

- 줄: 화면 바닥(`bottom: 0`) 전체 폭, 높이 `--ku-menu-bar-height: 60px`. 버튼 넷이 폭을 똑같이 나눈다(360px 폭이면 90px). 아이콘
  20px 밑에 12px 이름. 수 표시·열린 모양·`aria-*`는 3장과 같다. `<nav aria-label="지도 메뉴">`.
- 6.3이 `viewport-fit=cover`를 켜지 않기로 해 `env(safe-area-inset-bottom)`은 0이다. 줄은 안전 영역 안쪽 바닥에 붙는다.
- 줄 위로 올라가는 것(지금 바닥 기준 값에 줄 높이를 더한다):
  - 출처 표기: `bottom: 12px` → `줄 + 8px`.
  - 현 위치·위성·피드백 버튼 열: `bottom: 16px` → `줄 + 12px`.
  - 경사도 범례: 지금은 "현재 지도 목록" 버튼 위에 앉는다(`bottom: 96px`). 그 버튼이 없어지므로 출처 표기 위로 내려간다 —
    `줄 + 8 + 24(출처 높이) + 8 = 줄 + 40px`.
- 패널이 열려 있거나 건물 상세가 열려 있으면 위 셋을 숨긴다. 지금은 모바일 필터·목록이 열렸을 때 버튼 열과 범례를, 필터나 상세가
  열렸을 때 출처를 숨긴다 — 이것을 "어느 패널이든"으로 넓힌다.
- 건물 상세 시트가 열려 있는 동안 줄을 그리지 않는다(6.3). 상세를 닫는 0.28초 애니메이션 뒤 선택이 비워질 때 다시 나온다.
- 지금 위쪽의 검색창·별, "시설 필터" 버튼, 왼쪽 아래 "현재 지도 목록" 버튼은 이 모드에서 그리지 않는다.
- 언어 버튼은 오른쪽 위 그대로이고(6.3), 쌓임 순서를 메뉴 패널(1100)보다 위(1150)로 올린다. 언어 목록은 버튼 아래로 펼쳐져 위쪽
  검색 패널의 결과나 높이 큰 아래 패널과 겹칠 수 있는데, 지금 값(1000)이면 목록이 그 밑에 깔려 고를 수 없다. 건물 상세(1200)보다는
  아래다.

### 4.2 검색

- 줄의 **검색**을 누르면 위쪽에 검색 패널이 열린다: `top: 보이는 위 + 16px; left: 16px; right: 72px`(오른쪽은 언어 버튼 48px + 사이
  8px). `[검색창(48px)][닫기(48×48, X)]` 한 줄, 그 아래 결과. 검색창 모양은 지금 모바일 검색창과 같다.
- 연 즉시 검색창에 초점이 간다(5.4).
- 결과가 키보드와 줄에 가리지 않게 패널을 세로 flex로 두고 결과 목록만 줄어들며 넘치면 스크롤한다. 패널은 보이는 영역 안에 든다:
  `--ku-visible-top`·`--ku-visible-bottom`을 패널이 열려 있는 동안 `visualViewport`의 `resize`·`scroll`마다 맞추고, 패널 높이 한도는
  `bottom - top - 24px`(위 16 + 아래 8)이다.
  - 보이는 위 = `visualViewport.offsetTop`, 보이는 아래 = `min(offsetTop + height, innerHeight - 줄 높이)`. `visualViewport`가 없으면
    위 0, 아래 `innerHeight - 줄 높이`.
  - 이유: Android Chrome(108부터)과 iOS Safari는 화상 키보드가 떠도 레이아웃 뷰포트를 줄이지 않고 보이는 영역만 줄이거나 옮긴다.
    `dvh`만으로는 결과 끝이 키보드 밑으로 들어간다.
  - `interactive-widget=resizes-content`(viewport 메타)는 쓰지 않는다. iOS는 무시하고, 바꾸면 공개·관리자 화면 전체 재검증이 든다
    (6.3이 `viewport-fit`을 미룬 것과 같은 이유).
- 이 모드에서 검색창의 Esc는 결과 목록만 닫지 않고 패널을 닫는다(6.4 "열린 패널이 있으면 그것만 닫고"). 펼침 모드의 검색창은 지금처럼
  첫 Esc가 결과 목록만 닫는다 — 그 모드에서 검색은 패널이 아니다(2장).
- 검색어 지우기(X, 지금 26px)를 이 모드에서 44px로 키운다(4.3 끝).

### 4.3 필터·즐겨찾기·목록

- 아래에서 올라오는 패널: `left: 16px; right: 16px; bottom: 줄 + 8px`, 높이 한도 `calc(100dvh - 줄 - 8px - 76px)`(위쪽 76px은 언어
  버튼 16 + 48 + 12 몫), 넘치면 패널 안에서 스크롤한다. 비모달이다(6.4).
- 내용은 3장의 패널과 같다. 목록 패널의 목록 높이 한도(지금 모바일 `calc(100dvh - 298px)`)는 패널이 스크롤하므로 풀어 준다.
- 44px(6.4): 접힌 줄·아래 줄의 패널 안 조작을 모두 44px 이상으로 한다. 지금 모자라는 것은 필터 칩(40px), 목록 닫기(36px), 검색어
  지우기(26px)다. 펼침 모드의 같은 조작은 손대지 않는다(2장 "지금 모습").
- 768px 이상이 되면 3장 또는 2장 모습이 된다(6.3).

## 5. 열린 패널

### 5.1 상태

- `openPanel: "search" | "filter" | "favorites" | "browse" | null`과 접힘 여부를 `Map`이 든다(작은 훅 `useMapMenu`로 묶는다). 지금의
  `showFavorites`·`mobileFilterOpen`·`browseOpen`과 `FilterPanel`·`MapBrowseList` 안의 열림 상태를 없앤다. `SearchControl` 안의 결과
  열림(`open`·`isFocused`)은 남긴다 — 결과 목록은 "검색창에 초점·검색어가 있을 때" 뜨는 것이고, 그 규칙은 바꾸지 않는다.
- 패널마다 내용 뿌리에 고정 id를 둔다: `map-search-panel`·`map-filter-panel`·`map-favorites-panel`·`map-browse-panel`(마지막은 지금
  id). 접힌 줄·아래 줄 버튼과 펼침 모드의 별·"현재 지도 목록"의 `aria-controls`가 이 id를 가리킨다. 한 번에 하나만 그려지므로 겹치지
  않는다.

### 5.2 전이 (6.4 표를 코드로)

| 6.4의 일                      | 코드                                                                                                         |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 다른 버튼 / 열린 버튼 다시    | `toggle(panel)` — 같으면 닫고 다르면 연다                                                                    |
| 항목을 고른다                 | 고른 쪽 처리(지도 이동·상세) 뒤 닫고 초점을 돌린다(5.4)                                                      |
| 지도를 누른다                 | 5.3                                                                                                          |
| 필터 안에서 바꾼다            | 아무것도 하지 않는다                                                                                         |
| Esc                           | 5.4                                                                                                          |
| 768px 경계를 넘는다           | `Map`의 `resize` 처리에서 폭이 바뀐 때만 닫는다. 초점이 패널 안에 있었으면 새 모드의 여는 자리로 옮긴다(5.4) |
| 모바일에서 건물 상세가 열린다 | 건물을 고르는 함수(`selectBuilding`)가 닫는다. 웹에서도 닫는다 — 아래                                        |

- 건물을 고르는 길은 넷이다: 폴리곤 누르기, 검색 결과, 즐겨찾기, 지하철역 마커. 지금은 각자 `setSelectedBuilding`을 부른다. 이것을
  `selectBuilding` 하나로 모으고 거기서 패널을 닫는다(5.5의 타이머 취소도 여기 있다).
  - 선택된 건물 id가 바뀌는 것을 지켜보는 방식은 쓰지 않는다. 같은 역을 다시 누르면 id가 그대로라 패널이 남는다.
  - 웹에서도 닫는 까닭: 검색·즐겨찾기에서 고르면 어차피 닫히고, 폴리곤은 지도 누르기로 닫힌다. 남는 길은 지하철역뿐인데 그때만
    왼쪽 패널이 남을 까닭이 없다.
  - `SubwayMarkers`는 `memo`라 `onSelect`가 안정된 참조여야 한다(그 파일 끝 주석). `selectBuilding`은 상태 설정 함수와 ref만 쓰게 해
    참조를 고정한다.

### 5.3 지도를 누르면

- 지도 안에 작은 구성 요소 하나를 두고 Leaflet 컨테이너(`map.getContainer()`)의 DOM `click`을 듣는다. `map.dragging.moved()`가 참이면
  (끌어서 옮긴 뒤) 건너뛰고, 아니면 닫는다(초점은 돌리지 않는다).
  - Leaflet도 같은 값으로 끈 뒤의 지도 `click`을 막는다(`Map._draggableMoved`). 끌면서 목록 패널을 보는 쓰임(지도를 옮기면 "현재 지도
    목록"이 바뀐다)이 있어 끌기는 닫지 않는다.
  - DOM에서 들으므로 폴리곤·시설·명소·지하철·묶음·현 위치 마커를 누를 때 모두 닫힌다.
  - 팝업 안을 누른 것은 건너뛴다(`.leaflet-popup` 안). 팝업은 지도 위에 뜬 다른 패널이라 그것을 누른 것은 지도를 누른 것이 아니다.
    Leaflet 1.9.4의 `DomEvent.disableClickPropagation`은 `mousedown`·`touchstart`·`dblclick`·`contextmenu`만 막고 `click`은 표시
    (`_leaflet_disable_click`)만 남긴다 — DOM `click`은 컨테이너까지 올라오므로 직접 걸러야 한다.
  - 버린 길: Leaflet `click`+`popupopen`. 마커는 지도로 번지지 않아(`bubblingMouseEvents: false`) 팝업 없는 마커(묶음·현 위치)와 열린
    팝업의 마커를 다시 누를 때(팝업만 닫힌다)를 놓친다.
- 메뉴 UI는 Leaflet 컨테이너 밖에 둔다. 지금 `SearchControl`은 `MapContainer`의 자식이라 컨테이너 안에 그려지고, 그 안을 누르면 위
  `click`이 난다. 안에 둔 채 거를 수도 있지만, 그러면 모드마다 자리 기준(Leaflet 컨테이너 대 지도 셸)이 갈리고 `useMap`이 메뉴 안에
  남는다. 밖으로 옮긴다(6.1).

### 5.4 초점과 Esc

- 버튼으로 열 때: `flushSync`로 패널을 그린 뒤 같은 손 안에서 패널 id 안의 첫 조작(입력·버튼)에 초점을 준다. 조작이 없으면(빈
  즐겨찾기) 패널 뿌리(`tabIndex={-1}`)에 준다. iOS Safari는 사용자 동작의 손 밖(효과·타이머)에서 준 초점으로는 화상 키보드를 띄우지
  않는 것으로 알려져 있어 손 안에서 준다. 실제 기기에서 키보드가 뜨는지는 사용자 확인 항목이다.
- 닫으며 초점을 연 버튼으로 돌리는 경우: Esc, 패널 안 닫기 버튼, 항목 고르기. 연 버튼을 다시 누르면 초점은 이미 거기 있다. 지도
  누르기에서는 돌리지 않는다(사용자가 지도를 눌렀다).
  - 연 버튼은 모드마다 다르다: 접힌 줄·아래 줄은 그 버튼, 펼침 모드는 별·"현재 지도 목록". 훅이 패널별 ref를 받는다.
  - 모바일에서 검색·즐겨찾기로 건물을 고르면 줄이 사라진다. 그때는 건물 상세(`<aside>`, `tabIndex={-1}`)에 초점을 준다. 폴리곤·역을
    눌러 열 때는 초점을 옮기지 않는다(지금과 같다).
  - 768px 경계를 넘을 때 초점이 패널 안에 있었으면, 새 모드에서 그 패널의 여는 버튼으로 옮긴다. 펼침 모드의 필터처럼 여는 버튼이
    없으면 그 패널 내용의 첫 조작으로, 펼침 모드의 검색은 검색창으로 옮긴다. 회전·창 크기 변경은 사용자가 다른 곳을 누른 것이 아니라
    초점이 문서로 떨어지면 안 된다.
- Esc: 패널이 열려 있는 동안 `window`의 `keydown`(버블)을 듣는다. `defaultPrevented`면 건너뛰고, 아니면 닫고 초점을 연 버튼으로
  돌린다. 초점이 지도나 상세에 있어도 닫힌다(6.4 "열린 패널이 있으면").
  - Esc를 먼저 쓰는 다른 UI는 `preventDefault`로 표시한다. 모달(`useModalFocus`: 피드백·등록 요청·사진 확대·확인)은 이미 문서 캡처
    단계에서 `preventDefault`·`stopPropagation`한다. 펼침 모드 검색창은 결과 목록이 열렸을 때 이미 한다. 언어 목록
    (`LanguageSwitcher`)과 경사도 범례 툴팁(`SlopeBandsLegend`)은 문서에서 듣고 닫기만 해 `preventDefault`를 더한다. 버블 단계에서
    `window`는 문서와 React 루트보다 늦게 받으므로 이들이 먼저 표시한다.
  - 버린 길: 메뉴 감싸개 하나의 `onKeyDown`. Tab으로 지도·언어로 나간 뒤 누른 Esc가 닿지 않는다.

### 5.5 상세를 닫는 0.28초

- 지금 `handleClosePanel`은 상세를 내리는 애니메이션(`sidePanelShouldClose`) 뒤 0.28초에 선택을 비운다. 그사이 다른 건물을 고르면
  선택이 지워지지 않게 ③에서 "활성 건물 id가 바뀌었으면 비우지 않는다"를 넣었다. 같은 건물을 다시 고르면 id가 같아 새 선택도
  지워진다. 메뉴 패널이 늘 열리고 닫히는 이번 화면에서 닫자마자 즐겨찾기·검색에서 다시 고를 길이 가까워진다.
- 바꾼다: 닫기 타이머를 ref에 두고, `selectBuilding`이 타이머가 걸려 있으면 취소한다. 그 경우 상세는 이미 내려가고 있으므로
  `SidePanel`의 `key`에 붙는 번호를 하나 올려 새로 띄운다. 같은 건물이어도 다시 올라온다. ③의 id 비교는 이 취소가 대신하므로 지운다.

### 7.2 E2E 새 파일 `e2e/map-menu.spec.ts`

- 웹 접기·펼치기: 처음 방문은 접힌 줄(버튼 순서, 펼친 요소인 검색 상자·필터 카드·왼쪽 아래 목록이 없음, 아무것도 저장하지 않음).
  펼치기 → 저장 `"false"`, 초점이 접기로, 새로 고쳐도 펼침. 접기 → 저장 `"true"`, 초점이 펼치기로. 저장소 읽기 예외·모르는 값이면 접힘.
- 웹 줄: 버튼마다 패널이 줄 오른쪽에 열리고 `aria-expanded`·`aria-controls`가 맞다. 하나만 열린다, 같은 버튼은 닫는다. Esc는 닫고 초점을
  버튼으로(검색창 안에서 결과가 떠 있어도 한 번에). 초점이 지도에 있어도 Esc로 닫힌다. 언어 목록이 열려 있으면 Esc는 언어 목록만
  닫는다. 필터 칩을 바꿔도 열린 채이고, 다시 열면 절 펼침이 남아 있다. 지도를 누르면 닫히고, 끌면 닫히지 않는다. 마커를 눌러도
  닫힌다. 마커 팝업 안을 누르면 닫히지 않는다. 검색·즐겨찾기·목록에서 고르면 닫히고 이동, 초점은 줄 버튼. 검색어는 다시 열어도 남는다. 상세가 열려도 줄은 남는다.
- 펼침: 별·"현재 지도 목록"·검색창 사이에서도 하나만 열린다(지금은 목록과 즐겨찾기가 같이 열린다). 첫 Esc는 결과 목록만(지금과 같다).
- 경계: 접힌 줄에서 필터 패널 안에 초점을 둔 채 390px로 줄이면 패널이 닫히고 아래 줄의 필터 버튼에 초점, 다시 넓히면 접힌 줄(저장
  값 그대로).
- 상세 닫기 경쟁: 닫기를 누르고 0.28초 안에 같은 건물을 즐겨찾기에서 다시 고르면 상세가 남는다(한 번의 `evaluate` 안에서 눌러 시간을
  고정한다).
- 모바일 360·390·430 세로와 740×360 가로: 줄 버튼 넷의 순서·44px 이상·화면 안, 가로 스크롤 없음, 출처·버튼 열이 줄 위, 언어 버튼이
  보인다. 각 패널이 줄 위에 있고 위쪽 언어 버튼과 겹치지 않으며, 패널 안 버튼·체크 줄이 44px 이상이다.
- 모바일 검색: 열면 검색창에 초점, 결과 끝이 줄 위, 390×400에서도 결과가 화면과 줄 안이고 스크롤된다. `visualViewport`를 가짜로
  바꿔(높이를 줄이고 `resize`를 보낸다) 결과 끝이 그 아래 경계 안으로 줄어드는지 본다 — 이벤트 연결 확인이다. 닫기 → 초점이 줄의
  검색으로. Esc 한 번에 닫힌다. 검색 패널이 열린 채 언어 목록을 열고 영어를 고를 수 있다.
- 모바일 상세: 검색으로 고르면 패널이 닫히고 줄이 숨고 초점이 상세로 간다. 상세를 닫으면 줄이 돌아온다. 지도를 누르면 패널이 닫힌다.

### 7.4 E2E 환경

- E2E는 `next dev`로 돈다. 2026-10-27 CI에서 왼쪽 아래 Next 개발 표시가 아래 줄의 첫 버튼(검색)을 덮어 누르기를 가로챘다. 운영에는
  없는 표시라 E2E 웹서버에서만 끈다(`playwright.config.ts`의 `NEXT_HIDE_DEV_INDICATOR` → `next.config.mjs`의 `devIndicators: false`).
  꺼도 빌드·실행 오류 표시는 남는다(Next `devIndicators` 문서).
- 기존 시험 여럿이 `getByText("중앙도서관").last()`로 검색 결과를 고른다. 같은 글자의 건물 이름표(지도 안)보다 결과가 DOM에서 뒤에
  있어야 그것이 잡힌다. 그래서 메뉴는 `MapContainer` 뒤에 그린다 — 예전 `SearchControl`도 지도 안 이름표 칸 뒤에 있었다.
- 2026-10-27 처음 방문을 접힘으로 바꾸며, 목 백엔드(`installMockBackend`)가 저장 값이 없을 때 `ku_menu_collapsed = "false"`를 넣게
  했다. 웹 기능 시험 대부분이 검색창·필터가 늘 보이는 펼친 모습에서 쓰였기 때문이다. 시험이 먼저 넣은 값과 새로 고침 뒤의 값은
  건드리지 않는다. 처음 방문 동작은 `expandMapMenu: false`로 이 값을 빼고 `map-menu.spec.ts`가 본다.

## 8. 하지 않는 것

- 다크모드 토글(⑤, 멘토링 설계 1장).
- `viewport-fit=cover`, `interactive-widget`(4.2).
- 관리자 화면.
- 모바일에서 검색·즐겨찾기로 고른 건물이 상세 시트에 가리는 것(멘토링 설계 5.2가 이미 후속으로 미뤘다).
