# 글자 크기 설계

2026-10-28

## 이 문서의 목적

PR ⑥의 요구는 멘토링 설계(`docs/specs/2026-10-25-mentoring-feedback-design.md`) 8장이다. 공개 지도 글자를 작게·보통·크게 세 단계로
바꾸고, 저장 값은 `ku_font_scale`, 관리자 화면은 바꾸지 않는다. 이 문서는 그것을 코드로 옮길 때 정할 것을 적는다. 정할 것은 버튼 자리·모양,
커지는 글자와 그대로인 글자, 배율을 거는 방법, 지도 위 이름, 시험이다. 8장에 있는 것은 되풀이하지 않고 절 번호로 가리킨다. 상태를 두는 틀은
다크 모드(`docs/specs/2026-10-28-dark-mode-design.md` 2장)와 같다.

결정 표기: **[사용자]**는 사용자가 정한 것, **[판단]**은 Claude가 정하고 사용자에게 알린 것이다.

## 1. 버튼

### 1.1 모양과 동작

- **[사용자]** 2026-10-28 ycc 웹사이트 설교 요약 화면처럼 `가−`·`가＋` 두 버튼으로 한다. `가−`는 작은 글자(14px), `가＋`는 큰
  글자(18px)로 써서 모양만으로 방향이 보인다.
- 단계는 작게 ↔ 보통 ↔ 크게다. 처음은 보통이고(8.1), 한 번 누르면 한 단계 움직인다.
- 끝 단계(작게의 `가−`, 크게의 `가＋`)는 흐리게 보이고 눌러도 아무 일이 없다.
  - **[판단]** `disabled` 대신 `aria-disabled="true"`로 한다. `disabled`면 키보드로 `가＋`를 눌러 크게에 닿는 순간 버튼이 초점을
    잃고 초점이 문서로 떨어진다.
- 버튼 글자는 언어마다 다르다. **[판단]** `가`는 한국어 글자라 다른 언어 화면에서는 그 언어의 글자를 쓴다.

  | 언어 | 보이는 글자  | 버튼 이름(접근 이름·`title`) | 묶음 이름 | 바뀐 뒤 읽어 줄 글                |
  | ---- | ------------ | ---------------------------- | --------- | --------------------------------- |
  | ko   | `가−` `가＋` | 글자 작게 · 글자 크게        | 글자 크기 | 글자 크기: 작게 / 보통 / 크게     |
  | en   | `A−` `A＋`   | Smaller text · Larger text   | Text size | Text size: Small / Normal / Large |
  | zh   | `字−` `字＋` | 缩小字号 · 放大字号          | 字号      | 字号：小 / 标准 / 大              |

- 두 버튼은 `role="group"` 묶음 안에 있다. 버튼 이름은 단계에 따라 바뀌지 않으므로 이름만으로는 지금 단계를 모른다. **[판단]**
  - 묶음 안에 지금 단계를 늘 담은 숨김 글(`.ku-visually-hidden`, 예: "글자 크기: 보통")을 두고, 두 버튼이 `aria-describedby`로
    가리킨다. 저장된 단계로 다시 들어와 버튼에 초점을 옮겨도 지금 단계가 읽힌다.
  - 이 숨김 글에 `aria-live="polite"`를 달아, 누르면 바뀐 단계("글자 크기: 크게")를 읽어 준다. 처음 그릴 때 들어 있는 글은 바뀐
    것이 아니라 읽지 않는다.
- 버튼 위 글자(`가−`·`가＋`)는 배율을 따라 커지지 않는다(2.2). 커지면 누르는 사이에 버튼이 움직인다.
- 누르면 글자 크기만 바뀐다. 열린 메뉴 패널·건물 상세는 그대로다. 누른 버튼은 끝 단계에 닿아도 초점을 잃지 않는다. 다시 그려져도
  같은 요소로 남는다.

### 1.2 자리

- 오른쪽 아래 지도 버튼 열(`.ku-map-actions`)에 두 버튼을 가로로 붙인 줄 하나를 더한다. 확대·축소(＋/−)는 세로 묶음이라 가로로 두면
  헷갈리지 않는다.
- 이 열은 접힌 줄·펼침·모바일 세 모드 모두에 있다. 다크모드 토글과 달리 글자 크기는 **모든 모드에서 이 열 한 곳에만** 둔다. 메뉴 줄은
  그대로 다섯 칸이다.
- 웹(768px 이상): **[사용자]** 피드백 바로 위.
  - 펼침: 확대·축소 → 내 위치 → 위성 → 다크모드 → **글자 크기** → 피드백
  - 접힌 줄: 확대·축소 → 내 위치 → 위성 → **글자 크기** → 피드백
  - 버튼은 열의 다른 버튼과 같은 44px다. 열의 폭이 이 줄만큼 넓어지고, 열 왼쪽에 바닥을 맞추는 경사도 범례가 그만큼 왼쪽으로 비킨다.
  - 2026-10-28 웹 레이아웃 높이 470px 이하(휴대폰 가로)에서는 확대·축소 묶음을 뺀다. 이 줄이 더해진 열이 오른쪽 위 언어 상자에 닿았다
    (844×390에서 확대 버튼 위 14px가 언어 상자 밑, 펼친 모습은 화면 밖). 두 손가락·휠로 확대할 수 있다.
    - 2026-10-28 조건을 `max-height: 560px`로 올렸고, 휴대폰 가로 화면은 모바일 레이아웃이 되었다(`docs/specs/2026-10-28-mobile-fixes-design.md` 1.1).
- 2026-10-28 열 상자와 그 바깥 틀(`.ku-map-corner`)은 터치를 받지 않고, 버튼과 범례만 받는다. 상자가 가장 넓은 이 줄과 범례에 맞춰
  넓어져, 좁은 버튼 옆과 범례 위의 투명한 빈 자리가 지도와 출처 표기 링크의 터치를 가져갔다(390×844에서 54×222px).
- 모바일(767px 이하): **[판단]** 열 맨 위(내 위치 위). 버튼은 48px다.
  - 피드백 바로 위에 두면 안 되는 이유: 이 줄은 열(48px)보다 넓다. 모바일 경사도 범례는 열 왼쪽 10px까지 차지하고(`right: 74px`)
    출처 표기 바로 위에 서므로 열의 아래쪽과 높이가 겹친다. 줄이 열 아래쪽에 있으면 범례를 덮는다. 열 맨 위는 범례보다 높다.
  - 세로로 세우면 열이 범례와 겹치지 않는다. 그러나 열이 48px 두 칸만큼 높아져, 가로 모드(높이 375px)에서 오른쪽 위 언어 버튼과
    부딪힌다.
  - 가로 모드에서 보이는 높이가 약 358px보다 낮으면 줄이 오른쪽 위 언어 버튼 밑에 깔린다(열 222px + 아래 72px, 언어 버튼 아래 끝
    64px). 이 PR 전에는 열이 짧아 그 기준이 약 300px이었다. 2026-10-28 낮은 높이의 자리는 ⑦에서 정한다 — 실제 휴대폰 가로 화면은
    주소창 때문에 그보다 낮은 경우가 많다.
- 모바일에서 상세 시트나 메뉴 패널이 열린 동안에는 지도 버튼 열 전체가 숨으므로(`.ku-map-corner[data-panel-open]`·
  `[data-overlay-open]`) 글자 크기 버튼도 보이지 않는다. 다른 버튼과 같은 규칙이라 그대로 둔다. ⑦ 모바일 점검에서 다시 본다.

## 2. 범위와 배율

### 2.1 커지는 글자

8.1의 "화면 글자 전체"를 이렇게 나눈다.

- 검색·필터·즐겨찾기·목록 패널(접힌 줄의 패널, 모바일 시트, 웹 펼침의 사이드 패널)과 패널 제목. 패널 안의 버튼(필터 칩·목록 이동
  등)도 커진다.
- 건물 상세(제목·단과대·시설 목록·사진 설명·최종 수정일 등), 사진 확대(`PhotoLightbox`)의 제목·설명.
- 등록 요청 모달(`FacilityRequestModal`, 그 안의 `FacilityFields`와 위치 고르는 지도의 건물 이름 `.bldg-label`)·피드백 모달.
- 시설·명소·경사도 팝업, 경사도 범례의 설명 툴팁, 토스트(`.ku-toast`), 지도 오류 띠(`MapErrorBanner`), 웹 커서 이름표
  (`.ku-map-tooltip`).
- 지도 위 건물 이름(`.ku-building-label`)·명소 이름·지하철역 이름.
  - **[판단]** 지하철역 이름은 8.1의 목록에 없지만 명소 이름과 같은 지도 위 이름표라 함께 키운다.
- 크기를 주지 않아 물려받는 글자. 예: 시설 불러오기 실패 문구(`FacilityList`의 `<p>`), 등록 요청 모달 아래 버튼
  (`.ku-request-modal-actions button`). `globals.css`가 입력·버튼에 `font: inherit`만 주므로 조상의 크기를 따른다(3.3).

### 2.2 그대로인 글자

- **[사용자]** 2026-10-28 메뉴 줄 이름: 접힌 줄·모바일 아래 줄 버튼 이름과 개수 배지. 접힌 줄 칸(64px)과 360px 아래 줄 한 칸(72px)에서
  "라이트모드"가 지금도 꽉 차 있어(다크 모드 설계 1.2), 1.15배만 돼도 넘친다.
- 같은 이유로 칸이 정해진 버튼의 이름: 지도 버튼 열 이름(`.ku-map-action-label`), 언어 버튼(웹 세 버튼, 모바일 트리거·목록),
  글자 크기 버튼 글자.
- 아이콘처럼 쓰는 글자: 마커·묶음 숫자, 아이콘 이모지, 사진 넘김 화살표, 검색 지우기 `×`. 8.1의 "아이콘·마커 크기는 바꾸지 않는다".
- 출처 표기(`.ku-attribution`). 지도를 가리지 않게 최소 크기로 둔 각주다.
- **[판단]** 경사도 범례의 눈금 숫자(`.ku-slope-bands-ticks`, 예: 16.67%). 여섯 칸 눈금이 막대 폭에 같은 간격으로 놓인다.
  `slope-bands-legend.css`의 폭 주석대로 눈금 글자가 칸 간격과 거의 같아, 1.2배면 지금 폭(240px)에서 이웃 눈금끼리 겹친다. 폭을 같이
  늘리면 360px 모바일에서 범례 자리(출처 표기 위, 버튼 열 왼쪽)를 넘는다. 숫자를 그대로 두면 눈금 줄의 박힌 높이도 그대로 맞다.
  범례에서 읽는 설명(칸을 누르면 뜨는 툴팁)은 커진다(2.1).

### 2.3 배율

- **[판단]** 작게 0.9 · 보통 1 · 크게 1.2. 8.1이 처음 열어 둔 범위(크게 1.15~1.2) 중 큰 쪽이다. 메뉴 줄과 눈금 숫자가 2.2에서
  빠져 정해진 칸에 넣어야 하는 글자는 남지 않는다. 패널·상세 시트·모달은 시험(5.2)이 넘침을 본다. 넘치는 곳은 그 자리를 고친다. 값을
  바꿔야 하면 이 문서·멘토링 설계 8.1·시험을 함께 바꾼다.
- **[판단]** 모바일 검색창은 작게에서도 16px 아래로 내려가지 않는다(`max(16px, …)`). 입력 글자가 16px보다 작으면 iOS Safari가 초점을
  줄 때 화면을 확대한다. 웹 검색창은 지금도 15px라 이 PR에서 바닥을 두지 않고 그대로 배율을 따른다.

## 3. 상태와 배율 거는 방법

### 3.1 저장소와 훅 (`src/lib/fontScale.ts`, `src/lib/useFontScale.ts`)

다크 모드 설계 2.1과 같은 틀이다. 다른 것만 적는다.

- 기준은 `<html>`의 `data-font-scale` 속성이다. `"small"`·`"large"`면 그 단계, 없으면 보통이다. 보통일 때는 속성을 지운다.
- `src/lib/fontScale.ts`(React를 가져오지 않는다):
  - `FONT_SCALE_STORAGE_KEY = "ku_font_scale"`, `type FontScale = "small" | "normal" | "large"`, 순서 배열 `FONT_SCALES`.
  - `parseStoredFontScale(value)`: 정확히 `"small"`·`"large"`일 때만 그 단계이고, 그 밖(없음·`"normal"`·모르는 값)은 보통이다(멘토링
    설계 2장).
  - `FONT_SCALE_INIT_SCRIPT`: 3.2의 인라인 스크립트 문자열.
  - `scaledFontSize(px)`: 인라인 스타일용 `calc(Npx * var(--ku-fs, 1))` 문자열(3.3).
- `src/lib/useFontScale.ts`(`"use client"`):
  - `setFontScale(scale)`: 속성을 바꾸고, `localStorage`에 쓴다(예외는 삼킨다 — 화면만 바뀐다). 그리고 구독자에게 알린다.
  - `subscribeFontScale(listener)`, `useFontScale()`: `useSyncExternalStore(subscribe, 속성 읽기, () => "normal")`.
  - 한 단계 위·아래는 버튼 컴포넌트가 `FONT_SCALES` 순서로 정한다.
- 저장 값은 멘토링 설계 2장 표대로 `"small"`·`"normal"`·`"large"`를 쓴다. 보통으로 돌아오면 키를 지우지 않고 `"normal"`을 쓴다.
- 다른 탭의 변경은 지금 탭에 바로 반영하지 않는다(다크 모드 설계 2.1과 같다).

### 3.2 첫 그리기 전 (`src/app/layout.tsx`)

- 다크 모드 설계 2.2의 `<script>`에 `FONT_SCALE_INIT_SCRIPT`를 이어 붙인다. 스크립트 태그는 하나다.
  - 꼴: `;(function(){try{var s=localStorage.getItem("ku_font_scale");if(s==="small"||s==="large")document.documentElement.setAttribute("data-font-scale",s)}catch(e){}})();`.
    ES5만 쓴다.
  - 함수로 감싸 이어 붙인 스크립트에 전역 변수를 남기지 않고, 앞 `;`로 다크 모드 스크립트가 세미콜론 없이 끝나도 문장이 나뉜다.
  - 두 스크립트가 각자 `try`로 감싸져 있어 하나가 실패해도 다른 하나는 돈다.
- 관리자 화면에서도 이 속성은 걸린다. 관리자 CSS는 `--ku-fs`를 읽지 않고, 변수가 공개 화면 뿌리에만 있으므로(3.3) 관리자 글자는
  바뀌지 않는다.

### 3.3 `--ku-fs`

- 배율은 CSS 변수 `--ku-fs` 하나다. **공개 화면 뿌리에만** 값을 건다.

  ```css
  :root[data-font-scale="small"] .ku-font-scope {
    --ku-fs: 0.9;
  }
  :root[data-font-scale="large"] .ku-font-scope {
    --ku-fs: 1.2;
  }
  ```

- 커질 글자(2.1)는 `font-size: calc(12px * var(--ku-fs, 1))` 꼴로 쓴다. 변수가 없는 곳(관리자 화면)에서는 1배로 풀린다.
  - CSS: `map-ui.css`, `slope-bands-legend.css`(툴팁만), `globals.css`의 `.ku-toast`·`.leaflet-tooltip.bldg-label`.
  - 인라인 스타일: `FacilityMarkers`·`LandmarkMarkers`·`SlopeLayer` 팝업, `MapErrorBanner`, `FacilityList`, `PhotoCarousel` 설명,
    `FacilityFields`.
  - 공개·관리자가 함께 쓰는 `FacilityFields`·`.ku-toast`·`.bldg-label`·경사도 범례 툴팁도 같은 꼴로 쓴다. 관리자 쪽은 변수 밖이라
    그대로다.
- 크기를 주지 않은 글자(2.1)가 따라오도록 `.ku-font-scope` 자신에 `font-size: calc(1rem * var(--ku-fs, 1))`를 건다. 1rem은 지금
  이 뿌리들이 물려받는 값(브라우저 기본 글자 크기)이라 보통에서는 달라지지 않고, 사용자가 브라우저 기본 크기를 바꾼 것도 따른다.
  `<html>` 글자 크기는 바꾸지 않으므로 관리자 화면에 번지지 않는다.
- `.ku-font-scope`를 다는 곳:
  - `.ku-map-shell`(`Map.tsx`). 메뉴 패널·건물 상세·토스트·Leaflet 컨테이너(툴팁·팝업·마커)가 그 안이다.
  - `document.body`로 띄우는 공개 화면 뿌리: 피드백(`FeedbackButton`), 등록 요청(`FacilityRequestModal`), 사진 확대(`PhotoLightbox`).
    8.2의 "띄우는 뿌리에 공개 화면 표시를 단다"가 이것이다.
- Leaflet 기본 글자: `leaflet.css`(1.9.4)는 `.leaflet-container`에 `0.75rem`을 두고 이 파일들보다 늦게 불린다. `rem`이라 뿌리의
  배율을 따르지 않으므로 `.ku-font-scope .leaflet-container`로 특이도를 올려 `calc(0.75rem * var(--ku-fs, 1))`로 덮는다(보통에서는 `leaflet.css`의 0.75rem과 같은 값이다).
  - 팝업 내용(`.leaflet-popup-content`)은 `em`이라 컨테이너를 따라온다. 덮지 않는다.
  - `.leaflet-tooltip`에는 글자 크기를 걸지 않는다. `leaflet.css`도 걸지 않아 컨테이너를 물려받는다. `.ku-font-scope .leaflet-tooltip`
    같은 규칙을 두면 클래스 하나짜리 `.ku-building-label`의 크기를 이긴다.
- 줄 높이는 단위 없는 값이라 글자를 따라간다. 글자를 담은 상자가 높이를 `height`로 박아 둔 곳은 크게에서 잘리지 않게
  `min-height`로 바꾼다. 찾는 일은 시험(5.2)이 한다.
- 버리는 방법:
  - `rem` 전환(`<html>` 글자 크기를 바꿈). 속성이 관리자 화면에도 걸려 관리자 글자까지 바뀐다(8.1 "관리자 화면에는 이 설정이 없다").
  - CSS `zoom`. 아이콘·마커까지 커지고(8.1), Leaflet이 재는 좌표와 화면 좌표가 어긋난다.
  - `em`으로 뿌리 글자만 바꾸기. 중첩된 `em`이 곱해져 자리마다 값을 따로 셈해야 한다.

## 4. 지도 위 이름

- 명소 이름(`LandmarkMarkers`)·지하철역 이름(`SubwayMarkers`)은 `L.divIcon` HTML 문자열에 글자 크기를 박는다. 각 값을
  `calc(<지금 값> * var(--ku-fs, 1))` 꼴로 바꾼다. 변수는 그려진 자리(지도 셸 안)에서 풀리므로 HTML이 배율마다 달라지지 않는다. 그래서
  아이콘 캐시 키(8.2)는 그대로 둔다. 기준점(`iconAnchor`)은 아이콘 왼쪽 위에서 잰 고정 px이다. 이름은 두 아이콘 모두 동그라미 아래에
  붙어 아래로 자라므로 동그라미와 기준점의 자리는 그대로다. 다시 잴 것이 없다.
- Leaflet 툴팁·팝업은 열릴 때 자기 크기를 재서 자리를 잡는다(툴팁은 가운데, 팝업은 폭과 화면 안 들이기). 배율이 바뀌면 크기가
  바뀐다. 그래서 `Map.tsx`가 `useFontScale()` 값이 바뀔 때 지도에 열려 있는 툴팁·팝업 레이어마다 `update()`를 부른다
  (`map.eachLayer`).
  - 건물 이름(`.ku-building-label`)도 이 툴팁에 든다. 멘토링 설계 5.2가 굵기 때문에 자리를 다시 재는 것과 같은 이유다. ③의
    강조(`buildingLabel.ts`)는 클래스를 바꾸고 `update()`를 부르는데, 배율 갱신도 같은 `update()`라 둘이 겹쳐도 강조 클래스는 그대로다.
  - 데스크톱에서 열린 시설·명소·경사도 팝업은 지도 밖 버튼 열을 눌러도 닫히지 않는다(Leaflet은 지도 클릭에만 닫는다). 그래서 팝업도
    다시 잰다.
  - 첫 그리기에서는 배율이 이미 걸린 뒤에 툴팁을 만들므로 부를 것이 없다.
- 등록 요청 모달의 위치 지도(`FacilityMap`)는 다시 재지 않는다. 모달 바탕이 화면 전체를 덮어, 모달이 열린 동안 글자 크기 버튼을 누를
  수 없다.
- 모바일에서 누른 건물 이름을 상세 시트 위로 옮기는 계산(멘토링 설계 5.2)은 누를 때 한 번 잰다. 상세가 열린 동안에는 버튼 열이 숨어
  배율을 바꿀 수 없으므로(1.2) 다시 잴 일이 없다.

## 5. 시험

### 5.1 단위 (vitest, `src/lib/fontScale.test.ts`)

- `parseStoredFontScale`: `"small"`·`"large"`는 그 단계다. `"normal"`·`null`·`"LARGE"`·`"1.2"`는 보통이다.
- `FONT_SCALE_INIT_SCRIPT`: 가짜 `localStorage`·`document`로 돌린다(다크 모드 설계 5.1과 같은 방법). `"small"`·`"large"`면 속성이
  걸린다. 그 밖의 값이나 `getItem` 예외면 걸리지 않고 예외도 밖으로 나오지 않는다.
- `setFontScale`: 속성·저장 값을 바꾸고 구독자를 부른다. 보통으로 바꾸면 속성을 지운다. `setItem`이 예외를 던져도 속성은 바뀐다.

### 5.2 E2E 새 파일 `e2e/font-scale.spec.ts`

- 처음 방문: `<html>`에 속성이 없고, 두 버튼이 모두 눌린다(`aria-disabled` 없음).
- 세 자리 — 접힌 줄(`expandMapMenu: false`), 펼침, 모바일 390×844 — 에서 버튼 줄이 지도 버튼 열 안 1.2의 자리에 있다.
  - 처음 숨김 글은 "글자 크기: 보통"이고 두 버튼의 `aria-describedby`가 그것을 가리킨다.
  - `가＋`를 키보드(Enter)로 누르면 `data-font-scale="large"`가 되고 저장 값은 `"large"`다. `가＋`는 `aria-disabled="true"`가 되고,
    초점은 `가＋`에 남으며, 숨김 글이 "글자 크기: 크게"다.
  - `가−`를 두 번 누르면 작게가 되고, 한 번 더 눌러도 그대로다.
  - 열린 메뉴 패널은 누른 뒤에도 열려 있다(접힌 줄에서 필터를 열어 둔 채).
- 배율이 닿는 곳: 크게에서 아래 각 자리의 대표 글자 하나씩이 보통 때 크기의 1.2배(반올림 오차 0.1px)다.
  - 검색 결과·필터·즐겨찾기·목록 패널, 건물 상세
  - 등록 요청 모달(`FacilityFields` 이름, 위치 지도 건물 이름, 아래 버튼)·피드백 모달
  - 시설·명소·경사도 팝업, 경사도 범례 툴팁
  - 건물 이름·명소 이름·지하철역 이름
  - 크기를 주지 않은 글자: 시설 불러오기 실패 문구(시설 조회를 실패시킨다)
- 그대로인 곳(2.2): 크게에서도 메뉴 줄 이름·지도 버튼 열 이름·언어 버튼·글자 크기 버튼 글자·출처 표기·범례 눈금 숫자 크기가 보통
  때와 같다.
- 관리자: 저장 값 `"large"`로 대시보드, 관리자 시설 폼 모달(`FacilityFields`), 관리자 지도 건물 이름(`.bldg-label`)을 열면 글자
  크기가 보통 때와 같다.
- 열린 팝업: 데스크톱에서 시설 팝업을 연 채 `가＋`를 누르면 팝업이 열린 채 남는다. 내용 상자(`.leaflet-popup-content`) 폭이 크게에서
  같은 팝업을 새로 열었을 때의 폭과 1px 안에서 같고, 닫기 버튼이 화면 안에 있다. Leaflet은 열 때 잰 폭을 내용 상자에 박아 두므로,
  다시 재지 않으면 보통 때 폭이 남는다.
- 강조와 배율(멘토링 설계 5.2의 "⑥의 몫"): 이름이 보이는 확대에서 마우스를 올린 건물과 선택된 건물 각각에 대해 배율을 크게로
  바꾸면 강조(불투명도 1, 굵기 800)가 남고 이름 가운데가 1px 안에서 그대로다. 마우스를 빼거나 선택을 풀면 흐린 이름으로 돌아온다.
- 첫 그리기 전: 저장 값 `"large"`에서 앱 JS를 막고 연다. `data-font-scale="large"`다(다크 모드 설계 5.2와 같은 방법). 같은 상태에서
  `ku_theme = "dark"`도 걸리는지 함께 보아, 이어 붙인 두 스크립트가 다 도는지 확인한다.
- 저장소 예외: `localStorage`가 `ku_font_scale`에 예외를 던지면 보통으로 열린다. 버튼을 누르면 화면은 커지고 `pageerror`가 없다.
- 넘침: 360×780 크게에서 검색·필터·즐겨찾기·목록 패널, 건물 상세 시트, 등록 요청·피드백 모달, 경사도 범례가 가로로 넘치지 않는다
  (`scrollWidth ≤ clientWidth`). 글자를 담은 버튼·칩은 내용이 잘리지 않는다. 범례 눈금은 크게에서도 이웃끼리 겹치지 않는다(기존
  `public-map.spec.ts` 눈금 시험과 같은 비교).
- 모바일 검색창은 작게에서도 16px다.
- 모바일 버튼 줄은 경사도를 켰을 때 범례와 겹치지 않는다. 가로 모드 667×375에서 언어 버튼과도 겹치지 않는다.
- 언어: en은 `A−`·`A＋`, zh는 `字−`·`字＋`이고, 버튼 이름이 1.1 표와 같다.

### 5.3 고치는 기존 E2E

- `e2e/support/mockBackend.ts`: `fontScale?: "small" | "large"` 옵션. 저장 값이 없으면 `ku_font_scale`를 넣는다(`theme`과 같은
  방식).
- `e2e/theme.spec.ts` "웹 펼침" 토글 시험: 열 버튼 이름의 끝 세 개가 `위성 · 다크모드 · 피드백`이라는 단언이 거짓이 된다. 끝 다섯 개
  `위성 · 다크모드 · 글자 작게 · 글자 크게 · 피드백`으로 바꾼다.
- `e2e/public-map.spec.ts` 모바일 경사도 범례 시험: 범례 오른쪽 끝이 열 상자(`.ku-map-actions`)의 왼쪽 끝 이하라는 단언이 거짓이 된다.
  모바일 열 맨 위 줄이 열 상자를 왼쪽으로 넓힌다(1.2). 열 상자 대신 범례와 높이가 겹치는 버튼 각각의 왼쪽 끝과 비교하도록 바꾼다.
  웹 범례 시험은 열 상자 기준의 상대 비교라 그대로 맞다.
