# 시설 상세 모달화와 건물 동영상 섹션 설계

**작성일:** 2026-08-04

## 문제

건물 상세 페이지의 `시설 현황` 카드에서 시설 한 줄이 **컨트롤 4~6개를 담은 `flex-wrap` 컨테이너**다. 담기는 개수가 시설 상태에 따라 달라진다.

| 컨트롤            | 출처                          | 조건               |
| ----------------- | ----------------------------- | ------------------ |
| `동영상`          | 행이 직접 렌더                | 항상               |
| `현재 상태: 설치` | `FacilityInstallationControl` | 항상               |
| `미설치로 변경`   | `FacilityInstallationControl` | 항상               |
| `번역 필요`       | `FacilityTranslationControl`  | 번역이 필요할 때만 |
| `재번역`          | `FacilityTranslationControl`  | 번역이 필요할 때만 |
| `삭제`            | 행이 직접 렌더                | 항상               |

두 컴포넌트가 각각 **두 개씩** 넣는다는 점이 밖에서 보이지 않는다. 그래서 번역이 필요한 행만 폭을 넘겨 `삭제`가 다음 줄 맨 왼쪽으로 떨어지고, **행마다 액션 위치가 달라진다.**

시각 언어도 섞여 있다. 상태를 알리는 알약 칩(초록 `현재 상태: 설치`, 노랑 `번역 필요`)과 누르는 버튼(회색 `미설치로 변경`, 주황 `재번역`, 테두리 없는 빨강 `삭제`)이 같은 줄에 같은 크기로 놓여, 어느 것이 클릭 대상인지 형태로 구분되지 않는다. 상태 칩 바로 옆에 그 상태를 바꾸는 버튼이 붙어 읽는 순서도 꼬인다.

여기에 위도·경도가 소수점 7자리로 한 줄을 더 차지한다. `lat`이 있는 행에만 붙어 행 높이도 들쭉날쭉하다. 목록을 훑을 때 쓰는 정보가 아니다.

## 목표

- 행에서 액션을 걷어내 **행의 요소 수를 상태와 무관하게 고정**한다. 줄바꿈 문제는 원인이 사라진다.
- 행이 "손봐야 할 시설"을 한눈에 드러내게 한다.
- 건물 상세에서 동영상 관리를 건물 단위 진입점으로 모은다.

## 범위 밖

- `video_url` 저장 위치 변경. 동영상은 계속 `building_facilities`의 컬럼이고 공개 화면에서도 그 시설 밑에 렌더된다. 건물 동영상 항목의 식별자는 시설 id이며 건물 단위 대표 영상이 아니다.
- 건물당 동영상 개수 제약. 스키마상 시설당 하나이며 그 이상은 규약으로 둔다.
- 시설 이름·설명·층·좌표 편집 기능 신설.
- 시설 삭제 시 동영상이 함께 지워지는 동작 변경.
- **독립 시설 대시보드 `/admin/dashboard/facilities`.** 이 화면은 같은 세 컴포넌트를 같은 방식으로 렌더하고 `수정` 버튼까지 더 있어 행이 더 붐빈다. 이번에는 건물 상세만 바꾸고 대시보드는 옛 행 UI로 남는다 — 두 화면이 한동안 다른 모양이 된다는 뜻이다. 자세한 파급은 `알려진 위험`에.
- **동영상 업로드 API의 기존 결함.** 소유권 검증·입력 검증·상한 불일치는 이 설계가 손대지 않고 그대로 승계한다. `후속 과제`에.

## 설계 1: 건물 동영상 섹션

건물 사진 카드가 카드 하나에 `PhotoManager` 하나를 꽂는 구조다. 동영상도 같은 모양으로 맞춘다 — 카드 제목 `건물 동영상` + `BuildingVideoManager` 하나.

```
┌─ 건물 동영상 ──────────────────────┐
│  ▶ [썸네일]  경사로                │
│              "경사로 입구"          │
│                          관리 ›    │
│  [+ 동영상 추가]                   │
└────────────────────────────────────┘
```

**내용:** 이 건물의 시설 중 `video_url`이 있는 것들을 목록으로 보여준다. 항목마다 시설명과 캡션, `관리` 버튼.

**정렬:** 시설 목록과 같은 순서로 둔다. 현재 시설 쿼리에는 `order`가 없어 DB 반환 순서가 그대로 화면 순서가 되므로, 이 섹션을 만들면서 시설 쿼리에 정렬 기준을 하나 정한다. 안 정하면 운영자가 학습한 순서가 어느 날 바뀌고 E2E locator도 흔들린다.

**공개 미노출 표시:** 공개 API는 `is_installed`가 참인 시설만 내려보낸다. 그래서 미설치 시설에 동영상이 있으면 **관리자에게는 보이고 공개 화면에는 안 보인다.** 목록에서 그 항목에 `공개 안 됨` 표시를 붙인다. 표시 없이 두면 "올렸는데 왜 안 보이냐"가 운영 문의로 돌아온다.

**추가 흐름:** `+ 동영상 추가` → 시설 선택 드롭다운 → 확인 → 기존 `FacilityVideoModal`이 그 시설을 대상으로 열린다.

**교체 경고:** 드롭다운에서 이미 동영상이 있는 시설을 고르면 교체된다고 알린다. `video_url`이 단일 컬럼이라 두 번째 업로드는 덮어쓰기다. 덮어쓴 옛 R2 객체는 참조를 잃고 남는다(`후속 과제`).

**재사용:** 업로드·압축·진행률·캡션·삭제는 `FacilityVideoModal`을 그대로 쓴다. 이 모달은 ffmpeg 압축과 중첩 `ConfirmModal`을 갖고 있어 옮기거나 풀어헤치지 않는다. 포커스 처리는 이 모달이 따로 갖고 있지 않고 공용 `useModalFocus`를 쓴다.

**캡션 번역:** 캡션은 `video_caption_en` / `video_caption_zh`로 번역되는데, 그 번역은 `FacilityVideoModal`이 직접 태우고 `translation_status`에는 반영되지 않는다. 캡션이 이 섹션의 주 표시 정보가 되지만 **캡션 번역 실패는 어디에도 드러나지 않는다.** 이번 범위에서는 캡션 번역 판정을 만들지 않고 `후속 과제`로 둔다 — 설계 2의 배지 규칙이 캡션을 덮지 않는다는 뜻이므로 규칙 서술에서 그 예외를 밝힌다.

**시설이 없는 건물:** 드롭다운에 고를 것이 없으므로 `+ 동영상 추가`를 비활성화하고 먼저 시설을 등록하라고 안내한다.

## 설계 2: 시설 행을 상세 모달로

```
┌─ 시설 현황 ────────────────────────┐
│ ♿  경사로                        › │
│ 🅿  장애인 주차                    › │
│ 🚻  장애인용 화장실 · 전 층 번역필요 › │
│ 🛗  1층 엘리베이터        번역필요 › │
└────────────────────────────────────┘
```

**행:** 아이콘 · 이름 · 설명(층) · 배지 · `›`. 행 전체가 하나의 `<button>`이다.

**배지:** 손봐야 할 때만 붙는다. `미설치`(`is_installed`가 참이 아님), `번역 필요`(`facilityNeedsTranslation`). 정상 시설은 오른쪽이 빈다. **배지가 보이는 행이 곧 손봐야 할 행**이라는 규칙이 목록 전체에서 성립한다 — 아래 두 예외를 뺀다.

- **캡션 번역 실패는 안 잡힌다.** 설계 1의 캡션 번역 항 참조.
- **건물 목록의 경고 카드와 판정이 다르다.** 서버 SQL 플래그는 `translation_status <> 'translated'`만 보는데 `facilityNeedsTranslation`은 그보다 넓어 부분 실패도 잡는다. 경고가 없는 건물에 들어가도 배지가 있는 시설이 있을 수 있다. 통일은 `후속 과제`.

`번역 필요`는 **상시 상태가 아니라 예외 신호다.** 시설을 저장하면 곧바로 자동 번역이 돌아 정상 경로에서는 `translated`가 된다. 배지가 뜨는 경우는 번역 호출이 실패했거나 일부 필드만 채워진 때뿐이다. 그래서 이 배지는 자주 보이면 안 되고, 보이면 실제로 손이 필요하다.

배지는 `<span>`이다. 행이 `<button>`이므로 그 안에 버튼을 두면 안 된다.

**행에서 빠지는 것:** 위도·경도 줄. 모달로 옮긴다.

**모달 내용:** 한 줄에 하나씩.

| 항목 | 내용                                              |
| ---- | ------------------------------------------------- |
| 제목 | 시설명                                            |
| 상태 | `FacilityInstallationControl` 재사용              |
| 번역 | `FacilityTranslationControl` 재사용 (필요할 때만) |
| 위치 | 위도·경도 표시                                    |
| 삭제 | 확인창을 거친다                                   |

**남는 문제 하나:** `FacilityInstallationControl`은 칩과 버튼을 하나의 flex 컨테이너에 넣는다. 모달에서 항목을 한 줄에 하나씩 놓아도 그 줄 안에서는 칩과 버튼이 여전히 나란하다. 이 설계가 푸는 것은 **줄바꿈이지 읽는 순서가 아니다.** 컨트롤을 가르는 일은 이번 범위 밖이고, 대시보드도 같은 컴포넌트를 쓰므로 가를 때 두 화면을 같이 봐야 한다.

**삭제 성공 후:** 모달을 닫고 시설 목록을 다시 읽는다. 포커스는 `시설 현황` 카드의 `+ 시설 추가` 버튼으로 보낸다. 열었던 행이 사라져 `useModalFocus`의 기본 복귀 대상이 없어지고, 남은 모달도 없으면 포커스가 `<body>`로 떨어지기 때문이다.

**동영상은 모달에 없다.** 설계 1의 건물 섹션이 그 자리를 대신한다. 모달 위에 동영상 모달을 겹치는 것 자체는 `useModalFocus`가 스택으로 지원하므로 불가능하지 않다 — 겹치지 않는 쪽을 고른 이유는 동영상 진입점을 한 곳에 모으기 위해서지 기술적 제약 때문이 아니다.

**삭제 확인창:** 대상 시설에 동영상이 있으면 "이 시설의 동영상도 함께 삭제됩니다"를 덧붙인다. 동영상이 건물 섹션에 보이게 된 뒤로는, 시설을 지웠을 뿐인데 건물 동영상이 사라지는 일이 예고 없이 일어나기 때문이다.

## 설계 3: 카드 헤더의 일괄 재번역

지금은 `번역 필요` 칩과 `재번역` 버튼이 한 컴포넌트에서 같이 나오므로 행에서 바로 고칠 수 있다. 설계 2는 이 둘을 가른다 — 행에는 배지만 남고 `재번역`은 모달로 들어간다. 한 건을 고치는 데 행 클릭 · 재번역 · 닫기가 필요해진다.

배지가 예외 신호인 한 그 비용은 감수할 만하다. 감수할 수 없는 것은 **번역 API가 한동안 죽어 시설 여러 건이 한꺼번에 `failed`로 쌓인 날**이다. 그때는 시설마다 모달을 여닫게 된다.

그래서 `시설 현황` 카드 헤더에 진입점을 하나 더 둔다.

```
┌─ 시설 현황 ──────────────────────────────────┐
│         번역 필요 3건 · 전부 재번역  [+ 시설 추가] │
│ ♿  경사로                                  › │
└──────────────────────────────────────────────┘
```

- **대상:** `facilityNeedsTranslation`이 참인 이 건물의 시설 전부. 0건이면 렌더하지 않는다.
- **순차 실행.** 파파고를 병렬로 두들기지 않는다. 진행 중에는 버튼을 비활성화하고 `3건 중 1건` 식으로 남긴다.
- **재검증은 마지막에 한 번.** `FacilityTranslationControl`은 건마다 `/api/revalidate-facilities`를 부르지만, 일괄에서 그렇게 하면 N번 부르게 된다.
- **부분 실패는 배지로 남는다.** 끝나고 `fetchData()`를 한 번 돌리면 실패한 시설의 배지가 그대로 남아 다음 조치 대상이 드러난다. 실패 건수를 토스트로 알린다.
- **행 배지는 그대로 `<span>`이다.** 이 버튼은 카드 헤더에 있으므로 행의 요소 수 고정을 깨지 않는다.

## 상태 소유

건물 상세 페이지가 `facilities` 한 벌을 `fetchData()`로 소유한다. 이 설계는 그 구조를 바꾸지 않는다.

- `BuildingVideoManager`는 조회를 갖지 않는다. `facilities`를 props로 받고 `video_url`이 있는 항목을 파생한다.
- `FacilityDetailModal`도 조회를 갖지 않는다. 시설 id를 받고 본문은 부모의 `facilities`에서 찾아 쓴다. **객체를 통째로 붙들면 `fetchData()` 후 모달 내용이 옛 값으로 남는다.**
- 모든 변경은 성공 후 부모 `fetchData()`를 await 한다. 낙관적 업데이트는 쓰지 않는다.

이 규칙이 있어야 "모달에서 상태를 토글하면 목록 배지가 따라 바뀐다"가 성립한다.

## 컴포넌트 경계

**신규**

| 파일                                             | 책임                                            |
| ------------------------------------------------ | ----------------------------------------------- |
| `src/components/admin/BuildingVideoManager.tsx`  | 건물 동영상 목록 · 시설 선택 · 업로드 모달 진입 |
| `src/components/admin/FacilityDetailModal.tsx`   | 시설 하나의 상태·번역·위치·삭제                 |
| `src/lib/facilityBadges.ts`                      | 시설에서 배지 목록을 계산하는 순수 함수         |
| `src/components/admin/BulkRetranslateButton.tsx` | 번역 필요 시설 일괄 재번역 (설계 3)             |

**수정**

| 파일                                         | 변경                                                             |
| -------------------------------------------- | ---------------------------------------------------------------- |
| `src/app/admin/buildings/[id]/page.tsx`      | 동영상 카드 추가 · 시설 행 단순화 · 모달 연결 · 헤더 일괄 재번역 |
| `src/app/admin/admin-ui.css`                 | 시설 행·배지 클래스 (인라인 스타일 대신)                         |
| `src/components/admin/AddFacilityButton.tsx` | 선택적 `buttonRef` prop — 삭제 후 포커스 복귀 대상               |

`FacilityInstallationControl`과 `FacilityTranslationControl`은 그대로 두고 모달 안에서 재사용한다. 두 컴포넌트는 대시보드도 쓰므로 손대면 두 화면이 같이 움직인다.

`facilityBadges.ts`는 **판정만** 돌려준다 — `Array<"missing" | "translation_needed">`. 배열 순서는 이 함수가 고정하고(미설치가 먼저), 라벨과 클래스는 컴포넌트가 매핑한다. 표시 문자열까지 이 함수가 쥐면 순수 함수가 UI 언어의 원천이 되어 나중에 목록·모달·E2E 접근 이름을 함께 고쳐야 한다.

배지 판정을 빼는 이유는 이 프로젝트에 jsdom이 없어 컴포넌트 단위 테스트가 불가능하기 때문이다. 순수 함수로 두어야 vitest가 덮을 수 있다. 번역 필요 판정은 이미 `facilityNeedsTranslation`에 있으므로 그것을 호출한다 — 조건을 두 벌로 만들지 않는다.

## 접근성

- 행이 `<button>`이므로 내부에 상호작용 요소를 두지 않는다. 배지는 `<span>`.
- 행의 접근 이름은 자손 텍스트로 만들어진다. 배지 `<span>`의 글자가 그대로 이름에 들어가므로 `aria-label`을 따로 붙이지 않는다 — 붙이면 시설명을 덮어쓴다.
- `FacilityInstallationControl`과 `FacilityTranslationControl`은 각각 `role="status"` live region을 갖는다. 모달이 열릴 때마다 이 영역이 삽입되어 낭독된다. 같은 정보를 행 배지가 이미 전달하므로, **모달 안에서는 두 컨트롤의 live region을 끄거나** 배지 쪽을 장식으로 돌리는 것 중 하나를 구현 때 정한다.
- 모달은 기존 `useModalFocus`를 쓴다. ESC로 닫히고 포커스가 갇히며, 닫으면 열었던 행으로 돌아간다(훅이 이미 한다). 삭제 경로만 예외이며 설계 2의 `삭제 성공 후` 참조.

## 검증

**단위 (vitest)** — `facilityBadges.ts`. 설치·미설치, 번역 필요·불필요의 조합에서 나오는 배지 목록.

**E2E (Playwright)**

- 시설 행 클릭 → 모달이 열리고 시설명이 제목에 있다
- 모달에서 상태를 토글하면 목록 배지가 따라 바뀐다
- 모달을 닫으면 포커스가 행으로 돌아온다
- 모달에서 시설을 삭제하면 모달이 닫히고 포커스가 `+ 시설 추가`로 간다
- 정상 시설 행에는 배지가 없다
- 번역 필요 시설이 0건이면 `전부 재번역`이 렌더되지 않는다
- `전부 재번역`을 누르면 대상 시설 배지가 모두 사라진다
- 일부만 번역에 실패하면 실패한 시설의 배지만 남는다
- 건물 동영상 섹션에서 시설을 고르면 업로드 모달이 열린다
- 이미 동영상이 있는 시설을 고르면 교체 경고가 뜬다
- 미설치 시설의 동영상 항목에 `공개 안 됨` 표시가 있다
- 시설이 없는 건물에서 `+ 동영상 추가`가 비활성이다

**수동** — 번역이 필요한 시설이 여러 개인 건물에서 행 높이가 균일한지. 좁은 폭(390px)에서 배지가 이름을 밀어내지 않는지. 교체 경고를 승인한 뒤 실제로 새 동영상이 공개 화면에 뜨는지.

## 알려진 위험

- **E2E mock이 동영상 업로드를 태우지 못한다.** ffmpeg 압축과 R2 업로드가 얽혀 있어, 건물 동영상 섹션은 "모달이 열리는 것"까지만 자동으로 확인된다. 업로드가 실제로 되는지는 수동 확인이 필요하다.
- **기존 E2E가 시설 행의 버튼을 직접 누른다.** 두 화면을 구분해야 한다. 건물 상세 `/admin/buildings/*`를 겨냥한 것은 `admin-p0.spec.ts`와 `admin-buildings-slopes.spec.ts`이며 이쪽 단언은 깨진다 — 계약을 새 흐름으로 옮겨 적어야 하며 단언을 지우기만 해서는 안 된다. 반면 `/admin/dashboard/facilities`를 겨냥한 것(터치 영역 44px 검사 포함)은 그 화면이 이번 범위 밖이므로 손대지 않는다. **둘을 섞어 한꺼번에 고치면 대시보드 회귀를 놓친다.**
- **행이 button이 되면 전역 button 리셋의 영향을 받는다.** `text-align: center`와 색 미상속을 명시적으로 되돌려야 한다. 관리자 모바일 카드에서 같은 문제가 이미 한 번 있었다.
- **재사용하는 업로드 API에 기존 결함이 있다.** 이 설계는 그것을 고치지 않고 진입점만 늘린다. `후속 과제` 참조 — 특히 소유권 미검증은 건물 단위 UI가 "이 건물의 시설만 고를 수 있다"는 인상을 주기 때문에 서버가 그것을 보장한다는 오해를 부른다. 보장하지 않는다.

## 후속 과제

- 시설 이름·설명·층·좌표를 모달에서 편집하기
- 배지 규칙을 건물 관리 목록의 경고 카드 정의와 맞추기 (서버 SQL은 `translation_status`만, 클라이언트는 필드 누락까지 본다)
- `video_caption` 번역 실패를 판정에 포함하기. 지금은 `translateFacility` 대상이 아니라 어느 배지에도 안 잡힌다
- 동영상 교체 시 R2에 남는 옛 객체 정리
- 시설 대시보드 `/admin/dashboard/facilities`를 같은 행 규칙으로 맞추기
- 업로드 상한: 모달 문구를 실제 동작(presign 라우트 500MB)에 맞췄다. 남은 것은 아무도 호출하지 않는 `upload-facility-video` 라우트(200MB)로, 죽은 코드라 지울지 되살릴지 정해야 한다
- `requireAdmin`이 로그인 여부만 확인하고 역할을 보지 않는다. 관리자가 아닌 인증 계정이 생길 수 있으면 아래 두 건의 심각도가 올라간다
- `facility-video-confirm`이 `videoUrl`을 검증 없이 저장한다. 임의 외부 URL이 공개 화면의 `<video src>`로 렌더된다
- `facility-video-presign`이 `fileSize`를 생략하면 상한 검사를 통과하고, presigned PUT에는 크기 조건이 없다. `facilityId`도 검증 없이 R2 key에 들어간다
- 동영상 업로드 3종 API가 시설의 건물 소속을 확인하지 않는다. 다른 건물의 시설 id로 호출하면 그대로 처리된다
