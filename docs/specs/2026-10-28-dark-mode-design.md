# 다크 모드 설계

2026-10-28

## 이 문서의 목적

멘토링 설계(`docs/specs/2026-10-25-mentoring-feedback-design.md`) 7장이 PR ⑤의 요구다 — 기기 설정을 따르지 않고 버튼으로만 다크에
들어가며, 저장 값은 `ku_theme`, 관리자 화면의 지도는 늘 밝다. 이 문서는 그것을 코드로 옮길 때 정할 것(버튼 모양·자리, 상태를 두는 곳,
관리자 지도를 밝게 두는 방법, 시험)을 적는다. 7장에 있는 것은 되풀이하지 않고 절 번호로 가리킨다.

결정 표기: **[사용자]**는 사용자가 정한 것, **[판단]**은 Claude가 정하고 사용자에게 알린 것이다.

## 1. 버튼

### 1.1 모양과 이름

- **[사용자]** 2026-10-28 보기 패널 없이 토글 버튼 하나로 한다. 버튼은 누르면 갈 모드를 보인다.

  | 지금 모드 | 아이콘 | 이름(접근 이름·`title`)            | 보이는 글자(영어만 짧다)      |
  | --------- | ------ | ---------------------------------- | ----------------------------- |
  | 밝음      | `Moon` | 다크모드 · Dark mode · 深色模式    | 다크모드 · Dark · 深色模式    |
  | 다크      | `Sun`  | 라이트모드 · Light mode · 浅色模式 | 라이트모드 · Light · 浅色模式 |

- **[판단]** `aria-pressed`는 달지 않는다. 이름이 상태에 따라 바뀌는 버튼에 눌림 상태까지 달면 "라이트모드, 눌림"처럼 두 신호가
  겹친다(WAI-ARIA APG Button 패턴: 눌림 상태를 쓰는 토글은 이름을 바꾸지 않는다).
- **[판단]** 영어의 보이는 글자만 "Dark"·"Light"로 줄인다. 모바일 360px 아래 줄 한 칸(72px, 안쪽 64px)에 12px로 "Light mode"를
  넣으면 넘쳐 말줄임이 된다. 접근 이름은 "Light mode"로 두어 보이는 글자를 앞에 품는다(WCAG 2.5.3 이름 안의 글자).
- 번역 키: `themeToDark`·`themeToLight`(이름), `themeToDarkLabel`·`themeToLightLabel`(보이는 글자).
- 누르면 모드만 바뀐다. 열린 메뉴 패널·건물 상세·초점은 그대로다. 버튼은 같은 요소로 남아 초점을 잃지 않는다.

### 1.2 공개 지도 자리

멘토링 설계 1장이 ④의 줄에 '보기'를 더하기로 한 자리에 토글을 둔다.

- **접힌 줄(rail):** 목록 아래에 가름줄을 두고 맨 끝에 둔다 — `[펼치기] — [검색][필터][즐겨찾기][목록] — [다크모드]`. 버튼 모양은
  다른 줄 버튼과 같다(64×56px, 아이콘 20px, 11px 이름). 패널을 열지 않으므로 `aria-expanded`·`aria-controls`가 없다.
- **아래 줄(bar):** 오른쪽 끝 다섯째 칸. 칸 나눔을 4에서 5로 바꾼다(360px이면 72px). 상세가 열려 줄이 숨는 동안에는 토글도 없다.
- **펼침(expanded):** **[사용자]** 2026-10-28 오른쪽 아래 지도 버튼 열(`.ku-map-actions`)의 위성 버튼 다음, 피드백 앞에 둔다. 모양은
  위성 버튼과 같은 `ku-map-action--labeled`. 이 열은 모든 모드에 있지만 토글은 펼침 모드에서만 이 열에 그린다 — 한 화면에 토글은
  하나다.
- 이름이 잘리면 안 된다. 접힌 줄 버튼의 글자 자리는 64px에서 테두리 2px와 좌우 안쪽 여백 4px씩을 빼면 54px인데, 11px 한글 다섯
  글자("라이트모드")가 그만큼이다. 토글만 좌우 안쪽 여백을 2px로 줄여 58px로 한다. 시험이 세 언어·세 자리·두 이름(밝음·다크)에서
  말줄임 없이 들어가는지 본다(5.2).

### 1.3 관리자 화면

- `src/app/admin/dashboard/layout.tsx` 헤더의 `.ku-admin-account`에서 "설정" 앞에 `ku-admin-button` 토글을 둔다. 이름은 한국어만이다.
- **[판단]** 768px 이상에서는 아이콘만 보인다(`Moon`/`Sun`, 이름은 `aria-label`과 `title`). 768~899px 헤더는 이미 이메일을 빼고 탭
  여백을 줄여야 로그아웃이 화면 안에 든다(`admin-ui.css`의 그 구간 주석). 글자 버튼 하나를 더 넣을 자리가 없고, 그 구간만 모양을
  바꾸면 규칙이 둘이 된다.
  - 그래도 폭이 모자라다(2026-10-28, 대체 글꼴 768px에서 36px 넘침). 768~899px은 탭 좌우 여백을 10px에서 6px로 줄이고, 900px
    이상은 이메일이 말줄임으로 줄어들어 남는 폭을 내준다(`min-width: 0`).
- 767px 이하에서는 계정 칸의 다른 버튼처럼 숨고, ⋮ 메뉴에 같은 이름(글자)의 `menuitem`을 첫 항목으로 더한다. 누르면 모드를 바꾸고
  메뉴를 닫은 뒤 초점을 ⋮ 버튼으로 돌린다. 다른 항목은 모달을 열거나 화면을 옮기지만 이 항목은 아무것도 열지 않아, 돌리지 않으면
  초점이 사라진 항목과 함께 문서로 떨어진다.
- 건물 상세·새 건물(`/admin/buildings/*`)과 로그인(`/admin`)은 자기 헤더를 쓰고 대시보드 헤더가 없다. 이 화면들에는 버튼을 두지 않고
  저장 값만 따른다. 다크는 대시보드 헤더의 버튼으로만 들어가므로 7.2의 "버튼으로만"은 지켜진다. **[판단]**

## 2. 상태

### 2.1 저장소와 훅 (`src/lib/colorMode.ts`, `src/lib/useColorMode.ts`)

- 기준은 `<html>`의 `data-theme` 속성이다. `"dark"`면 다크, 없으면 밝음이다. 밝음일 때는 속성을 지운다.
- 두 모듈로 나눈다. 서버 컴포넌트인 루트 레이아웃이 스크립트 문자열을 가져오는데, 같은 모듈에 React 훅이 있으면 서버 그래프에 훅이
  들어가고, `"use client"`를 달면 서버가 받는 것이 문자열이 아니라 클라이언트 참조가 된다.
  - 파일 이름은 `colorMode`다. `src/lib/theme.ts`는 이미 TS 쪽 색 값(`campusColor` 등)을 담고 있다.
  - `src/lib/colorMode.ts`(React를 가져오지 않는다): `COLOR_MODE_STORAGE_KEY = "ku_theme"`, `type ColorMode = "light" | "dark"`,
    `parseStoredColorMode(value)` — 정확히 `"dark"`일 때만 다크, 그 밖(없음·`"light"`·모르는 값)은 밝음(멘토링 설계 2장),
    `COLOR_MODE_INIT_SCRIPT` — 2.2의 인라인 스크립트 문자열.
  - `src/lib/useColorMode.ts`(`"use client"`): `setColorMode(theme)` — 속성을 바꾸고, `localStorage`에 쓰고(예외는 삼킨다 — 화면만
    바뀐다), 구독자에게 알린다. `useColorMode()` — `useSyncExternalStore(subscribe, 속성 읽기, () => "light")`.
- **[판단]** 멘토링 설계 7.2의 "상태 공급자(Context) 하나"를 모듈 저장소로 바꾼다. 같은 값 하나를 모두가 읽고 바꾸면 모두 다시
  그린다는 뜻은 그대로다. 바꾸는 이유:
  - 관리자 화면은 서버에서 먼저 그려진다. 서버는 저장 값을 모르므로 서버의 첫 값은 밝음이어야 한다. Context에 `useState`를 쓰면 처음
    값을 `<html>`에서 읽을 때 서버 결과와 달라 hydration이 어긋나고, 효과에서 고치면 다크인 사람에게 밝은 값으로 한 번 그린다(공개
    지도는 밝은 타일을 받았다가 버린다). `useSyncExternalStore`는 hydration 동안 서버 값을 쓰고 끝나자마자 실제 값으로 다시 그린다.
    hydration 뒤에 처음 그려지는 공개 지도(`ssr: false`)는 처음부터 실제 값을 읽는다.
  - 속성을 거는 일은 어차피 React 밖(2.2)에서 먼저 일어난다. 속성을 기준으로 두면 값이 한 곳에만 있다.
- 다른 탭의 변경은 지금 탭에 바로 반영하지 않는다. 멘토링 설계 7.3은 "다른 쪽도 그 모드로 **열린다**"이고, 다음에 열 때 저장 값을
  읽는다.

### 2.2 첫 그리기 전 (`src/app/layout.tsx`)

- `<html lang="ko" suppressHydrationWarning>`. `<head>`의 첫 자식으로 `<script dangerouslySetInnerHTML={{ __html: COLOR_MODE_INIT_SCRIPT }} />`.
- 스크립트: `try { if (localStorage.getItem("ku_theme") === "dark") document.documentElement.setAttribute("data-theme", "dark") } catch (e) {}`
  꼴. ES5 문법만 쓴다. ⑥이 같은 스크립트에 `ku_font_scale`을 더한다.
- `<head>`의 동기 인라인 스크립트는 브라우저가 문서를 읽는 중 그 자리에서 실행하고, 화면은 `<head>`를 다 읽은 뒤에 그린다. 그래서
  첫 그리기 전에 속성이 걸린다. 지금 같은 `<head>`에 JSON-LD 스크립트를 같은 방식으로 넣고 있다.
- `suppressHydrationWarning`은 `<html>` 요소 자신의 속성 차이만 덮는다. 자식의 hydration 검사는 그대로다.

## 3. 색

### 3.1 다크 토큰

- `src/app/globals.css`의 `@media (prefers-color-scheme: dark)` 두 곳을 바꾼다.
  - 토큰 블록: `:root[data-theme="dark"] { color-scheme: dark; … }`. 값은 그대로다.
  - 타일 어둡게(`.leaflet-tile-pane`의 `filter`): `:root[data-theme="dark"] .leaflet-tile-pane`로 걸고, `.ku-light-scope .leaflet-tile-pane`
    을 다크 선택자에 붙여(`:root[data-theme="dark"] .ku-light-scope .leaflet-tile-pane`) `filter: none`으로 푼다. 다크 쪽
    선택자의 특이도가 높아 `.ku-light-scope .leaflet-tile-pane`만으로는 지지 않는다. 밝은 범위 클래스가 Leaflet 컨테이너에 있든 그 바깥 틀에 있든 같이 풀린다(3.2).
- 화면의 다른 색은 모두 토큰을 읽는다(색 토큰 선언은 `globals.css`에만 있다). `document.body`로 띄우는 공개 모달도 `:root` 토큰을
  읽어 함께 바뀐다.
- `src/components/MapWrapper.tsx` 로딩 자리의 `#f5f5f0`을 `var(--ku-bg)`로 바꾼다. 멘토링 설계 7.1대로 쓰이지 않는
  `src/app/page.module.css`를 지운다.

### 3.2 관리자 지도는 밝게

- **[사용자]** 관리자 화면의 지도는 늘 밝다 — 타일과 지도 위 색 모두(멘토링 설계 7.3).
- 지도 위 UI 중 토큰을 읽는 것이 있다. 예: 관리자 지도의 건물 이름표(`.leaflet-tooltip.bldg-label`)는 `--ku-text-2` 글자에
  `--ku-surface` 테두리다. 다크 토큰이 닿으면 밝은 타일 위에 밝은 글자가 된다.
- 그래서 밝은 토큰 블록의 선택자를 `:root, .ku-light-scope`로 하고, 밝게 둘 지도를 감싼 요소에 `ku-light-scope`를 단다. 그 요소가
  밝은 값을 직접 선언하므로 `<html>`에서 물려받는 다크 값을 이긴다. 안의 타일·이름표·팝업·Leaflet 컨트롤·geoman 도구가 모두 밝게
  남는다. `color-scheme: light`도 같은 블록에 있다.
  - 다는 자리: Leaflet 컨테이너 요소. 단 `FacilityMap`은 지도와 그 형제인 현 위치 버튼(`.ku-facility-map-locate`)을 함께 감싼 바깥
    틀이다. 제보함 드로어의 그 버튼은 `admin-ui.css`가 토큰으로 칠하는데(`.ku-inbox-drawer .ku-facility-map-locate`), 틀 안에서
    토큰이 밝은 값으로 풀려 밝은 지도와 같이 밝다.
  - 밝은 토큰을 한 벌 더 적지 않고 선택자만 더한다. 값이 한 곳에 있다.
  - 토큰 블록의 `--ku-primary-text: var(--ku-crimson-600)` 같은 참조는 선언된 요소에서 풀리므로 `.ku-light-scope` 안에서도 밝은
    크림슨을 가리킨다.
- 지도 둘레(카드·툴바·패널)는 테마를 따른다 — 멘토링 설계 7.3의 "지도 밖".

### 3.3 다크에서 읽히지 않는 박힌 색

  팝업 이름 `#222`는 다크 팝업 바탕(`--ku-surface`) 위에서 대비가 1.1:1도 안 된다. 다크가 사용자가 고르는 모드가 되므로 ⑤에서 고친다.
  **[판단]**

## 5. 시험

### 5.1 단위 (vitest, `src/lib/colorMode.test.ts`)

두 모듈(2.1)을 한 시험 파일에서 본다.

- `parseStoredColorMode`: `"dark"` → 다크, `"light"`·`null`·`"DARK"`·`"1"` → 밝음.
- `COLOR_MODE_INIT_SCRIPT`: 가짜 `localStorage`·`document`를 인자로 받는 함수로 감싸 돌린다(vitest 환경이 `node`다). 저장 값 `"dark"`면
  속성이 걸리고, 그 밖의 값이나 `getItem` 예외면 걸리지 않으며 예외가 밖으로 나오지 않는다.
- `setColorMode`: 속성·저장 값을 바꾸고 구독자를 부른다. `setItem`이 예외를 던져도 속성은 바뀌고 예외가 나오지 않는다. 밝음으로 바꾸면
  속성을 지운다.

### 5.2 E2E 새 파일 `e2e/theme.spec.ts`

- 처음 방문: 기기 다크(`colorScheme: "dark"`)여도 저장 값이 없으면 `<html>`에 속성이 없고, 밝은 타일(`light_all`)이며, 토글 이름은
  "다크모드"다.
- 세 자리에서 토글: 접힌 줄(`expandMapMenu: false`), 펼침(`.ku-map-actions`), 모바일 390×844 아래 줄. 누르면 `data-theme="dark"`,
  `dark_all` 타일, 건물 채움 `#FF4D3D`, `body` 바탕이 다크 `--ku-bg`, 저장 값 `"dark"`, 이름 "라이트모드". 다시 누르면 되돌아온다.
  열린 메뉴 패널은 토글 뒤에도 열려 있다(접힌 줄에서 필터를 열어 둔 채).
- 첫 그리기 전: 저장 값 `"dark"`에서 앱 JS(`/_next/static/**/*.js`)를 막고 연다. 인라인 스크립트만 돌 수 있는 상태에서
  `data-theme="dark"`이고 `body` 바탕이 다크 `--ku-bg`다. 효과나 늦은 스크립트로 옮기면 이 시험이 깨진다.
- 새로 고침: 저장 값 `"dark"`로 평소처럼 열면 공개 지도의 **첫 타일 요청부터** `dark_all`이다(`page.on("request")`로 모아
  `light_all`이 하나도 없다). 콘솔에 hydration 경고가 없다.
- 저장소 예외: `localStorage.getItem`·`setItem`이 `ku_theme`에 예외를 던지게 하면 밝게 열리고, 토글하면 화면은 다크가 되며
  `pageerror`가 없다.
- 이름 잘림: ko·en·zh 각각에서 접힌 줄·아래 줄(360×780)·펼침의 토글 글자가 밝음·다크 두 이름 모두 `scrollWidth ≤ clientWidth`다.
- 공개 등록 요청 모달: 다크에서 모달 안 지도가 `dark_all`이다.
- 공개 화면 대비 검사(다크): 접힌 줄의 검색 결과·필터·즐겨찾기·목록 패널, 건물 상세, 시설·명소·경사도 팝업, 등록 요청·피드백 모달을
  차례로 열고 글자 대비를 잰다.
  - 글자를 직접 가진 보이는 요소마다 글자색과, 화면에서 그 밑에 처음 깔린 불투명(알파 0.9 이상) 바탕색의 WCAG 대비를 잰다.
    `--ku-map-control`은 알파 0.94·0.96이라 불투명으로 친다. 그 사이에 배경 그림이 있으면(사진) 건너뛴다.
  - "밑에 깔린"은 글자 가운데 점의 쌓임(`elementsFromPoint`)에서 자기부터 아래로 본다. Leaflet 팝업 닫기 버튼은 DOM에서
    `.leaflet-popup`의 자식이라 조상을 따라 올라가면 지도 컨테이너의 회색 바탕을 만나지만, 화면에서는 팝업 상자 위에 있다. 가운데 점이
    화면 밖이거나 자기가 잡히지 않으면(`pointer-events: none`) DOM 조상으로 올라간다.
  - 기준 4.5:1, 큰 글자(24px 이상, 또는 18.66px 이상이면서 굵기 700 이상)는 3:1.
  - `.leaflet-tile-pane`·`.leaflet-marker-pane`(바탕이 박힌 이름표·마커) 안은 뺀다.
  - 밝은 화면에는 돌리지 않는다. 밝은 `--ku-text-3`(`#8a837d`)이 흰 바탕에서 4.5:1이 안 되는 등 이 PR 밖의 기존 값이 걸린다.
- 관리자:
  - 웹 헤더 토글과 390px의 ⋮ 메뉴 항목이 모드를 바꾼다. ⋮ 항목을 키보드(Enter)로 누르면 메뉴가 닫히고 초점이 ⋮ 버튼에 있다.
  - 768·899·900·1280px에서 헤더가 가로로 넘치지 않고(`scrollWidth ≤ clientWidth`), 토글·로그아웃(767px 이하는 ⋮)이 화면 안에 있다.
  - 다크에서 관리자 지도 — 작업 지도(시설·명소·경사도), 건물 상세 미리보기, 폴리곤 편집, 경사도 경로 그리기·수정, 시설 폼 모달,
    제보함 드로어 — 는 `light_all`만 받고 `dark_all`이 없으며 타일 칸의 `filter`가 `none`이다. 지도 위 건물 이름표 글자색이 밝은 `--ku-text-3`(`rgb(138, 131, 125)`, 작업 화면은 이름표를 옅게 칠한다 —
    `admin-ui.css`의 `.ku-map-workspace .bldg-label`)이고, 작업 지도의 확대 버튼(`.leaflet-control-zoom a`, 토큰으로 칠한다)과 제보함 드로어의 현 위치 버튼 바탕이 밝은
    `--ku-surface`(흰색)다. 경사도 목록 지도와 경로 그리기 지도의 외곽선이 밝은 지도 값(`#1C1917`)이다.
