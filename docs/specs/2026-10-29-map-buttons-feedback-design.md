## 1. 좁은 화면 지도 버튼 이름 (PR 1)

### 1.1 지금

- 웹은 현 위치·위성·경사도·(펼침의 다크모드)·피드백 버튼이 아이콘 아래 이름을 보인다(`.ku-map-action--labeled`).
- 모바일 레이아웃(767px 이하 또는 가로 좁은 화면, `src/lib/viewport.ts`)은 같은 버튼을 48×48로 줄이고 이름을 `display: none`으로
  숨겼다. 웹 화면에서 본 사람은 "데스크톱은 좋다", 휴대폰에서는 "아이콘만 보고 직관적으로 모르겠다"고 했다.

### 1.2 동작

- **[사용자]** 모바일 레이아웃에서도 이름 붙은 버튼은 아이콘 아래 이름을 보인다. 글자 크기 두 버튼(`가−`·`가＋`)은 그대로다(4장에서
  바뀐다).
- **[판단]** 이름 붙은 버튼은 56×52px, 이름 글자는 10px(웹 10.5px)다.
  - 폭을 하나로 정한다. 세로 좁은 화면의 경사도 범례가 열 왼쪽 한 자리에 맞춰 서기 때문이다(`right` = 16 + 56 + 10 = 82px).
    글자 길이를 따라 폭이 바뀌면 영어에서 피드백·현 위치 버튼이 범례를 덮는다.
  - 56px는 넓은 글꼴의 가장 긴 이름이 들어가는 폭이다. 굵은 10px에서 "Feedback"이 Segoe UI 45px, Verdana 53px다. CI 리눅스는
    `sans-serif`가 DejaVu Sans(Verdana와 너비가 비슷하다)라 Verdana로 재서 정했다. 52px였다면 Verdana에서 넘친다.
  - 이름 글자는 글자 크기 배율을 따르지 않는다(`docs/specs/2026-10-28-font-scale-design.md` 2.2 그대로).
- **[판단]** 영어 현 위치 버튼의 보이는 이름은 "My Location"(Segoe UI 굵게 59px)이 칸에 들어가지 않아 **"Location"**으로 줄인다.
  새 번역 키 `myLocationLabel`(ko 현 위치 · en Location · zh 我的位置)이고, 웹에서도 같은 이름을 보인다. 접근 이름·`title`은
  `myLocation`("My Location") 그대로다. 보이는 이름이 접근 이름에 들어 있어 WCAG 2.5.3(Label in Name)을 지킨다.
- 세로 좁은 화면의 열은 이름 붙은 네 버튼이 4px씩 높아져 16px 높아진다. 가로 좁은 화면의 가로 줄은 32px 넓어진다.

### 1.3 시험 (`e2e/map-button-labels.spec.ts`)

- 360×780 · 390×844 · 740×360 × ko·en·zh: 이름이 위 순서대로 보이고, 버튼 칸 안에 들어가며, 버튼이 48px 이상이고 폭이 모두 같다.
- 같은 세 크기에서 경사도를 켜면 범례가 지도 버튼 어느 것도 덮지 않는다.

## 2. 경사도 버튼 아이콘 (PR 1)

- 지금은 lucide `Mountain`이다. 밑선(`H2`)으로 닫힌 두 봉우리라 산으로 읽힌다. 이 아이콘은 공개 지도 버튼 한 곳에서만 쓴다.
- **[사용자]** 밑선 없이 꺾은선 그래프처럼 한다.
- **[판단]** `src/components/map/iconography.tsx`의 `SlopeLineIcon`(`createLucideIcon("slope-line", …)`, 클래스 `lucide-slope-line`).
  선 하나 `m2 17 5-8 4 4 5-7 6 8` — 왼쪽 아래에서 오르내리며 두 번 오르고 오른쪽 중간에서 끝난다. 양 끝이 바닥에 닿지 않아 봉우리
  윤곽으로 읽히지 않는다. 굵기·끝 모양은 lucide 기본(2px, 둥근 끝)이다.
- **[판단]** lucide `TrendingUp`·`ChartLine`을 쓰지 않는다. `TrendingUp`은 이미 경사로 시설 아이콘(`facilityStyleCatalog`의
  `trending-up`)이라 같은 지도에서 둘이 헷갈린다.
- 시험: 웹·모바일에서 경사도 버튼 아이콘이 `lucide-slope-line`이고 `lucide-mountain`이 아니다(E2E). 아이콘 노드가 닫기(`z`)·가로
  밑선(`h`) 없는 선 하나다(`iconography.test.ts`).

## 3. 건물 이름이 보이는 확대 (PR 1)

- 지금은 웹 17, 모바일 18 이상에서 모든 건물 이름이 보인다(`Map.tsx`의 `buildingLabelsVisible`). 모바일은 16에서 열리므로 두 번
  확대해야 했다. 보낸 화면은 건물 크기로 보아 확대 17로 추정한다.
- **[판단]** 웹·모바일 모두 17부터 보인다. `buildingLabel.ts`의 `BUILDING_LABEL_MIN_ZOOM = 17` 하나로 쓰고, 웹 커서 이름표가 물러나는
  두 조건(`mouseover`·`mousemove`)도 같은 상수를 쓴다.
  - 확대 17에서 화면 1px가 나타내는 땅은 기기와 상관없이 같으므로, 이름끼리의 겹침은 이미 받아들인 웹 17과 같다. 휴대폰은 화면이
    좁아 한 번에 보이는 이름 수가 적을 뿐이다.
  - 명소 이름(`LandmarkMarkers`의 `showLabels`)도 같은 값을 받으므로 모바일에서 함께 17부터 보인다.
- 처음 확대(16)는 그대로다. 캠퍼스 전체가 한 화면에 들어오는 확대라 이름을 다 띄우면 겹친다.
- 시험: 1280×800·390×844에서 처음에는 이름이 숨고, 한 번 확대(17)하면 건물 이름과 명소 이름이 보인다.

## 4. 글자 크기 슬라이더 (PR 2)

버튼 모양·단계·저장 값은 이 장이 `docs/specs/2026-10-28-font-scale-design.md`(이하 "글자 설계")를 대신한다. 글자 설계는 이 장이
건드리지 않은 것(커지는 글자와 그대로인 글자, `--ku-fs` 틀, 지도 위 이름 다시 재기)에서만 기준이다.

### 4.1 정한 것

- **[사용자]** `가−`·`가＋` 두 버튼을 버튼 하나로 바꾸고, 누르면 슬라이더로 조절한다.
- **[사용자]** 슬라이더로 바꾸는 김에 범위를 넓힌다. **90% ~ 150%, 10%씩 일곱 칸.**
  - 1.2배에서 멈췄던 까닭은 칸이 정해진 글자(메뉴 줄 이름·범례 눈금)였는데, ⑥에서 그 글자들은 이미 배율을 따르지 않게 뺐다
    (글자 설계 2.2·2.3). 남는 위험은 패널·상세 시트·모달이 150%에서 넘치는 것이고, 시험으로 찾아 그 자리를 고친다.
- **[사용자]** 이미 고른 값은 이어진다. 저장 값 `"small"`은 90%, `"large"`는 120%다.

### 4.2 값과 저장

- **[판단]** 값은 백분율 정수 `90 | 100 | 110 | 120 | 130 | 140 | 150`(`src/lib/fontScale.ts`의 `FONT_SCALES`)이고 처음은 100이다.
- **[판단]** 같은 키 `ku_font_scale`에 숫자 문자열(`"90"`~`"150"`)을 쓴다. 100으로 돌아와도 지우지 않고 `"100"`을 쓴다.
  - 읽기는 일곱 숫자 문자열 중 하나와 정확히 같을 때 그 값이다. 옛 값 `"small"`·`"normal"`·`"large"`는 90·100·120이다. 그 밖
    (`"95"`·`"160"`·`"1.2"`·`" 120"`·`"LARGE"` 등)은 100이다.
  - 옛 값을 새 꼴로 고쳐 쓰지 않는다. 읽기가 옛 값을 계속 받고, 슬라이더를 움직이면 새 꼴로 바뀐다.
- **[판단]** 배율은 지금처럼 `<html data-font-scale>`에 건다. 100이 아닐 때 그 숫자(`"150"`)를 걸고 100이면 지운다. CSS는 여섯
  규칙 `:root[data-font-scale="150"] .ku-font-scope { --ku-fs: 1.5; }`이다.
  - `<html>`에 `--ku-fs`를 인라인으로 걸지 않는다. 변수가 관리자 화면까지 닿아, 함께 쓰는 `FacilityFields`·`.ku-toast`·
    `.bldg-label`이 관리자에서도 커진다.
- **[판단]** 첫 그리기 스크립트는 옛 값을 먼저 숫자로 바꾸고, 100이 아닌 여섯 값과 정확히 맞을 때만 속성을 건다. 정규식은
  `FONT_SCALES`에서 만들고, 단위 시험이 스크립트와 읽기 함수의 답이 같은지 본다.

### 4.3 버튼과 슬라이더 칸

- **[판단]** 버튼은 1장의 이름 붙은 버튼과 같은 꼴이다. 아이콘 자리에 언어별 글자(`가`·`A`·`字`, 키 `fontScaleGlyph`), 아래에
  이름(`fontScale`: 글자 크기·Text size·字号)을 둔다. 접근 이름도 `fontScale`이고, `title`은 지금 값을 붙인 "글자 크기
  120%"다.
  - `aria-expanded`가 있고, 열렸을 때만 `aria-controls`가 칸을 가리킨다. 열린 동안은 눌린 버튼과 같은 색이다.
  - 자리는 지금과 같다. 웹은 피드백 바로 위, 모바일은 열 맨 위다. 세로 좁은 화면 열 맨 위 줄이 102px에서 56px로 줄어 다른 버튼과
    폭이 같아진다.
  - "Text size"는 굵은 10px에서 Segoe UI 38px, Verdana 50px, DejaVu Sans 41px라 56px 칸에 들어간다.
- **[판단]** 누르면 `작은 가 ──●── 큰 가  120%` 칸(`.ku-font-scale-popover`)이 열린다. 슬라이더는 `<input type="range">`(90~150, 10씩)이고
  끄는 대로 바로 바뀐다. 지도에 열린 툴팁·팝업은 값이 바뀔 때마다 다시 잰다(글자 설계 4장).
  - 열리면 초점이 슬라이더로 간다. 보장하는 키는 화살표·Home·End다. PageUp·PageDown은 브라우저마다 움직이는 칸 수가 달라 보장하지
    않는다.
  - 버튼과 칸의 글자는 배율을 따르지 않는다. 끄는 사이에 칸이 커지면 손가락 밑에서 슬라이더가 움직인다.
- **[판단]** 칸 자리
  - 세로 열(웹·세로 좁은 화면)에서는 버튼 왼쪽 8px이고, 아래 끝을 버튼에 맞춘다. 폭 240px다.
  - 가로 좁은 화면에서는 범례까지 담은 버튼 묶음(`.ku-map-corner`)의 위 8px, 왼쪽 끝에 맞춘다. 경사도를 켜도 범례를 덮지 않는다.
  - 웹에서 경사도를 켜도 칸은 범례 바로 위에 열려 덮지 않는다. 범례(56px)와 칸 아래 끝(피드백 버튼 48.6px + 간격 10px)이 모두 px로
    정해진 높이라 2.6px 틈이 글꼴과 배율에 상관없이 남는다(2026-10-29 headless 화면 확인).
- **[판단]** 닫기: 버튼을 다시 누름, 바깥을 누름(`pointerdown`), Esc, 초점이 칸 밖 요소로 감(바깥 `focusin`).
  - Esc는 열린 지도 메뉴 패널을 함께 닫지 않고(`preventDefault`), 초점을 버튼으로 돌려준다.
  - 경사도 범례 툴팁은 바깥을 누를 때만 닫혀, 키보드로는 툴팁과 칸이 함께 열릴 수 있다. Esc 한 번에 나중에 연 칸만 닫는다. 칸의 Esc
    수신기는 캡처 단계에 두고, 범례는 이미 처리된 Esc(`defaultPrevented`)를 넘긴다. 두 번째 Esc가 툴팁을 닫는다(Codex 리뷰).
  - `focusout`을 쓰지 않는다. 칸 안 글자(값·양 끝 글자)를 누르면 초점이 `body`로 가 칸이 닫혀 버린다.
  - 모바일에서 상세 시트·메뉴 패널을 여는 손짓은 모두 칸 바깥 누름이라, 열이 숨기 전에 칸이 닫힌다.
- **[판단]** 숨김 상태 글(`aria-live`)과 버튼의 `aria-describedby`를 없앤다. 슬라이더가 이름과 값("글자 크기, 120%")을 스스로 읽어
  준다.
  - 버튼에 초점만 두었을 때는 `title`이 설명으로 읽힌다("글자 크기, 버튼, 글자 크기 120%"). Chrome 접근성 트리에서 이름 "글자
    크기"·설명 "글자 크기 120%"를 확인했다. 이름을 보이는 글자와 같게 두어 WCAG 2.5.3을 지키고, 마우스를 올리면 지금 값이 보인다.
- **[판단]** 번역 키 `fontScaleDown`·`fontScaleUp`·`fontScaleDownGlyph`·`fontScaleUpGlyph`·`fontScaleStatusSmall`·
  `fontScaleStatusNormal`·`fontScaleStatusLarge`를 지우고 `fontScaleGlyph`를 더한다.

### 4.4 시험

- 단위(`src/lib/fontScale.test.ts`): 일곱 숫자 문자열·옛 세 값·그 밖의 값(`"95"`·`" 120"`·`"__proto__"` 등) 읽기. 첫 그리기
  스크립트가 같은 입력 전부에서 읽기 함수와 같은 속성을 건다. 저장소 예외, `setFontScale(150)`·`(100)`.
- `e2e/font-scale.spec.ts` 버튼
  - 처음: 속성 없음, `aria-expanded="false"`, 설명 "글자 크기 100%", 칸 없음.
  - 접힌 줄·펼침(경사도 켬)·모바일 390×844·가로 740×360(경사도 켬): 열 버튼 차례, 키보드로 열면 슬라이더에 초점, 화살표·Home·End,
    Esc로 닫고 초점이 버튼에 돌아옴, 접힌 줄에서 열어 둔 필터 패널은 남음. 칸은 화면 안이고 지도 버튼·범례를 덮지 않는다.
  - 닫기: 버튼 다시 누름·지도 누름·Tab. 칸 안 글자를 눌러도 남는다. 모바일에서 아래 줄 "검색"을 누르면 닫히고 패널을 닫아도 닫혀 있다.
  - 키보드로 범례 툴팁을 연 채 칸을 열면 첫 Esc는 칸만 닫고 초점을 버튼에 돌려주며, 두 번째 Esc가 툴팁을 닫는다.
  - 마우스로 슬라이더 끝을 누르면 150. 터치(`hasTouch`)로 탭해 열고, 끝을 탭하면 150, 지도를 탭하면 닫힌다.
  - 옛 값 `"small"`·`"large"`·`"normal"`, en·zh 이름, 앱 JS 없이 `"130"`·`"large"`(다크와 함께), 저장소 예외.
- `e2e/font-scale.spec.ts` 배율·넘침
  - 글자 설계 5.2의 자리마다 150%에서 1.5배다. 90%에서 건물 상세 제목이 0.9배다.
  - 그대로인 글자에 버튼 글자·이름과 칸 글자(150%에서도 100%에서 연 칸과 같은 크기)를 더한다. 관리자는 `"150"`과 옛 `"large"`에서
    그대로다.
  - ko·en × 360×780·740×360, 150%: 검색·필터(칸 연 뒤)·즐겨찾기·목록 패널, 건물 상세, 등록 요청·피드백 모달, 경사도 범례, 슬라이더
