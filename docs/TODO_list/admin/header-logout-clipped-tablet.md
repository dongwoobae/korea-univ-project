# 768~828px 폭에서 관리자 헤더의 `로그아웃` 버튼이 화면 밖으로 잘린다

관리자 헤더는 767px 이하에서만 이메일·`설정`·`지도`·`로그아웃`을 숨기고 메뉴(`ku-admin-menu`)로 접는다
(`src/app/admin/admin-ui.css`의 `@media (max-width: 767px)` 안 `.ku-admin-email` … `.ku-admin-logout` 규칙).
768px부터는 브랜드·메뉴 링크(`ku-admin-nav`)·이메일·버튼이 모두 한 줄에 펼쳐지는데, 그 합이 폭보다 넓어
헤더가 넘친다. 맨 끝의 `로그아웃`이 화면 밖으로 나가 누를 수 없다.

2026-10-14 Playwright로 잰 헤더 넘침(`scrollWidth - clientWidth`, 독립 시설 화면, 이메일 `admin@example.com`):

| 폭    | `main`(c469f93) | `feat/admin-map-first` |
| ----- | --------------- | ---------------------- |
| 768px | 67px            | 61px                   |
| 800px | 35px            | 29px                   |
| 820px | 15px            | 9px                    |
| 900px | 0               | 0                      |

관리자 지도 우선 리디자인 PR ①(#28)이 만든 문제가 아니라 그 전부터 있었다. PR ①은 태블릿 폭에서 작업 화면의 목록
숨김만 다루고 헤더 접힘 경계는 바꾸지 않았다. 이메일이 길면 넘침도 커진다.

## 막힌 이유

**어떻게 접을지가 디자인 결정이다.** 핸드오버(`docs/specs/2026-10-14-admin-map-first-handoff/README.md`)는 데스크톱과
모바일 헤더만 정하고 그 사이 폭을 정하지 않는다.

## 트리거

없음. 태블릿으로 관리자를 쓰는 사람이 있으면 앞당긴다.

## 착수 시 정할 것

- **무엇을 먼저 접을지.**
  - 이메일만 숨긴다 — 메뉴 팝오버(`ku-admin-menu-popover`)에 이메일이 이미 있지만, 그 메뉴는 767px 이하에서만 보인다.
    이메일 칸 폭(지금 약 115px)만큼 줄어 768px에서도 들어간다. 긴 이메일에도 안전하다.
  - 메뉴로 접는 경계를 올린다(예: 899px 이하) — 단순하지만 768px 이상에서 아래 nav 등 다른 모바일 규칙과 경계가
    갈린다. 같은 767px 경계를 쓰는 규칙이 여러 개라 메뉴 접힘만 따로 올려야 한다.
  - 이메일에 `max-width` + 말줄임 — 한 줄은 지키지만 768px에서는 그래도 모자랄 수 있다.
- **E2E.** `e2e/admin-shell.spec.ts`에 768px에서 `로그아웃`이 화면 안에 있고 헤더가 넘치지 않는지 더한다.

## 출처

2026-10-14 관리자 지도 우선 리디자인 ① 마무리 중 태블릿(820px) 확인에서 발견.
