# 제보함 드로어가 바쁜 동안 다른 화면으로 떠나면 승인 뒤 번역 호출이 빠질 수 있다

등록 요청 드로어는 승인 응답을 받은 뒤 클라이언트에서 `translateFacility`와 `/api/revalidate-facilities`를 부르고,
그동안 바쁜 상태로 남는다. 드로어의 닫기 길(✕·배경·Esc·같은 화면 헤더 링크)은 바쁜 동안 막지만, 다른 헤더 링크와
브라우저 뒤로가기는 막지 않는다. 레이아웃의 이동 가드(`UnsavedChangesGuard`)가 저장 안 한 변경(dirty)만 보기 때문이다.
승인 응답 뒤 번역 호출 전에 화면을 떠나면 시설은 만들어졌지만 번역이 비고, 공개 지도 캐시도 다시 만들어지지 않는다.

옛 검토 모달(`FacilityRequestReviewModal`, 2026-10-15 삭제)에도 있던 틈이다. 관리자 지도 우선 리디자인 PR ④가 만든
문제가 아니다(설계 `docs/specs/2026-10-14-admin-map-first-redesign-design.md` 7.2).

## 막힌 이유

**가드가 막을 이유를 하나만 안다.** 바쁜 동안을 dirty로 등록하면 이동 확인 창이 "저장하지 않은 변경사항이 있어요"라고
말해 상황과 맞지 않는다. 가드에 "진행 중인 작업" 같은 두 번째 이유와 문구를 더해야 한다.

## 트리거

번역이 빈 승인 시설이 실제로 나오면 앞당긴다. 건물 화면의 재번역 버튼으로 손으로 메울 수 있다.

## 착수 시 정할 것

- 가드에 진행 중 작업을 등록하는 API와 확인 문구(막을지, 물을지).
- 같은 틈이 있는 다른 화면(독립 시설·명소 저장 뒤 번역)을 함께 다룰지.
