# R2에 DB가 참조하지 않는 영상·포스터가 쌓인다

`facility-videos/` 아래 객체를 만드는 경로는 여럿인데, 지우는 경로는
`delete-facility-video` 하나뿐이다. 그 라우트도 **DB가 지금 가리키는 객체**만 지운다.
그래서 아래 경우에 남은 객체는 아무도 지우지 않는다.

- 영상을 교체할 때: `facility-video-confirm`이 새 URL로 덮어쓰고, 옛 영상·포스터는 그대로 둔다.
- presign과 PUT은 끝났는데 confirm이 실패하거나 응답이 유실될 때.
- 포스터 PUT이 끝난 뒤 업로드를 취소할 때(`2026-10-07-sidepanel-media-loading-design.md` 4.3).
- 삭제에서 영상은 지웠는데 포스터 삭제가 실패할 때(같은 설계 4.5).

공개 화면에는 영향이 없다. DB가 가리키지 않는 객체는 렌더되지 않는다. 비용은 R2 저장 용량뿐이다.

## 막힌 이유

**차단 사유 없음.** 범위 때문에 미뤘다. 사이드패널 로딩 설계는 파일을 줄이는 것이 목적이었고,
수거는 별도의 판단(언제 지워도 안전한가)이 필요하다.

## 트리거

- R2 사용량이 무료 한도에 다가간다.
- 영상 교체가 잦아진다.

## 착수 시 정할 것

- **수거 방식.**
  - **로컬 수거 스크립트**: `facility-videos/` 목록과 DB의 `video_url`·`video_poster_url`을 대조해,
    참조되지 않고 일정 시간이 지난 객체를 지운다. `DRY_RUN` 기본. 모든 원인을 한 곳에서 처리한다.
    대신 사람이 주기적으로 돌려야 한다.
  - **교체 시 즉시 삭제**: confirm이 옛 키를 기억했다가 새 값 저장 후 지운다. 교체만 해결하고 나머지 경로는 남는다.
  - **확정 전 객체를 별도 접두사에 두기**(staging): confirm이 정식 키로 옮긴다. 가장 깔끔하지만 업로드 계약이 바뀐다.
- **"일정 시간"의 기준.** 진행 중인 업로드(presign 유효 시간 1시간)를 지우면 안 된다.
- **일괄 변환 스크립트의 journal과의 관계.** `--purge` 전의 원본은 DB가 참조하지 않지만 일부러 남긴 것이다.
  수거 대상에서 빼야 한다.
