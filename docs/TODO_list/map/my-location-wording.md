# 현 위치 버튼과 그 안내 문구의 표기가 갈라져 있다

공개 지도의 현위치 버튼은 보이는 라벨과 접근 이름이 모두 `myLocation`("현 위치")인데
(`src/components/map/Map.tsx`), 그 버튼이 만들어 내는 결과물은 다른 표기를 쓴다.

| 키                  | 값(ko)                               | 쓰이는 곳           |
| ------------------- | ------------------------------------ | ------------------- |
| `myLocation`        | 현 위치                              | 버튼 라벨·접근 이름 |
| `myLocationMarker`  | 현재 위치                            | 위치 마커 `title`   |
| `locateUnsupported` | 현재 위치를 사용할 수 없는 브라우저… | 미지원 토스트       |
| `locateUnavailable` | 현재 위치를 확인할 수 없어요         | 실패 토스트         |

**"현 위치"를 누른 사용자가 "현재 위치"라는 다른 이름으로 안내를 받는다.**
스크린리더 사용자에게는 버튼 이름과 마커 이름이 서로 다른 대상처럼 들리고,
토스트만 들은 사용자는 어느 버튼이 낸 문구인지 되짚기 어렵다.

이 갈라짐은 이번 브랜치가 만들었다. 이전에는 버튼도 `"현재 위치"` 고정
문자열이라 넷이 같았고, 데스크톱 라벨을 달면서 `t("myLocation")`으로 바꾸는
과정에서 버튼만 "현 위치"로 옮겨 갔다.

## 막힌 이유

**차단 사유 없음.** 번역 문자열 몇 줄이다. 어느 쪽 표기로 통일할지가 카피
결정이라 임의로 정하지 않았을 뿐이다.

## 트리거

없음.

## 착수 시 정할 것

- **어느 표기로 모을지.** 선택지와 함의:
  - **토스트·마커를 "현 위치"로 맞춘다** — 버튼이 기준이 되고 네 문구가 한 이름을
    쓴다. 다만 `myLocationMarker`는 지도 위 마커에 붙는 명사구라, "현 위치"가
    기능 이름이 아니라 장소 이름처럼 읽힐 수 있다.
  - **마커 키를 `myLocationPin` 등으로 갈라 쓴다** — 버튼과 마커가 다른 이름을
    갖는 것을 설계로 못박고, 토스트만 버튼 표기에 맞춘다. 이 경우 왜 다른지가
    설계 문서에 남아야 다음 사람이 다시 되돌리지 않는다.
  - **버튼을 "현재 위치"로 되돌린다** — 가장 적은 변경이지만, 라벨이 아이콘 아래
    세로로 들어가고 `white-space: nowrap`이라 버튼 폭이 늘어난다. 폭을 실제로
    재 보고 판단할 것.
- **en/zh도 같이 손댈지.** 한국어만 고치면 세 언어의 문구 관계가 서로 달라진다.
  지금 en/zh는 버튼(`My Location` / `我的位置`)과 마커(`Your location` /
  `当前位置`)가 원래 다른 표현이라 이 문제가 그대로 나타나지는 않는다.
