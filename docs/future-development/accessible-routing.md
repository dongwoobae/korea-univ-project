# 접근 가능한 경로 탐색

## 상태

- 분류: 후속 고도화
- 현재 릴리스 포함 여부: 포함하지 않음
- 관련 감사 항목: `UX-P3-01`
- 선행 조건: 현재 정보 지도의 UX·접근성 개선과 관리자 데이터 관리 안정화

## 결정 배경

현재 지도는 건물·시설·명소·경사도 정보를 탐색하는 정보 지도다. 출발지에서
목적지까지 이동할 수 있는 경로를 안내하려면 화면에 경로선을 추가하는 것만으로는
충분하지 않다. 실제 보행로의 연결 관계, 건물 출입구, 계단, 경사로, 엘리베이터,
공사 및 통행 제한을 하나의 네트워크로 구축해야 한다.

이 작업은 새로운 데이터 모델, 보행로 편집 도구, 현장 데이터 수집, 경로 탐색
알고리즘 및 실제 사용자 검증이 필요한 독립적인 개발 규모다. 따라서 현재 지도
완성 범위에서 제외하고 별도의 후속 개발 단계로 진행한다.

## 현재 경사도 데이터의 한계

현재 `slope_segments`는 GPX에서 얻은 위도·경도·고도 좌표를 `segments` JSON으로
저장하고, 지도에서 해당 좌표를 직접 연결해 표시한다.

이 방식에는 다음 한계가 있다.

- GPS 오차로 선이 실제 보행로를 벗어나거나 건물 폴리곤을 침범할 수 있다.
- 동일한 길을 다시 측정하면 서로 다른 모양의 선이 만들어질 수 있다.
- 경사도 선 사이의 연결 관계가 없어서 출발지와 목적지 사이의 경로를 계산할 수 없다.
- 계단, 횡단보도, 실내 통로처럼 이동 가능 여부를 결정하는 정보를 표현하지 못한다.
- GPX 기록을 실제 길의 기준 형상으로 사용하므로 지도 데이터의 품질이 측정 기기의
  정확도에 좌우된다.

따라서 GPX는 길 자체가 아니라 **경사도를 측정한 원본 자료**로 취급해야 한다.

## 목표 사용자 여정

1. 사용자가 출발지와 목적지를 선택한다.
2. 이동 조건을 선택한다.
   - 계단 회피
   - 완만한 경사 우선
   - 엘리베이터 이용
3. 접근 가능한 추천 경로와 대체 경로를 확인한다.
4. 각 구간의 경사, 계단, 엘리베이터, 공사 및 통행 제한을 확인한다.
5. 경로의 정보가 오래되었거나 실제 현장과 다르면 피드백을 제출한다.

## 핵심 설계 원칙

### 보행로가 기준 데이터다

지도에 표시되는 선과 경로 계산에는 관리자가 검수한 보행로 중심선을 사용한다.
GPS 측정점은 가까운 보행로 위에 투영하여 경사도 계산에만 사용한다.

```text
GPX 원본 좌표
      ↓ 보행로 매칭 및 검수
보행로 중심선 + 구간별 경사도
      ↓
지도 표시 + 접근 가능한 경로 계산
```

### 보행로를 연결 그래프로 관리한다

보행로는 교차점과 구간으로 나눈다.

- 노드: 교차점, 건물 출입구, 계단 시작·종료점, 엘리베이터 승강 지점
- 엣지: 두 노드를 연결하는 일반 보행로, 경사로, 계단, 횡단보도, 실내 통로
- 가중치: 거리, 경사, 예상 이동 난이도
- 제한: 휠체어 통행 가능 여부, 운영 시간, 공사 및 임시 폐쇄

### 자동 보정 결과는 관리자가 검수한다

가장 가까운 선에 무조건 GPS 좌표를 붙이면 평행한 보행로, 도로 반대편, 실내·실외
구간에 잘못 연결될 수 있다. 자동 매칭 결과와 허용 거리 밖 좌표를 관리자에게
보여주고 확정 후 공개한다.

## 데이터 모델 초안

구현 시점의 기술 검토에 따라 이름과 저장 형식은 변경할 수 있다.

### `walkway_nodes`

- 식별자
- 위치 좌표
- 노드 유형: 교차점, 출입구, 엘리베이터, 계단 연결점 등
- 건물 및 시설 연결 정보
- 공개·검수 상태

### `walkway_edges`

- 시작 노드와 종료 노드
- 검수된 보행로 중심선
- 구간 유형: 보행로, 횡단보도, 경사로, 계단, 실내 통로
- 거리와 이동 방향
- 휠체어 통행 가능 여부
- 운영 시간 및 상시 제한
- 공개·검수 상태

### `walkway_slope_sections`

- 보행로 구간 식별자
- 구간 내 시작·종료 위치
- 경사율과 측정 신뢰도
- 측정 일시 및 원본 GPX 식별자

### `walkway_restrictions`

- 보행로 구간 식별자
- 공사, 행사, 고장, 임시 폐쇄 등의 제한 유형
- 적용 시작·종료 시각
- 우회 안내와 확인 일시

기존 `slope_segments`는 즉시 삭제하지 않고 GPX 원본 및 마이그레이션 출처로
보존한다.

## 관리자 데이터 구축 흐름

1. 지도에서 실제 보행로 중심선을 작성한다.
2. 보행로 끝점을 기존 교차점이나 건물 출입구에 연결한다.
3. 계단, 경사로, 횡단보도, 실내 통로 등의 구간 유형을 지정한다.
4. GPX를 업로드하고 측정값을 선택한 보행로에 매칭한다.
5. 허용 거리 밖 좌표, 건물 침범 및 연결되지 않은 구간을 검토한다.
6. 미리보기에서 경사도와 연결 관계를 확인한 뒤 공개한다.

실외 보행로가 건물 폴리곤을 침범하면 데이터 품질 경고를 표시한다. 다만 실내
통로나 출입구 연결선은 의도적으로 건물 내부에 포함될 수 있으므로 일괄 차단하지
않는다.

## 단계별 개발 범위

### 1단계: 조사와 데이터 기준 확정

- 우선 구축할 캠퍼스와 대표 이동 구간 선정
- 보행로 유형과 접근성 속성 정의
- 건물 출입구·엘리베이터 연결 기준 정의
- 현장 조사 및 데이터 관리 책임 결정

### 2단계: 보행로 네트워크 구축

- 보행로 노드·구간 데이터 모델
- 관리자 보행로 작성·수정·연결 도구
- 연결되지 않은 구간과 건물 침범 검증
- 공개 지도 보행로 레이어

### 3단계: 경사도 데이터 정비

- 기존 GPX 원본 보존 및 보행로 매칭
- 구간별 경사도 산출
- 자동 매칭 미리보기와 관리자 확정
- 측정 일시와 신뢰도 표시

### 4단계: 경로 탐색

- 접근성 조건을 반영한 경로 비용 모델
- 출발지·목적지 선택 UI
- 추천 경로와 대체 경로
- 구간별 주의사항 및 우회 안내

### 5단계: 현장 검증과 운영

- 휠체어 및 이동약자 사용자 테스트
- 실제 이동 시간과 경로 정확도 검증
- 공사·고장·임시 폐쇄 갱신 절차
- 잘못된 경로 신고와 관리자 처리 흐름

## 현재 버전에서의 처리

- 경로 탐색 기능과 보행로 데이터 모델은 구현하지 않는다.
- 현재 경사도는 경로 안내가 아닌 참고 정보로 취급한다.
- 경사도 표시가 실제 보행 가능성을 보장하는 것으로 오인되지 않도록 명칭과 안내
  문구를 별도 UX 작업에서 검토한다.
- 건물을 크게 침범하거나 오차가 명확한 경사도 기록은 수동 보정 또는 비공개 처리를
  검토한다.

## 구현 전 결정할 사항

- 첫 구축 범위를 단일 캠퍼스로 제한할지 여부
- 자체 조사 데이터와 OpenStreetMap 등 외부 데이터의 결합 방식
- 실내 이동과 층간 엘리베이터 연결을 어느 단계까지 포함할지
- 경사도 측정 장비와 허용 오차 기준
- 경로 탐색을 클라이언트, 서버 또는 외부 엔진에서 수행할지
- 임시 통행 제한 정보를 누가 얼마나 자주 갱신할지
- 안전 관련 안내와 데이터 최신성 책임 범위
