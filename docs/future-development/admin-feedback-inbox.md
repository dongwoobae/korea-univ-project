# 관리자 피드백함 후속 개발

> **2026-10-08 — 일부 완료.** 아래 범위 중 일부가 관리자 제보함의 피드백 탭으로 끝났다. 설계는 [`docs/specs/2026-10-08-facility-request-design.md`](../specs/2026-10-08-facility-request-design.md) 6장. 본문은 당시 기록으로 두고, 남은 범위만 이 문서에서 이어 간다.
>
> | 이 문서                     | 당시 | 현재                                                                                    |
> | --------------------------- | ---- | --------------------------------------------------------------------------------------- |
> | 목록·상태 변경              | 계획 | 제보함 피드백 탭(`/admin/dashboard/inbox?tab=feedback`). 상태 선택 상자로 바로 저장     |
> | 상태 필터·서버 페이지네이션 | 계획 | 처리 전(신규·확인 중) / 신규 / 확인 중 / 처리 완료 / 전체, 번호 페이지네이션            |

## 배경

현재 공개 피드백 폼은 `POST /api/feedback`으로 제출 내용을
`feedback_submissions` 테이블에 저장하며, 서버 제출 실패 시 `mailto:` 링크를
보조 수단으로 제공한다.

향후에는 메일 보내기 기능을 제거하고, 인증된 관리자가 관리자 페이지에서
접수된 피드백을 직접 확인하고 처리할 수 있도록 한다. 관리자 피드백함이
준비되기 전까지는 현재 제출 및 메일 보조 흐름을 유지한다.

## 개발 범위

- 인증된 관리자만 접근할 수 있는 피드백 목록과 상세 화면
- 신규, 확인 중, 처리 완료 상태와 상태 변경 기능
- 유형, 상태, 접수일 필터와 검색 및 서버 페이지네이션
- 관리자 내비게이션의 미확인 피드백 수 표시
- 피드백 원문, 접수 페이지 주소, 접수 시각 표시
- 관리자 조회 및 상태 변경에 필요한 RLS 정책
- 보관 기간과 삭제 기준을 포함한 개인정보 운영 기준
- 관리자 피드백함 배포 후 공개 폼의 `mailto:` 보조 수단 제거

## 제외 범위

- 접수 또는 상태 변경 이메일 알림
- 제출자의 이름, 이메일, 전화번호 수집
- 제출자와의 양방향 메시지 기능

## 완료 조건

- 비인증 사용자는 피드백 목록과 상세 내용을 조회할 수 없다.
- 관리자는 피드백을 최신순으로 조회하고 필터, 검색, 페이지 이동을 할 수 있다.
- 관리자가 상태를 변경하면 목록과 상세 화면에 즉시 반영된다.
- 공개 피드백 제출 성공 및 실패 상태가 기존과 동일하게 안내된다.
- 관리자 피드백함 배포와 함께 메일 보내기 UI 및 `mailto:` 의존성을 제거한다.
