# 시설 상세 모달화와 건물 동영상 섹션 설계

**작성일:** 2026-08-04

## 문제

건물 상세 페이지의 `시설 현황` 카드에서 시설 한 줄이 **컨트롤 4~6개를 담은 `flex-wrap` 컨테이너**다. 담기는 개수가 시설 상태에 따라 달라진다.

| 컨트롤            | 출처                          | 조건               |
| ----------------- | ----------------------------- | ------------------ |
| `동영상`          | 행이 직접 렌더                | 항상               |
| `현재 상태: 설치` | `FacilityInstallationControl` | 항상               |
| `미설치로 변경`   | `FacilityInstallationControl` | 항상               |
| `번역 필요`       | `FacilityTranslationControl`  | 번역이 필요할 때만 |
| `재번역`          | `FacilityTranslationControl`  | 번역이 필요할 때만 |
| `삭제`            | 행이 직접 렌더                | 항상               |

두 컴포넌트가 각각 **두 개씩** 넣는다는 점이 밖에서 보이지 않는다. 그래서 번역이 필요한 행만 폭을 넘겨 `삭제`가 다음 줄 맨 왼쪽으로 떨어지고, **행마다 액션 위치가 달라진다.**

시각 언어도 섞여 있다. 상태를 알리는 알약 칩(초록 `현재 상태: 설치`, 노랑 `번역 필요`)과 누르는 버튼(회색 `미설치로 변경`, 주황 `재번역`, 테두리 없는 빨강 `삭제`)이 같은 줄에 같은 크기로 놓여, 어느 것이 클릭 대상인지 형태로 구분되지 않는다. 상태 칩 바로 옆에 그 상태를 바꾸는 버튼이 붙어 읽는 순서도 꼬인다.

여기에 위도·경도가 소수점 7자리로 매 행 세 번째 줄을 차지한다. 목록을 훑을 때 쓰는 정보가 아니다.

## 목표

- 행에서 액션을 걷어내 **행의 요소 수를 상태와 무관하게 고정**한다. 줄바꿈 문제는 원인이 사라진다.
- 행이 "손봐야 할 시설"을 한눈에 드러내게 한다.
- 동영상 관리를 건물 단위 진입점으로 옮긴다.

## 범위 밖

- `video_url` 저장 위치 변경. 동영상은 계속 `building_facilities`의 컬럼이고 공개 화면에서도 그 시설 밑에 렌더된다.
- 건물당 동영상 개수 제약. 스키마상 시설당 하나이며 그 이상은 규약으로 둔다.
- 시설 이름·설명·층·좌표 편집 기능 신설.
- 시설 삭제 시 동영상이 함께 지워지는 동작 변경.

## 설계 1: 건물 동영상 섹션

건물 사진 카드가 카드 하나에 `PhotoManager` 하나를 꽂는 구조다. 동영상도 같은 모양으로 맞춘다 — 카드 제목 `건물 동영상` + `BuildingVideoManager` 하나.

```
┌─ 건물 동영상 ──────────────────────┐
│  ▶ [썸네일]  경사로                │
│              "경사로 입구"          │
│                          관리 ›    │
│  [+ 동영상 추가]                   │
└────────────────────────────────────┘
```

**내용:** 이 건물의 시설 중 `video_url`이 있는 것들을 목록으로 보여준다. 항목마다 시설명과 캡션, `관리` 버튼.

**추가 흐름:** `+ 동영상 추가` → 시설 선택 드롭다운 → 확인 → 기존 `FacilityVideoModal`이 그 시설을 대상으로 열린다.

**교체 경고:** 드롭다운에서 이미 동영상이 있는 시설을 고르면 교체된다고 알린다. `video_url`이 단일 컬럼이라 두 번째 업로드는 덮어쓰기다.

**재사용:** 업로드·압축·진행률·캡션·삭제는 `FacilityVideoModal`을 그대로 쓴다. 이 모달은 ffmpeg 압축과 자체 포커스 트랩, 중첩 `ConfirmModal`을 갖고 있어 옮기거나 풀어헤치지 않는다.

**시설이 없는 건물:** 드롭다운에 고를 것이 없으므로 `+ 동영상 추가`를 비활성화하고 먼저 시설을 등록하라고 안내한다.

## 설계 2: 시설 행을 상세 모달로

```
┌─ 시설 현황 ────────────────────────┐
│ ♿  경사로                        › │
│ 🅿  장애인 주차                    › │
│ 🚻  장애인용 화장실 · 전 층 번역필요 › │
│ 🛗  1층 엘리베이터        번역필요 › │
└────────────────────────────────────┘
```

**행:** 아이콘 · 이름 · 설명(층) · 배지 · `›`. 행 전체가 하나의 `<button>`이다.

**배지:** 손봐야 할 때만 붙는다. `미설치`(`is_installed`가 참이 아님), `번역 필요`(`facilityNeedsTranslation`). 정상 시설은 오른쪽이 빈다. **배지가 보이는 행이 곧 손봐야 할 행**이라는 규칙이 목록 전체에서 성립한다.

배지는 `<span>`이다. 행이 `<button>`이므로 그 안에 버튼을 두면 안 된다.

**행에서 빠지는 것:** 위도·경도 줄. 모달로 옮긴다.

**모달 내용:** 한 줄에 하나씩.

| 항목 | 내용                                              |
| ---- | ------------------------------------------------- |
| 제목 | 시설명                                            |
| 상태 | `FacilityInstallationControl` 재사용              |
| 번역 | `FacilityTranslationControl` 재사용 (필요할 때만) |
| 위치 | 위도·경도 표시                                    |
| 삭제 | 확인창을 거친다                                   |

**동영상은 모달에 없다.** 설계 1의 건물 섹션이 그 자리를 대신하므로, 모달 위에 동영상 모달이 겹치는 구조가 생기지 않는다.

**삭제 확인창:** 대상 시설에 동영상이 있으면 "이 시설의 동영상도 함께 삭제됩니다"를 덧붙인다. 동영상이 건물 섹션에 보이게 된 뒤로는, 시설을 지웠을 뿐인데 건물 동영상이 사라지는 일이 예고 없이 일어나기 때문이다.

## 컴포넌트 경계

**신규**

| 파일                                            | 책임                                            |
| ----------------------------------------------- | ----------------------------------------------- |
| `src/components/admin/BuildingVideoManager.tsx` | 건물 동영상 목록 · 시설 선택 · 업로드 모달 진입 |
| `src/components/admin/FacilityDetailModal.tsx`  | 시설 하나의 상태·번역·위치·삭제                 |
| `src/lib/facilityBadges.ts`                     | 시설에서 배지 목록을 계산하는 순수 함수         |

**수정**

| 파일                                    | 변경                                          |
| --------------------------------------- | --------------------------------------------- |
| `src/app/admin/buildings/[id]/page.tsx` | 동영상 카드 추가 · 시설 행 단순화 · 모달 연결 |
| `src/app/admin/admin-ui.css`            | 시설 행·배지 클래스 (인라인 스타일 대신)      |

`FacilityInstallationControl`과 `FacilityTranslationControl`은 그대로 두고 모달 안에서 재사용한다. 두 컴포넌트가 각각 칩과 버튼을 함께 렌더하는 성질은 한 줄에 하나씩 놓이는 모달에서는 문제가 되지 않는다.

배지 판정을 `facilityBadges.ts`로 빼는 이유는 이 프로젝트에 jsdom이 없어 컴포넌트 단위 테스트가 불가능하기 때문이다. 순수 함수로 두어야 vitest가 덮을 수 있다. 번역 필요 판정은 이미 `facilityNeedsTranslation`에 있으므로 그것을 호출한다 — 조건을 두 벌로 만들지 않는다.

## 접근성

- 행이 `<button>`이므로 내부에 상호작용 요소를 두지 않는다. 배지는 `<span>`.
- 행의 접근 이름에 시설명과 배지가 함께 읽혀야 한다. 배지가 시각적으로만 존재하면 스크린 리더 사용자는 어느 행을 눌러야 하는지 알 수 없다.
- 모달은 기존 `useModalFocus`를 쓴다. ESC로 닫히고 포커스가 갇힌다.
- 모달을 닫으면 포커스가 열었던 행으로 돌아간다.

## 검증

**단위 (vitest)** — `facilityBadges.ts`. 설치·미설치, 번역 필요·불필요의 조합에서 나오는 배지 목록.

**E2E (Playwright)**

- 시설 행 클릭 → 모달이 열리고 시설명이 제목에 있다
- 모달에서 상태를 토글하면 목록 배지가 따라 바뀐다
- 모달을 닫으면 포커스가 행으로 돌아온다
- 정상 시설 행에는 배지가 없다
- 건물 동영상 섹션에서 시설을 고르면 업로드 모달이 열린다
- 시설이 없는 건물에서 `+ 동영상 추가`가 비활성이다

**수동** — 번역이 필요한 시설이 여러 개인 건물에서 행 높이가 균일한지. 좁은 폭(390px)에서 배지가 이름을 밀어내지 않는지.

## 알려진 위험

- **E2E mock이 동영상 업로드를 태우지 못한다.** ffmpeg 압축과 R2 업로드가 얽혀 있어, 건물 동영상 섹션은 "모달이 열리는 것"까지만 자동으로 확인된다. 업로드가 실제로 되는지는 수동 확인이 필요하다.
- **기존 E2E가 시설 행의 버튼을 직접 누른다.** 행이 모달로 바뀌면 그 단언들이 깨진다. 계약을 새 흐름으로 옮겨 적어야 하며, 단언을 지우기만 해서는 안 된다.
- **행이 button이 되면 전역 button 리셋의 영향을 받는다.** `text-align: center`와 색 미상속을 명시적으로 되돌려야 한다. 관리자 모바일 카드에서 같은 문제가 이미 한 번 있었다.

## 후속 과제

- 시설 이름·설명·층·좌표를 모달에서 편집하기
- 배지 규칙을 건물 관리 목록의 경고 카드 정의와 맞추기
- 동영상 교체 시 R2에 남는 옛 객체 정리
